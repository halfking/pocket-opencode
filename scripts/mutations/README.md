# scripts/mutations —— §935 的变异审计工具

## 这是什么

**四批**「判据变异」脚本：把某处实现**改坏**，看对应的判据**会不会红**。

| 脚本 | 覆盖的判据 | 批次数 |
|---|---|---|
| `s919.py` | §919 服务端字节闸的调用方登记簿 + Go 跨语言闸值门 | A1–A16 |
| `s920.py` | §920 精校兜底超字节闸时必须出声 | B1–B10 |
| `s921.py` | §921 全仓「长度限制」清单门 | V1–V9 |
| `s922.py` | §922 客户端单次预算 == 服务端闸值 + `chunkByLimit` 语义 + STT 413 | C1–C11 |

## 为什么它们在仓里（而不是 /tmp）

**§919–§922 当时的变异脚本没有落盘** —— 提交信息与主文档只留了「全中」的汇总。
⇒ 下一轮想复核「当时绿 = 现在绿」时，只能**按判据描述重建**一批等价变异。
⇒ 重建出来的东西能证明「**判据现在还有牙**」，**证明不了「当时那批脚本真的跑过」**
（历史读数没有第二份副本）。

⇒ 所以这四批脚本**落盘**在这里：下一轮要复核时，**跑它**，而不是再重建一遍。

## 怎么跑

```bash
cd <仓库根>
python3 scripts/mutations/run_all.py      # 四批依次跑
python3 scripts/mutations/s919.py         # 只跑某一批
```

退出码 0 = 全过；非 0 = 至少有一条变异**没被抓住**（或量具自证失败）。

## ⚠ 这些脚本会**就地改工作树**

这是「变异」的定义。三条自我保护（都在 `_harness.py` 里）：

1. **前置**：目标文件必须与 `HEAD` 一致（`git diff --quiet HEAD -- <file>`）
   ⇒ 你有未提交的改动时它**直接拒绝跑** ⇒ 不会把你的改动和变异混在一起。
2. **还原自证**：每条用例跑完立刻还原，并**逐字节**比对原文件 ⇒ 还原失败立刻退出。
3. **残留核对**：整批跑完比对 `git status --porcelain` 与前置快照**完全一致**
   ⇒ 任何一个字节的残留都会被抓到。

⇒ 跑完之后，工作树必须还是你交给我时的样子。

## 读法：三种用例

- **「必须红」** ⇒ 证明判据**有牙**（改坏了它会响）。
- **「负控 · 必须绿」** ⇒ 证明判据**不过度敏感**（语义等价的改动不该误报）。
- **「量具自检」** ⇒ 量的是**判据自己的盲区**（例如前端树缺失时 Go 那道门会被
  `t.Skipf` 跳过 ⇒ 变成空气门）⇒ **它不是「有牙」的证据**，是**局限**的证据。

## 口径纪律（每一条都是踩出来的）

- **落盘 → 在变异状态下跑判据 → 还原 → 核对**。
  还原早于跑判据 ⇒ 测的是**没变异的文件** ⇒ 变异「全绿」⇒ **假通过**。
- **落盘自证**用「文件确实变了 **且** 新串在场」，
  **不能**用「旧串不在场」（旧串不在场可能只是锚点写错）。
- **锚点必须按实现的真实写法来**；出现次数必须**恰好**等于预期（不符 ⇒ 立刻中止，
  不猜）。
- **还原也要自证**（文件回到原样）。

## 已知局限

- 这四批是**重建**的等价批次，**不是**当年那批脚本（见上）。
- 脚本里的锚点是**逐字**的 ⇒ 实现改了写法（哪怕语义没变）就要改脚本。
  这是刻意的：锚点一旦漂移，变异就变成**空操作**，而判据仍会显示「有反应」。
- `s919.py` 的 A16 是**量具自检**，它证明的是「这道门在某个前提下会变成空气门」。
