# ACP（Agent Client Protocol）通用化改造方案

## 目标

把后端从「OpenCode HTTP 专属」改造为「任意 ACP agent 可插拔」，通过 JSON-RPC 2.0 over stdio/HTTP/WebSocket 三种 transport 接入 Claude Code、Codex、Gemini CLI、Aider、Cline 等任何实现 ACP 的 agent。

参考协议：https://agentclientprotocol.com （Zed 主导，JSON-RPC 2.0 + camelCase）。

---

### 1.2 核心接口

```go
// AgentAdapter 是与编程 agent 通信的统一接口。所有实现（OpenCode、ACP-stdio、ACP-HTTP、ACP-WS）
// 都实现这套接口；handler 层只与 AgentAdapter 交互，不感知底层 transport。
type AgentAdapter interface {
    // 元数据
    Capabilities(ctx, agentRef) (*AgentCapabilities, error)
    HealthCheck(ctx, agentRef) error

    // 会话生命周期
    ListSessions(ctx, agentRef, opts ListOptions) ([]AgentSession, error)
    CreateSession(ctx, agentRef, req *CreateSessionRequest) (*AgentSession, error)
    LoadSession(ctx, agentRef, sessionID string) (*AgentSession, error)  // optional cap
    DeleteSession(ctx, agentRef, sessionID string) error                  // optional cap

    // 对话
    GetMessages(ctx, agentRef, sessionID string, opts ListOptions) ([]AgentMessage, error)
    SendPrompt(ctx, agentRef, sessionID string, req *SendPromptRequest) (*SendPromptResult, error)
    InterruptSession(ctx, agentRef, sessionID string) error
    SetSessionMode(ctx, agentRef, sessionID, mode string) error  // optional cap

    // 流式事件（ACP session/update notifications）
    SubscribeEvents(ctx, agentRef) (<-chan AgentEvent, func(), error)

    // Optional capabilities — handler 用 type assertion 探测
    // (PermissionCapable, QuestionCapable)
}

type PermissionCapable interface {
    ListPendingPermissions(ctx, agentRef, sessionID string) ([]PermissionRequest, error)
    ReplyPermission(ctx, agentRef, sessionID, requestID string, reply PermissionDecision) error
}

type QuestionCapable interface {
    ListPendingQuestions(ctx, agentRef, sessionID string) ([]Question, error)
    ReplyQuestion(ctx, agentRef, sessionID, requestID string, answers []QuestionAnswer) error
    RejectQuestion(ctx, agentRef, sessionID, requestID string) error
}
```

### 1.3 通用类型

```go
type AgentSession struct {
    ID         string
    Title      string
    Status     string  // "idle" | "busy" | "retry"
    Agent      string  // "opencode" | "codex" | "claude-code" | ...
    WorkingDir string
    CreatedAt  time.Time
    UpdatedAt  time.Time
    Metadata   map[string]any
}

type AgentMessage struct {
    ID        string
    SessionID string
    Role      string  // "user" | "assistant" | "system"
    Parts     []ContentBlock
    Timestamp time.Time
    Metadata  map[string]any
}

type ContentBlock struct {
    Type string  // "text" | "image" | "resource_link" | "tool_use" | "tool_result"
    Text string
    URL  string
    Data any
}

type AgentEvent struct {
    Type      string  // "message_chunk" | "tool_call" | "tool_call_update" | "permission_request" | ...
    SessionID string
    Data      any
    Timestamp time.Time
}
```

### 1.4 Transport 抽象

```go
// Transport 是 JSON-RPC 2.0 over 不同底层协议的统一抽象。
type Transport interface {
    // Start 启动 transport（建子进程 / 打开 HTTP 连接 / WebSocket upgrade）。
    Start(ctx context.Context) error
    // Close 关闭并清理。
    Close() error
    // Call 发送 JSON-RPC request 等响应（阻塞）。
    Call(ctx context.Context, method string, params json.RawMessage, out any) error
    // Notify 发送 JSON-RPC notification（不等待响应）。
    Notify(method string, params json.RawMessage) error
    // Recv 接收 next incoming notification 或 server-initiated request。
    // 实现：stdio = 读 stdout 的非 notification 帧；HTTP = SSE；WS = ws.ReadMessage
    Recv(ctx context.Context) (notification json.RawMessage, err error)
}
```

## 2. Transport 实现

### 2.1 stdio（首选，2 周内交付）

**关键实现要点**：
- 启动：`exec.CommandContext(agentPath, args...)` + 连接 stdin/stdout 管道
- 写：`json.NewEncoder(stdout).Encode(req)` + `\n` 分隔
- 读：goroutine `bufio.Scanner` 按行读 stdout，分类为 response / notification / request
- 子进程管理：超时 / SIGTERM / 重启（崩溃后自动起新进程）
- 日志：`cmd.Stderr = log.Writer()` 转发子进程 stderr 到 pocketd 日志

**file**: `transport_stdio.go`

### 2.2 HTTP（Streamable HTTP，1 周）

**关键实现要点**：
- 启动：`POST {baseURL}/acp` 携带 `Accept: application/json, text/event-stream`
- Call：单 POST + 等待 SSE 帧
- Notify：`POST {baseURL}/acp` 不带 `id` 字段
- Recv：长连接 GET `/acp` 收 SSE 流
- 鉴权：HTTP draft 提到 `Acp-Connection-Id` / `Acp-Session-Id` 头（v2 草案）

**file**: `transport_http.go`

### 2.3 WebSocket（1 周）

**关键实现要点**：
- 启动：`GET {wsURL}/acp` 带 `Upgrade: websocket`
- Call/Notify/Recv：直接复用 gorilla/websocket
- 与现有 PluginHub 集成：agent 可以反向连入 `/plugin/ws` 注册自己

**file**: `transport_ws.go`

## 3. Adapter 迁移

### 3.1 OpenCode 适配器（保兼容，3 天）

新增 `internal/agent/adapter_opencode.go`：把现有 `OpenCodeHTTPAdapter` 包装为 `AgentAdapter`：
- `AgentSession ← OpenCodeSession` 字段映射
- `AgentMessage ← OpenCodeMessage` 字段映射（把 OpenCode 的 `info{role} + parts[]` 转为 ContentBlock[]）
- `AgentEvent ← OpenCodeEvent` 字段映射（从 SSE 事件中提取 sessionID）
- Optional capabilities (Permission, Question) 通过 type assertion 暴露
- 保留 OpenCodeError 作为底层 transport error，向外转译为 AgentError

**关键决策**：OpenCode 的能力仍走 HTTP API（因为 OpenCode 不实现 ACP）；ACP 走 stdio/HTTP/WS。

## 4. Server 端改造

### 4.1 Server 字段重命名

```go
// 旧：
opencode adapter.OpenCodeAdapter

// 新：
agents  *agent.Registry      // 按 agentRef 分发到对应 adapter
```

新增 `internal/agent/registry.go`：按 `agent.Type + agent.Target` 缓存 adapter 实例；未配置 fallback 到 OpenCode。

### 4.2 handler 层改造

所有 18+ 处 `s.opencode.X(...)` 替换为 `s.agents.Get(agentRef).X(...)`：
- `agentRef` 从 query/path 参数构造（`{type, target}` JSON 或 `instance_id` 自动映射到 `type=opencode`）
- 兼容旧 `instance_id` query：自动构造 `agentRef{type:"opencode", target: instance_id}`

### 4.3 OpenCode Manager 改造

`opencode.Manager` / `EventStreamManager` / `PermissionManager` / `QuestionManager` 改造为接受 `AgentAdapter`（不再依赖 `OpenCodeAdapter`）。重命名 `internal/opencode` → `internal/agent/manager`（或保留 package 名兼容）。

### 4.4 MCP 路径保持

MCP（用于 ACC）路径不变：`mcp.Client` 继续独立存在。`agentbridge.Bridge` 也继续以 agent-specific 适配器为输入。

## 7. 风险与决策点

### 风险

1. **OpenCode HTTP API 与 ACP 协议语义不完全对齐** — OpenCode 没有 `session/list`、`session/delete`、`authenticate`、`session/set_mode` 等纯 ACP 方法；我们的 adapter 包装需要 mock 这些能力（返回空 / 501 NotImplemented）。
2. **stdio 进程生命周期** — 子进程崩溃后需要重启（exponential backoff）；前端要能感知 "agent reconnecting" 状态。
3. **JSON-RPC 2.0 严格性** — 必须严格遵循 spec（id 唯一、error vs result 二选一、notification 无 id）。
4. **多 transport 并存** — 同一 `agentRef` 不能同时有 stdio + WS 连接（实现层面禁止）。

### 不兼容决定（与你确认过的）

- 全面替换 `OpenCodeAdapter` → `AgentAdapter`
- 所有 call sites 一次性迁移（不保留 legacy wrapper）
- OpenCode 作为 `AdapterOpenCode` 重新实现，原 HTTP 调用路径不变

### 不在本次范围

- **不实现真实 Claude Code / Codex adapter**（那是后续 PR）
- **不动 ACC / MCP / agentbridge 路径**
- **不迁移 v1 ACP → v2 草案细节**（v2 仍 draft）
- **不重写 OpenCode 的 SSE / permission / question 内部实现**（只重新对外暴露）
- **不做前端 API breaking change**：handler URL 路径 + query 参数保持兼容；响应字段可扩展
