## 完全本地镜像与模拟器测试计划

### 1. 固化离线镜像策略
- 以 `~/work/docker-base-images` 和当前 Docker daemon 已有镜像为唯一来源，不执行 `docker pull`，不访问 Docker Hub。
- 检查并记录本地镜像架构；当前主机为 arm64，优先使用本地 arm64 `alpine:3.20`/`alpine:latest`、`node:22-bookworm-slim`、`nginx:alpine` 或 `kx-base:go-vue`。
- 将 Compose 分成“已导入镜像运行模式”和“本地预构建模式”：默认 `docker compose up` 不带 `--build`、不带 `pull`；缺镜像时明确失败并提示 `docker load`/本地镜像准备命令。
- 将 Go backend 继续使用宿主 `GOOS=linux GOARCH=arm64` 预构建二进制 + 本地 runtime 镜像；前端优先复用已构建的本地前端镜像，避免 `npm ci` 在 Docker build 内访问 npm registry。
- 固定 Compose 默认前端端口为 `4175`，修正示例、Origin 白名单和脚本中的历史 `4174` 不一致。

### 2. 无 pull 重新部署 Pocket 服务
- 先验证 `r112_postgres` 健康、`pocket_local` 数据库、Pocket API `8088` 和 frontend `4175`。
- 使用 `docker compose --pull never`（或等价的 image-only 模式）重建/重启仅 Pocket 自有服务；不停止、删除或重建共享 PG/Redis/Gateway。
- 检查容器架构、健康检查、API/前端端口、Compose 网络和日志，确认服务实际使用本地镜像。

### 3. 准备并启动 Android 模拟器
- 使用绝对路径 `/Users/xutaohuang/Library/Android/sdk/emulator/emulator` 和 `platform-tools/adb`，优先 AVD `pocket_test`，若不可用再使用 `Medium_Phone_API_36.1`。
- 启动模拟器并等待 `adb wait-for-device`、`sys.boot_completed=1`；只操作 Pocket 测试 AVD，不触碰现有真实设备/其他模拟器。
- 验证模拟器能访问宿主 `10.0.2.2:8088/healthz`；本轮统一使用 `10.0.2.2`，不与 `adb reverse` 混用。

### 4. 构建/安装 APK
- 使用实际 Capacitor 项目 `frontend/android`，不使用根目录的旧 `android` 壳。
- 先运行前端 typecheck/build；以 `VITE_API_BASE=http://10.0.2.2:8088` 生成 web assets 并执行 Capacitor 同步。
- 使用现有 Gradle/JDK/依赖缓存执行 `frontend/android/gradlew assembleDebug --offline`；若本地缓存不足，明确记录阻塞，不访问远程仓库。
- 安装 `frontend/android/app/build/outputs/apk/debug/app-debug.apk`，启动 `com.kaixuan.opencode.pocket/.MainActivity`，保存 logcat/截图到本地测试 artifacts。

### 5. 模拟器功能验证
- 通过 ADB 和应用界面验证：应用启动、登录 `admin/admin`、workspace/notes/notifications 页面加载、受保护 API 返回、frontend/backend health。
- 验证 WebSocket 登录后 token 连接：检查应用 logcat/网络行为，确保使用 `ws://10.0.2.2:8088/ws?token=...`，不测试未认证连接。
- 对 OpenCode 实例/会话链路做健康探测；当前 `4096` 未监听，标记 instance/session 为 `SKIPPED/OFFLINE`，不伪造通过。
- 运行已有 UI/模拟器脚本前先修正其错误路径/端口，或新增本地专用 `deploy/本地方案/local-emulator-test.sh`，避免影响旧脚本。
