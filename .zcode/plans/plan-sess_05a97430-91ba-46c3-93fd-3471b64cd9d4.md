## 目标

以当前工作树为准完成“立即任务”后端 API 闭环：保留已经存在的分页、邮箱 CRUD、摘要读取和 SSOT 推送实现，但补上安全隔离、输入校验、事务一致性和测试覆盖。不会覆盖或回滚现有未提交改动，也不在本轮假设外部 kxmemory/OpenCode 服务已部署。

## 当前审计结论

- `backend/internal/server/mobile_api.go:133-224` 的会话游标分页已经存在，使用稳定 ID 排序、`limit+1` 判断 `has_more`，当前重点是补边界测试并确认非法/重复游标行为。
- `server_assistant.go` 中账户加密、账户 PUT/DELETE、摘要列表、邮件 GET/PATCH、SSOT conflict 广播也已有初版实现。
- 当前初版的关键问题：邮件列表/详情/读写没有按当前用户约束；显式 `account_id` 同步未校验账户归属；账户更新先写元数据再写凭证，可能半成功；`authType` 更新没有持久化到 `UpdateAccount`；邮件 PATCH 两次更新可能部分成功；legacy 邮件推送忽略插入错误；workspace 字段虽已迁移但邮件 SQL 尚未实际隔离。
- OAuth callback 和完整 XOAUTH2 IMAP 连接不属于列出的本地 handler 任务，且需要外部 provider/client 配置；本轮不伪造“已连接”，只确保 `oauth2` 凭证仍使用 AES-GCM 加密并正确保存 `auth_type`。

## 实施步骤

### 1. 固定 handler 依赖边界，便于单元测试

- 在 `backend/internal/server` 为邮箱存储和同步器定义窄接口，`Server` 继续接收现有 `*email.Store`/`*email.Fetcher` 并在构造时注入；生产行为不变，测试可使用内存 fake，不依赖 PostgreSQL。
- 保持现有 nil-store/nil-crypto 的 503 降级契约和 JWT 认证优先级。

### 2. 加强账户创建、更新和删除

- 文件：`backend/internal/server/server_assistant.go`、`backend/internal/email/model.go`、`backend/internal/email/store.go`。
- 账户创建：先解析/校验 body，再检查加密依赖；校验 `authType`、凭证必填、IMAP 端口范围、同步间隔范围、邮箱/host 基本格式和 rules JSON；密码与 OAuth token 都走 `Crypto.EncryptString`，响应绝不带密文。
- 账户更新：先完成所有字段校验和凭证加密，再执行持久化；新增带 owner/workspace 条件的更新方法，单次事务同时更新元数据和可选 credential，避免加密失败或第二次 SQL 失败导致半成功；确保 `auth_type` 真正写入。
- 删除：使用 owner/workspace 条件删除并检查影响行数；陌生账户统一返回 404，避免泄露存在性。
- 创建时把 JWT 中的 workspace 写入账户记录；为 `Account` 增加内部 `WorkspaceID`（JSON `omitempty`），沿用已有 schema 默认值兼容旧数据。

### 3. 收紧邮件列表、详情、PATCH 和同步的数据边界

- 文件：`backend/internal/server/server_assistant.go`、`backend/internal/email/store.go`、`backend/internal/email/model.go`。
- 新增 scope-aware store 方法：按 `user_id + workspace_id` join `email_accounts` 查询邮件列表、详情、摘要；邮件读/星标更新使用单条 SQL 同时更新两个可选字段，并检查 affected rows；未授权或不存在都映射为 404。
- `GET /api/emails` 不再接受任意账户 ID 造成跨用户泄露；账户过滤器必须属于当前 user/workspace。
- `POST /api/emails/sync` 的显式账户先校验归属；跨用户账户和不存在账户都返回不可区分的 404；legacy `emails` 推送逐条校验账户归属、拒绝伪造其他账户数据，并统计/返回实际写入结果，不再吞掉插入错误。
- 保留现有主动 IMAP 模式；同步结果中的账户信息只来自当前用户。对新抓取邮件补上分类触发所需的用户上下文，若 kxmemory 未配置则保持明确跳过，不阻断同步。

### 4. 完善每日摘要和 SSOT 推送契约

- 文件：`backend/internal/server/server_assistant.go`、`backend/internal/email/store.go`、`backend/internal/websocket` 相关测试。
- 摘要列表继续支持 `limit`，统一在 handler/store 层限制到 1-200；所有查询按 user/workspace 隔离；日期详情保持严格 `YYYY-MM-DD` 校验和 404 未生成语义。
- SSOT conflict 路径保留现有 `note.ssot_conflict` 事件格式，增加 nil-safe 广播保护和事件 payload 测试，确认包含 `noteId`、conflicts、category、domain；kxmemory 不可用/失败时继续返回结构化降级错误，不广播伪造冲突。
- 本轮不把外部 kxmemory 部署或 OpenCode 4096 连接写入本地实现；最终报告中明确剩余外部阻塞项。

### 5. 验证移动会话游标分页

- 文件：`backend/internal/server/mobile_api.go`、`backend/internal/server/server_assistant_test.go` 或独立测试文件。
- 覆盖默认/上限 limit、asc/desc、多页完整遍历、非法 base64、游标指向不存在 ID、空结果和重复 ID；确保不会重复或跳过合法会话。
- 仅在发现行为问题时修改分页实现；若当前实现通过测试则保留，避免无必要改动。

### 6. 补充单元测试并运行验证

- 扩展 server handler 测试 fake：账户创建成功/校验失败/密文不出响应；PUT 元数据与凭证更新、authType 持久化调用、跨用户 PUT/DELETE；邮件列表/详情/PATCH 的 owner 隔离和单次 flags 更新；摘要 list/detail limit、日期和 owner 隔离；显式同步跨用户拒绝；SSOT payload；分页边界。
- 增加 email crypto round-trip、随机 nonce/错误密钥测试；如当前 fake 无法验证 store SQL，则为新增 scope-aware store 方法补最小 SQL/integration 覆盖，优先使用仓库现有 PostgreSQL 测试方式，不引入不必要的新框架。
- 运行 `gofmt`、`go test ./...`、`go vet ./...`，并针对失败区分本轮回归与仓库既有失败；最后检查 `git diff`，只报告本轮触及文件。

## 明确不在本轮执行的外部项

- 部署或配置 kxmemory FastAPI、确认其真实端点、设置生产 `POCKET_KXMEMORY_BASE_URL`。
- 部署 OpenCode Server/4096 HTTP API、配置 `POCKET_OPENCODE_INSTANCES`、真实会话 E2E。
- 完整 Gmail/Outlook OAuth 授权回调接入、XOAUTH2 SASL、token refresh；这些需要 provider client ID/secret 和外部服务协调，不能通过本地 handler 安全推断。
