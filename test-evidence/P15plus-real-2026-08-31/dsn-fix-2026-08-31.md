## 修复方案

`kx-citus` 是实际可达的共享 PG(`POSTGRES_USER=kxuser`,`POSTGRES_DB=llm_gateway`,password=`audit_admin_pw_local_only`),且 `acc-integration` compose 注释中提到 `kx-citus-pg17` —— 即此容器就是设计上要取代 `llm-gateway-pg` 的实现。

**操作步骤**:
```bash
# 1. 在 kx-citus 上创建 pocket 数据库(Citus 部分支持,本地节点生效)
docker exec kx-citus psql -U kxuser -d llm_gateway -c "CREATE DATABASE pocket;"

# 2. 停掉旧 pocketd
docker stop opencode-pocket-pocketd-local-opp && docker rm opencode-pocket-pocketd-local-opp

# 3. 用正确 DSN 启动 pocketd(在 bridge 网络,因为 kx-citus 也在 bridge)
docker run -d \
  --name opencode-pocket-pocketd-local-opp \
  --network bridge \
  --add-host=kx-citus:172.17.0.3 \    # bridge 网络不做容器名 DNS 解析,需静态 host entry
  -e POCKET_HTTP_PORT=8088 \
  -e POCKET_POSTGRES_DSN="postgresql://kxuser:audit_admin_pw_local_only@kx-citus:5432/pocket?sslmode=disable" \
  -e POCKET_PG_SCHEMA=opencode_pocket \
  -e POCKET_DEV_AUTH=true \
  -e POCKET_AUTH_USER=admin \
  -e POCKET_AUTH_PASS=d18db57a2e35e792b5223e562be2c3ea \  # 必须 ≥8 字符(原 admin/admin 不行)
  -e POCKET_JWT_SECRET=917a4d4aa7e0b376c571ef37d1c26fad84f4370a8634a0b7 \
  -e POCKET_DATA_DIR=/app/data \
  -p 8090:8088 \
  -v /Users/xutaohuang/Downloads/kaixuan/opp/data:/app/data \
  -v /Users/xutaohuang/Downloads/kaixuan/opp/logs:/var/log/pocketd \
  --restart unless-stopped \
  opencode-pocket:pocket-opp
```

**关键点**:
1. `--add-host=kx-citus:172.17.0.3` — bridge 是默认网络,**不做容器名 DNS 解析**,需静态 host entry 指向实际 IP
2. `POCKET_AUTH_PASS=d18db57a2e35e792b5223e562be2c3ea`(32 字符)— `users.go:48` 拒绝 <8 字符密码,首次 `admin/admin` 重启因密码过短未 bootstrap
3. `POCKET_PG_SCHEMA=opencode_pocket` — `pg.go:80` 自动 `CREATE SCHEMA IF NOT EXISTS`,无需手工建

## 教训

1. **不要轻信容器名 DNS**: 用户原话"llm-gateway-pg位于docker中,不是主机"提示正确诊断方向,但即使在 Docker 中,该服务名仍需 (a) 容器实际存在 + (b) 共享 user-defined network 才解析得到
2. **bridge 网络不做容器名 DNS 解析** —— 这是 Docker 行为,不是配置问题。`--add-host` 是正确做法
3. **bootstrap 密码长度 ≥8 字符** 是 `auth/users.go:48` 硬约束,首启时务必使用长密码
4. **`kx-citus` 是设计上取代 `llm-gateway-pg` 的共享 PG**(注释明确),后续配置应使用 `kx-citus` 这个实际容器名,或由 compose 起 alias
