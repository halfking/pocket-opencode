## 3. CI 审计与修复

**前置事实**：`92e1e4b`（P0 之前的纯文档提交）frontend CI 已红 —— typecheck 报的正是本 commit 修复的 3 个存量错误（usePendingApprovals 签名 ×2 / sqlite-web-init TS2307）。即 main 的 frontend CI 在 P0 之前就是红的，本 commit 已使其 typecheck+build+既有 5 套件转绿。

**本次引入的红（已修复）**：新增步骤 `node --test src/features/tasks/__tests__/health.test.mjs` 在 CI 失败：
```
TypeError [ERR_UNKNOWN_FILE_EXTENSION]: Unknown file extension ".ts" .../health.ts
# Node.js v20.20.2
```
根因：health.test.mjs 直接 import `../health.ts`（与既有 diffParse.test.mjs 同款模式），本地 Node v22.22.3 原生 type-stripping 可跑，CI 钉在 Node 20 不支持。**修复**：`.github/workflows/frontend.yml` node-version `"20"` → `"22"`（Node 20 已 EOL，22 为现行 LTS；两处 job 同步）。

**审计连带修复的存量 CI 断裂（android assembleDebug 作业，92e1e4b 起从未绿过，双重根因）**：
1. `cap sync` 前未构建 web assets —— dist 被 gitignore，报 `Could not find the web assets directory: ./dist` → 补 `npm run build:fast` 步骤（commit `fa1b8df`）。
2. dist 修复后暴露 gradle 真实错误：`@capacitor/android@8` 的 build.gradle 声明 `JavaVersion.VERSION_21`，CI JDK 17 报 `invalid source release: 21` → JDK 17 → 21（commit `cd321fa`）。

**终态**：`cd321fa` 的 frontend workflow **全绿**（run 33066231321，2m30s：typecheck + build + node 测试（node22，含 health 8 用例）+ android assembleDebug 含 @capacitor/local-notifications 插件）。

**存量红（与本次无关，登记不修复）**：
- `backend` workflow：`TestACPStdioAdapter_*` / `TestStdioTransport_*` 系列失败（92e1e4b 同样红，前端改动不触碰该代码路径）→ 移交 P1 前后端联调时排查。
