## 1. 起点：代码在，但判据量的不是声音

§40 修的是「说话人标签在收尾时不丢」。读盘时发现标签本身也是可疑的：
`ingest-speech.ts` 调 `SpeakerDiarizer.identify(embedding)`，而 embedding 来自
`speaker-embedding.ts` 的 `extractWebEmbedding` → `spectrumEmbedding`。

那个函数把音频**按时间均分成 32 块**，每块取平均绝对值：

```ts
for (let b = 0; b < EMBED_DIM; b++) {
  const start = b * chunk, end = Math.min(start + chunk, pcm.length)
  for (let i = start; i < end; i++) sum += Math.abs(data[i])
  bins[b] = sum / (end - start)
}
```

它**只读时域幅度包络，完全不碰频谱**。而音色（音高、共振峰）是频谱量。

## 2. 实测（`node --experimental-strip-types` 驱动真实导出函数，非复制实现）

| 场景 | cosine | 阈值 0.72 下的判定 |
|---|---|---|
| 同一包络，基频差 2.4 倍（男 110Hz vs 女 260Hz） | **0.998473** | 同一人 ❌ |
| 不同的人，不同包络 | **0.241667** | 不同人 ✅（但理由是错的） |
| 解码失败兜底 `hashEmbedding`（同一人两段） | 0.677911 | 每段都算新说话人 |
| 零向量 vs 任意 profile | 0 | 每段都算新说话人 |
| 原生 ECAPA(192 维) vs Web(32 维)，同一人 | 0.229773 | 永远认不出来 |

结论：它实际在测「**这两段话的响度节奏像不像**」，产品要的是「**这是不是同一个嗓音**」。
两个方向都错：同一人换个说法被拆开，不同的人说话节奏一致被并成一个。

## 3. 修：换成 log-mel（48 维 = 24 个 mel 带的均值 + 标准差）

- 均值 = 长期平均谱 → 主要由声道形状决定 = 音色；
- 标准差 = 发音动态 → 语速、口型开合，同属说话人特征。

同一批合成信号（3 男 + 3 女，各自不同句子）：

| | min | max |
|---|---|---|
| 同一人 | 0.9999 | 1.0000 |
| 异人 | 0.9818 | 0.9847 |

**区间无重叠。** 阈值据此从 0.72 改为 **0.99**。

> ⚠ 阈值与特征强绑定：新特征下**任意两段语音**都 > 0.97，沿用 0.72 会把整场会议合并成一个人。

配套修的四处静默失效：

1. `cosineSimilarity` 原来 `min(len)` 截断比较 → 改为维度不等直接返回 `-1`（不可比）。
   用 0 而不是 -1 是错的：0 是合法相似度（「正交」），会让调用方分不清该跳过还是该新建。
2. `ingest-speech.ts` 的 `.catch(() => new Float32Array())` → 改为显式 `null`。
   零向量余弦恒 0 ⇒ **每次提取失败都新建一个说话人**；提取失败是全局性的
   （sherpa 不可用 + webm 解码失败），一个人 30 段话被标成「说话人 1…30」。
   现在走整场共用的兜底标签，并带 `known: false` 标明「本次没区分出来」。
3. 历史库里维度不符的 profile（旧的 32 维包络、192/512 维 ECAPA）永远比不过阈值
   ⇒ 每段都新说话人。新增 `settleDimension`：第一次拿到真向量后**在内存里**清一次。
   刻意不在 `loadProfiles` 里筛 —— 那时还不知道本次是不是原生设备，会误删合法声纹。
4. `blobToEmbedding` 改为复制到 `byteOffset = 0` 的新缓冲区（见 §5.3）。

## 4. 结构性改动：让判据**第一次**跑得起来

`speaker-embedding.ts` 顶部是 `import { sherpa } from './sherpa'`——**无扩展名**
⇒ Node 的 ESM 解析器直接 `ERR_MODULE_NOT_FOUND`
⇒ 整条说话人链路（特征 + 聚类判据）在 Node 里**一行都跑不起来**
⇒ 从来没有任何门守着它。

拆出零 import 的 `speaker-features.ts`（DSP + 判别 + 序列化），
`speaker-diarization.ts` 改指它 ⇒ 两道门写得出来（41 例）。

这与 `voiceprint-writes.ts` 的既有约定是同一条：**决策与 DSP 保持纯，I/O 一律外置**。

## 5. 四次自我更正（这一节是本文档最值钱的部分）

### 5.1 「有环境声就会把同一个人拆开」——我一开始说得比实测严重

第一版注释写的是「底噪足以让同一个人被拆成好几个说话人」，并把它当成加
「有声帧门控」的理由。加完实测：

| 底噪 | 关门控 | 开门控 |
|---|---|---|
| 0.001 | 0.9765 | 0.9815 |
| 0.01 | 0.9267 | 0.9380 |
| 0.03 | 0.7201 | 0.7348 |

门控**一致地好约 0.01**，但**不改变结论**。注释已改成实测值，并写明噪声才是主要敌人。

### 5.2 CMVN：我说它「不做就彻底不能用」，实测不成立

先测了增益扫描：音量 ÷2/÷4/÷8 时撤掉 CMVN 只降 0.000~0.003，**要到 ÷64 才跌破阈值**。
我又测了噪声：0.9765 vs 0.9640——有改善，不决定性。

于是门禁改成断言 CMVN **自己保证的那条性质**（向量均值为 0 = 只编码谱的形状、
不编码绝对电平），而不是断言「撤掉它会崩」。源码注释同步改为实测值。

### 5.3 ⚠ 我写下的「旧代码会抛 RangeError」是**错的**

我在 `blobToEmbedding` 注释里写「非 4 整除长度会抛 `Invalid typed array length`」。
实测：V8 直接截断，`byteLength=11` 照样返回 `length=2`，**不抛**。

真正会炸的是**偏移未对齐**：`byteOffset = 3` 时抛
`RangeError: start offset of Float32Array should be a multiple of 4`。
这才是真缺陷（它在 `loadSpeakerProfiles` 的 `map` 里，一次错位就让整场录音的
说话人列表加载失败，外层 catch 吞成「空库」）。注释与门禁都已改成对齐这一条。

> 这条是**先写断言、再被自己的断言打脸**才查出来的。若只读代码不实测，
> 这条错误注释会长期留在仓库里误导后来人。

### 5.4 两处死代码，是变异验证逼出来的

| 死代码 | 变异结果 | 处置 |
|---|---|---|
| `identify` 循环里的 `isComparable` 守卫 | M10 去掉它，41 例全绿 | 删除（`settleDimension` 已保证维度一致，守卫恒真不可达） |
| `logMelEmbedding` 里的 `if (used === 0) return out` | M10 去掉它，41 例全绿 | 删除（gate 取自 energy 自身的分位数 ⇒ `used >= 1` 恒成立） |

两条都属于「看起来像被覆盖了，其实不可达」。不可达的死代码比缺一行保险更贵。

## 7. 门禁咬住的第一处缺陷是我自己写的

`speaker-features.test.ts` 第一次运行就红了：

```
含 NaN 必须判为不可用
true !== false
```

`isUsableEmbedding` 原来一趟扫：`if (!finite) return false; if (x !== 0) return true`
—— 向量前 7 格是 0.5、第 8 格是 NaN 时，index 0 就 return true，
**排在后面的 NaN 永远看不到**。一个带 NaN 的向量会静默污染该 profile 之后每一次比较。

修法：分两趟扫（先全扫有限性，再扫是否非零）。
**判据的某一侧从未被喂过**——这是 §67 那条教训的又一次复现。

## 8. 合并的代价不对称（决定阈值取向的依据）

- **错误合并**（两个不同的人被认成同一人）→ A 的话被记到 B 名下，纪要、行动项全错。**严重**。
- **错误拆分**（一个人被拆成多个说话人）→ 只是标签多、难看，用户还能手动改名。**轻微**。

所以判据只在「相似度 ≥ 阈值 **且** 明显甩开次优候选（`AMBIGUITY_MARGIN = 0.001`）」时才合并，
其余一律新建。宁可多几个标签，不可错配人。

## 9.5 【2026-10-07 续】用真实人声谱重新标定 —— 合成夹具的结论**是错的**

上面所有「同人 0.9999 / 异人 0.9847，区间无重叠」的结论都来自**合成语音**
（基频 + 三个共振峰的谐波叠加）。为了不拿这个当结论，做了一轮真实人声谱标定。

### 9.5.1 数据来源

MiniMax TTS（`mcode-tools connector__matrix__batch_text_to_audio`），
**9 个音色 × 3 句** = 27 段普通话。其中两个音色是**故意挑得相近**的
（青涩青年 / 青年大学生、御姐 / 少女），用来把判别难度提上去。

```
mp3 --ffmpeg -f s16le -acodec pcm_s16le -ar 16000 -ac 1--> .raw（Int16 LE）
```

落到仓库的是**标定向量**（`frontend/src/native/__tests__/fixtures/real-speech-embeddings.json`，
37 KB，含完整出处），不是音频本身 —— `frontend/src` 总共才 11 MB，
塞 2 MB 音频进去不合适。

### 9.5.2 实测：合成夹具严重高估了余量

| | 合成语音 | 真实人声谱（TTS） |
|---|---|---|
| 同人下界 | 0.9999 | **0.9059**（3 秒段）/ 0.9850（整段） |
| 异人上界 | 0.9848 | **0.9927**（3 秒段）/ 0.9901（整段） |
| 分离窗口 | +0.0151 ✔ | **−0.0826** ✘ |

⇒ 真实数据上**不存在**任何能同时「不拆同人、不并异人」的阈值。

### 9.5.3 阈值权衡曲线（9 音色，同人 27 对 / 异人 324 对）

**整段（5.3~7.6 秒，接近真实 VAD 分段）**

| 阈值 | 同人被拆开 | 异人被误并 |
|---|---|---|
| **0.990（当前）** | **7.4%** | **1.2%** |
| 0.985 | 0% | 3.4% |
| 0.980 | 0% | 7.1% |
| 0.970 | 0% | 12.0% |

**3 秒段（短段，最坏情况）**

| 阈值 | 同人被拆开 | 异人被误并 |
|---|---|---|
| **0.990（当前）** | **66.7%** | 0.3% |
| 0.985 | 44.4% | 0.9% |
| 0.960 | 7.4% | 13.9% |

### 9.5.4 三条结论

1. **0.99 保持不变，但依据从「猜」变成「实测」。** 整段下它是接近最优点；
   再降到 0.985 虽让同人 0% 拆开，异人误并却升到 3.4% —— 那是更严重的错配
   （A 的话被记到 B 名下）。取舍方向仍然正确。

2. **分段长度是主导因素，不是阈值。** 3 秒段落下一个人会被拆成好几个说话人
   （66.7%），而 `vad-segmenter.ts` 的 `silenceMs: 1500` 意味着自然语流里
   **短段是常态**。任何单阈值都改不掉这件事：压到 0.96 能把拆开率降到 7.4%，
   代价是 13.9% 的异人误并。

3. **「同人」与「异人」分布重叠 ⇒ 单阈值聚类原理上就不够。** 要真正对齐需要二者之一：
   - **用已知参会人数做强制分配**（产品已经有 `participants` 输入，
     这条最便宜，且「名单是权威信息」本来就是既有决策）；
   - 换成真实声纹模型（原生 cap-sherpa ECAPA 已有，**Web 侧没有**）。

### 9.5.5 顺带改掉的一个特征缺陷：逐帧 CMVN

标定过程中对比了四个特征变体，结论是**逐帧 CMVN**（每帧减自己的 24 维 log-mel 均值）
在两套数据上**两个错误方向都更优**，于是落地：

| | 合成：分离窗口 | 真实：同人 min | 真实：异人 max |
|---|---|---|---|
| 无逐帧 CMVN | 0.0151 | 0.9059 | 0.9927 |
| **有逐帧 CMVN** | **0.0664** | **0.9441** | **0.9901** |

它去掉的是**帧级**的电平/谱倾斜差异（「麦克风离嘴的距离、这一秒说话响一点」），
这些与音色无关。⚠ 但它**没有**解决分布重叠。

同批对比里还有一个反例值得记：**MFCC 13 + Δ 一阶差分**在合成数据上窗口 +0.0442，
放到真实语音上窗口**变成 −0.0146**（不同说话人的得分比同一人的还高）。
⇒ 韵律差分特征对**句子内容**太敏感，合成夹具完全测不出来。

### 9.5.6 如何重建夹具

1. `mcode-tools connector call connector__matrix__get_voice_list --args '{}'` 取音色表；
2. 对每个音色用 `batch_text_to_audio` 生成 3 句（每次 ≤ 10 条，超过要拆批）；
3. `ffmpeg -i x.mp3 -f s16le -acodec pcm_s16le -ar 16000 -ac 1 x.raw`；
4. 读 Int16 LE → 除以 32768 → `logMelEmbedding(pcm)` → 存 JSON。
   长/短两个版本各存一份（整段 / 截断到 3.0 秒）。

改动 `logMelEmbedding` 后夹具会失真，`speaker-calibration.test.ts` 的
fixture 自检会先红（维度/有限性/单位性/长短不同），提醒重新生成。

### 9.5.7 新增门禁

`frontend/src/native/speaker-calibration.test.ts`（9 例）：

- **夹具自证 3 例**：维度一致、分量有限且是单位向量、样本量符合 9×3、分位数没算反、
  长短两份不是同一份数据。
- **阈值安全性 3 例**：整段异人误并 ≤ 2%、同人拆开 ≤ 15%、同人中位数高于阈值。
- **已知上限 3 例（双向 tripwire）**：短段拆开率 > 50%（一旦变好就打红，
  提示重新标定并更新文档）、短段异人误并仍 ≤ 2%、短段拆开率 > 长段的 2 倍
  （「分段长度是主导因素」这条结论一旦不成立就打红）。

## 9.6 【2026-10-07 续】用真实 ASR 输出标定去重 —— 抓到两个缺陷，其中一个是我自己引入的

`ANCHOR_COVERAGE = 0.6` 与 `OVERLAP_TIME_EPS_MS = 400` 一直标着「尚未按真实 ASR 输出校准」。
这次用同样套路做：MiniMax TTS 生成音频 → MiniMax ASR 转写，拿到的真实输出里
**自带一处同音错误**（ASR 把「走线下处理」听成了「手头先处理」）。

### 9.6.1 数据：先看被撤回的那版，再看正确的

**第一版（已撤回）**：我让 TTS 分别生成「没签的那两个客户我们走线下处理」和
「没签的那两个客户我们手头先处理」，再称之为「真实 ASR 的同音错误」。

**那是个错误前提**：走 zǒu 与 手 shǒu **根本不同音**，而且 ASR 两边都转对了 ——
覆盖率低完全是我自己写不同的字造成的。真实 ASR 什么都没做错。

**正确的数据**：让 TTS 生成**一段** 7.6 秒会议音频（两句），再用 ffmpeg
按不同窗口切分，**每一份都送真实 ASR 转写**：

| 窗口 | 真实 ASR 输出 |
|---|---|
| pre_c (0.0–2.4s) | 这个季度的续费方案，基本 |
| win_a (0.0–4.2s) | 这个季度的续费方案基本上已经定了。 |
| win_b (2.6–7.0s) | 已经定了。没签的那两个客户，我们走线下 |
| 下一句（无重叠） | 评审会，我准备一下对比表。 |

`win_a` 与 `win_b` **覆盖同一段音频**（重叠 1.6 秒），但上下文不同 ⇒ 重叠区
给出的字不一样（win_a 有「基本」，win_b 从句中开始所以没有）。
**这才是真实的切分重叠形态。**

### 9.6.2 缺陷 A：整段被前段包含时原样残留（用户报的「片段重复」）

旧代码两处都写：

```ts
const delta = body.length > prevBody.length ? body.slice(prevBody.length) : raw
```

当新段正文 **100% 已被前段包含**时，`body === prevBody`，于是走 `: raw` 分支，
**把整段原样吐出来**。实测：输入 5 段 → 输出仍是 5 段，
「对比表」在一份转写里出现 **2 次**。

修法：零净增时**整段丢弃**——正文已在累积文本里，丢它不丢内容，只消掉一次逐字重复。
但**只在时间轴确认重叠时才丢**（见 9.6.4）。

### 9.6.3 缺陷 B（更隐蔽）：修好 A 之后，暴露了上游一个既有 bug

修好 A 之后 `refine-plan.test.ts` 转红：第二位说话人的归属消失。
根因不在去重，在 **`attributeFullTranscript`**：

两个原始分段时间范围完全相同（`[0,1000] × 2`），两条回执与它们的距离并列，
而严格的 `>` 比较让**第一条通吃所有正文**，第二条变成它的尾巴重复。
去重识别出「已完全包含」并把第二条丢掉 ⇒ **林岚的归属消失** —— 正是 §40 拼尽全力修回来的东西。

修法：并列时优先给**还没拿到正文**的分段（`pickBucket(preferEmpty)`）。

### 9.6.4 但这个修法第一版是错的，被既有负控当场咬住

`transcribe-full-wire-contract.test.ts` 的负控随即转红。它守的是**可观测性**：

> wire 键被改名 ⇒ 三条回执全塌成 `[0,0]` ⇒ 退化形态**必须**表现为
> 「第 0 段吞掉全场」，输出看起来完全正常、只有标签齐全、归属全错。

我第一版无条件用 `preferEmpty`，结果退化**变得不可见**了 —— 后端改字段名就没人会发现。

区分点很清楚：

| 场景 | 回执时间范围 | 该怎么做 |
|---|---|---|
| `refine-plan` | `[0,9000]` / `[9000,18000]` —— **有位置信息** | `preferEmpty` |
| wire 负控 | 三条全是 `[0,0]` —— **无位置信息** | 回到纯得分（退化必须可见） |

⇒ 加了 `b.start === b.end` 的守卫。**零位置信息的回执按序分给不同分段，
是在假装我们知道它属于谁。**

### 9.6.5 试过降低覆盖率，撤回（**理由也一并更正**）

当时算出的「真重叠下界 0.4667 < 阈值 0.6」是**基于第一版诱导数据的**，
前提就是错的。用正确数据重测，覆盖率是 **0.6471 / 0.9167**，0.6 完全够用。

降档到 0.40 的实测（诱导数据上）：重复确实去掉了，但 LCS 在措辞错位处
只对齐一半，留下一堆残片（有一段最终只剩一个「。」）。

⇒ **维持 0.6**。注意结论没变，但**理由从「阈值不够低」变成了
「降低只会换来残片」** —— 同一结论，不同依据。
§9.6.1 里那个被撤回的「已知缺陷」已从源码注释与门禁中删除，只在文档留档。

★ 教训：**先证明「差异来自被测系统」，再把它算成被测系统的缺陷。**

## 9.65 两阶段接缝的**整体**验算（真实 ASR，全链路）

前面所有门都是单函数门。但本会话在接缝上出过两次问题，形态相同：
修好一处 → 暴露上游另一处 → 再修 → 破坏可观测性 → 再修。
**单函数门全绿，合起来才出问题。** 所以补一道跑整条接缝的门。

数据全部来自真实 ASR：同一段 7.6 秒会议音频按三种窗口切分，各转一次；
整段音频再转一次，服务端按静音切成 2 条回执。

| 阶段 | 输入 | 真实 ASR 输出 |
|---|---|---|
| 一（VAD 窗口） | pre_c 0–2.4s | 这个季度的续费方案，基本 |
| | win_a 0–4.2s | 这个季度的续费方案基本上已经定了。 |
| | win_b 2.6–7.0s | 已经定了。没签的那两个客户，我们走线下 |
| 二（整段重转） | 整段 0–7.6s | 这个季度的续费方案基本上已经定了。没签的那两个客户，我们走线下处理。 |

跑通后的结果：四个关键短语**各 1 次**、两位说话人**都保住**、
收尾正文 `这个季度的续费方案，基本上已经定了。没签的那两个客户，我们走线下处理。`

★ 一个容易被误判的现象：实时正文与收尾正文**必然不同**，
因为实时路径在窗口边界上把一句话切成了「……，基本」+「上已经定了。」，
而整段重转拿回完整句子。**「两阶段不一致」是设计意图，不是回归** ——
门禁里专门写了一条断言把这个区别钉住，免得后人把修复判成 bug。

新增 `meeting-two-stage-asr.test.ts`（11 例）。变异 3 条：
```
✔ T1 归因失效（attributeFullTranscript 恒返回 null）      → 转红
✔ T2 去重失效（dedupeSegments 变成原样返回）             → 转红
○ T3 撤掉「并列时优先空桶」                              → 仍全绿
```
T3 仍绿是**正确的**：本夹具三个窗口时间戳互不相同，回执得分本来就唯一，
优先空桶不改变分配。那个行为由 `refine-plan.test.ts` 守着
（它的夹具刻意让两段时间范围完全相同）。已在门禁头部写明「这道门不覆盖什么」。

## 9.8 【2026-10-07 续】生产区间读数 + 收尾合并：把「标签膨胀 2.31×」修到 0.92×

### 9.8.0 先说这一节在修什么：标定用的是长窗口，生产跑的是短窗口

§9.5 的标定全部基于**整段 5.3~7.6 秒**的 TTS 音频。但生产链路里声纹是
**逐 VAD 段**算的（`ingest-speech.ts:41` 的 `extractEmbeddingResult(opts.blob)`），
而 `VadSegmenter` 用 `silenceMs: 1500` 切段 ⇒ **每次判定只看 1.5~4 秒的一次发言**。

实测两个区间（同一批 27 段真实人声谱向量）：

| 区间 | 同人 min | 异人 max | **分离窗口** | 两人会议 | 三人轮转 | 标签膨胀 | 错合并 |
|---|---|---|---|---|---|---|---|
| 3.0s（**VAD 实际**） | 0.9441 | 0.9901 | **−0.0460** | 2 人 → **5 个标签** | 3 人 → **8 个** | **1.77×** | 0 |
| 5.3~7.6s（§9.5 标定用） | 0.9865 | 0.9943 | **−0.0078** | 2 人 → 2 个 | 3 人 → 4 个 | 1.09× | 0 |

**标定用的区间和生产用的区间不是同一个区间**，窗口差 6 倍。错合并恒为 0 是
§8 那条「宁可错拆不可错并」的设计意图，代价就是膨胀 1.77~2.31×。

### 9.8.1 三条走不通的路（都实测过，别再走）

**① 调阈值。** 0.97 → 标签数达标但错合并 2；0.95 → 17 标签、错合并 3。
分布重叠时降阈值就是拿「张冠李戴」换「标签少」。

**② 改特征参数。** 扫了 15 组（mel 16/24/32/40、FFT 256/512/1024、
`F_MIN`/`F_MAX`、仅均值、+Δ 动态、去逐帧 CMVN 及其组合）：

```
配置                        同人min   异人max    窗口
基线 24mel/FFT512            0.9441   0.9901   -0.0460
mel=16                      0.9537   0.9930   -0.0393   ← 最好的一组
mel=40                      0.9333   0.9863   -0.0531
FFT=1024                    0.9385   0.9885   -0.0500
仅均值(24维)                 0.9099   0.9896   -0.0797
无逐帧CMVN                  0.9059   0.9927   -0.0867
```

**没有任何一组能让窗口转正。** 特征调参这条路可以关掉了。
（扫描器带自检：本实现必须先复现夹具记录的基线 0.9441/0.9901，否则尺子没对上。）

**③ k-means 式二次重分配。** 改写 **0/44 段**。原因是结构性的：
贪心判错时会自建一个**单元素簇**，而单元素簇的质心就是它自己，余弦恒为 1.0
⇒ 每个错分点都「完美匹配自己」，**重分配没有任何压力去合并它们**。
这不是实现问题，是死路。

> ⚠ 读数教训：这一版我第一次跑出 0/44 时差点当成结论。实际是我的循环写坏了
> （`if (next.some(...)) continue` 几乎恒真 ⇒ 质心从未重算）。
> 修好循环后再加一列「归属改写 N/44」的直接计数才敢下结论。
> **簇数不变 ≠ 归属没变**——只看簇数会漏掉真实发生的重分配。

### 9.8.2 有效的杠杆：把「一次发言」换成「一个聚类的全部发言」

3 秒不够长，但一个聚类整场累积下来够长。把聚类成员的声纹取平均
（= 长窗口统计的廉价代理），再做**单链凝聚**：反复合并最接近的两簇，
每次合并后重算均值。

实测（同一批 27 段，阈值扫描）：

| 阈值 | 基线 | 合并后 | 两人会议 | 三人 | 四人 |
|---|---|---|---|---|---|
| 0.99 | 30（2.31×）错 0 | 30（2.31×）错 0 | — | — | — |
| 0.97 | 30（2.31×）错 0 | 15（1.15×）错 1 | | | |
| **0.95** | 30（2.31×）错 0 | **12（0.92×）错 1** | 5→**2** | 8→**3** | 7→3（真值 4） |
| 0.90 | 30（2.31×）错 0 | 10（0.77×）错 2 | | | |

⚠ **0.99 档一次都不合并** ⇒ 阈值**不能**照抄 `SAME_SPEAKER_MIN`。
两者量纲相同但含义不同：0.99 是「这次发言 vs 那次发言」，
0.95 是「一簇的全部发言 vs 另一簇的全部发言」，后者的统计量本身就稳得多。

⚠⚠ **代价写在明处**：0.95 档有 **1 例错合并**（四人会议里两个不同的人被并了）。
换来的是膨胀 2.31×→0.92×。选它的理由是 §8 的代价不对称：
错合并的纪要**已经被污染**，而标签多用户可以手动改名。

**与「拼接音频重算」对比**：把该簇的发言按 1500ms 静音拼起来重新提特征，
效果与「成员声纹取平均」**基本相当**（0.95 档 13 vs 12 个标签，错合并都是 1），
但需要解析 WAV、切片、重算音频。取平均省掉这一整套，实现成本差一个量级。

### 9.8.3 接线：收尾合并，只回贴仍是占位标签的段

- `SpeakerDiarizer.identify()` 顺带把每次的声纹记进 `samples`；
  `relabel()` 在收尾时合并并摘掉死簇。
- `recordingRuntime.stop()` **在等 `inFlightSegments` 清空之后**、
  置 `completed` 之前调用。提前调用会漏掉最后几段——
  而那几段常是让某个聚类变得可判定的关键。
- 决策抽成纯函数 `planSpeakerRelabel`（runtime 拖进 vue/capacitor，
  决策留在里面就一行行为门都没有）。
- ★ **只回贴仍是 `说话人 N` 的段**。用户中途亲手改过名的段，
  他的标签是他自己的输入，自动聚类无权覆盖（§40 刚把这件事修回来）。
- ★ **用户改过名的 profile 是锚点**，永不参与合并（可被吸收，自身不发起）。

### 9.8.4 我自己引入的一个缺陷，被门禁当场咬住

第一版在合并后把存活方的 embedding **换成聚类均值**，想着「这样下次比较更准」。
门禁立刻红了：合并后同一个人的新发言对合并质心的实测余弦是
**0.9970 / 0.9912 / 0.9895**（阈值 0.99）⇒ 第三段直接又分裂成新说话人。

根因是**两套统计量的标定基准不同**：`SAME_SPEAKER_MIN` 按「单次发言 vs 单次发言」
标定，而聚类均值是长窗口统计，单次发言去比它系统性偏低。

而且这不是不可达假设：diarizer 在**同一 session 内换场录音时会被复用**
（`if (freshSession || !this.diarizer)`）⇒「录完合并 → 再录一场」就会踩到。
⇒ 合并只负责**分组**，比对基准保持不变。
