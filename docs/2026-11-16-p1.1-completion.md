#### 交付物

   - 功能: 显示笔记同步状态的指示器组件
   
2. **syncState.ts** (220 行)
   - 位置: `frontend/src/stores/syncState.ts`
   - 功能: Pinia store 管理同步状态

#### 功能特性

**5 种同步状态**:
- ✅ 已同步 (绿色) - 笔记已成功同步到 memora
- 🔄 同步中 (蓝色，脉冲动画) - 正在同步中
- ⚠️ 冲突 (橙色) - 检测到本地和远程冲突
- ❌ 同步失败 (红色) - 同步出现错误
- 📴 离线 (灰色) - 网络不可达或 memora 未配置
- ⏳ 待同步 (黄色) - 本地编辑后等待同步

**交互功能**:
- 单击显示详情弹窗
- 显示最后同步时间、memora ID、错误信息
- 冲突状态时显示"解决冲突"按钮
- 自动轮询后端状态（30秒间隔）

**UI/UX 亮点**:
- 响应式设计，适配移动端
- 平滑过渡动画
- 悬停效果
- 颜色语义化（绿/蓝/橙/红/灰）
- 相对时间显示（刚刚/X分钟前/X小时前）

#### Store 设计

**syncState.ts 核心方法**:
```typescript
// Getters
getSyncState(noteId) // 获取笔记同步状态

// Actions
fetchSyncStatus(noteId?) // 从后端获取状态
markPending(noteId) // 标记待同步
markSyncing(noteId) // 标记同步中
markSynced(noteId, memoraId?) // 标记已同步
markConflict(noteId) // 标记冲突
markError(noteId, errorMessage) // 标记错误
resolveConflict(noteId, resolution) // 解决冲突
pullSync() // 手动触发同步拉取
clearState(noteId) // 清除状态
```

**API 集成**:
- `GET /api/sync/status` - 获取全局同步状态
- `POST /api/sync/resolve/:noteId` - 解决冲突
- `POST /api/sync/pull` - 拉取 memora 更新

## 🔧 技术决策

### 为什么使用独立的 syncState store？
- 与 knowledgeSearch store 职责分离
- 状态管理更清晰
- 可以在多个组件中复用
- 支持多个笔记同时管理状态

### 为什么选择 30 秒轮询？
- 平衡实时性和性能
- 避免频繁的网络请求
- 用户感知足够快
- 可配置（未来可优化为 WebSocket）

### 为什么使用 Map 存储状态？
- O(1) 查找性能
- 支持大量笔记
- 易于更新和删除
- TypeScript 类型安全
