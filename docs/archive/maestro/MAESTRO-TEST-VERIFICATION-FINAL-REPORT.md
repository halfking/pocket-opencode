### 2.2 关键发现：Android WebView 不支持 resource-id 映射

**根本原因**（Git commit 5b05e4d3，2026-10-27）：
- Android WebView **不会**将 DOM 的 `data-testid` 映射成无障碍节点的 `resource-id`
- 所有 `id:` 判据在 Android 平台上**恒假**
- 必须使用 `index:`、坐标或文本选择器替代

**修复文件**（7 处）：
1. `.maestro/_set-master-password.yaml` - 主密码输入框（2 处）
2. `.maestro/_login.yaml` - 解锁和 SSO 登录输入框（3 处）
3. `.maestro/regression-test-suite.yaml` - 笔记输入框（2 处）

**修复示例**：
```yaml
# 修复前（恒假）
- tapOn: { id: "master-password-input" }

# 修复后（使用 index）
- tapOn:
    index: 0
```

## 四、根本原因分析与修复（已完成）

### 4.1 核心问题定位

#### 问题 1：BACK 键导航错误
**现象**：BACK 键返回到电影列表页面而非 OpenPocket 首页  
**原因**：Android 系统导航栈问题  
**修复**：使用底部导航按钮替代 BACK 键

#### 问题 2：导航栏加载时序
**现象**：创建主密码后底部导航栏未完全加载  
**原因**：初始化耗时操作（SQLCipher + 向量索引）  
**修复**：
- 使用精确坐标点击 `(135, 2243)` 替代文本匹配
- 增加导航栏加载等待 `extendedWaitUntil`
- 调整验证时序（先返回首页，再验证导航栏）

#### 问题 3：恒假的 id 判据
**现象**：所有 `id:` 选择器无法匹配元素  
**根本原因**：Android WebView 不支持 resource-id 映射（Git commit 5b05e4d3）  
**修复**：7 处 `id:` 判据全部改为 `index:` 或文本选择器

### 4.2 应用的解决方案

**核心修复策略**：
1. ✅ **坐标点击导航**：`(135, 2243)` 点击首页按钮
2. ✅ **导航栏等待策略**：确保页面完全加载
3. ✅ **验证时序调整**：先导航再验证
4. ✅ **Smoke 成功模式复用**：经过验证的可靠方案
5. ✅ **index 定位替代 id**：适配 Android WebView 限制
