# 10 任务拆解与依赖图

**版本**：优化 v4
**日期**：2026-08-14
**说明**：owner 是职责归属，不代表当前已分配人员；所有任务按仓库现状拆分，先复用已有模块，再新增边界清晰的能力。

## 1. 角色与并行组

| 角色 | owner 代号 | 主要边界 |
|---|---|---|
| 产品/验收 | PO | 场景、优先级、验收样本、发布裁决 |
| 移动架构 | MA | 状态模型、路由、事件契约、Capacitor 边界 |
| 前端基础 | FE-Core | tokens、共享组件、store、路由守卫、WS bus |
| 前端功能 | FE-Feature | Notes/Email/Vault/AI 页面，不改后端契约 |
| 后端 API | BE-API | handler、DTO、作用域、错误和幂等 |
| 实时/Agent | BE-Realtime | ACP、会话、审批、WS 快照与事件 |
| 原生 Android | AND | 权限、录音、Keystore、后台任务、构建 |
| 安全 | SEC | 威胁建模、越权、敏感数据、日志和依赖审查 |
| QA/设备 | QA | 自动化、设备矩阵、故障注入、回归证据 |
| 发布运维 | REL | CI 门禁、feature flag、迁移、监控、回滚 |

## 4. 并行执行规则

- **G0** 只产出契约、发布前置和测试设计，不改业务源码；完成后由 MA/SEC/PO/REL 签字。
- **G1** 可并行改前端基础，但 `router-mobile.ts`、WS bus 和共享组件必须由 FE-Core 统一合并，避免互相覆盖。
- **G2/G3** 可并行；任何后端 DTO 变更必须先更新 E0-S2。E2-S3 只有在 E0-S5 明确纳入首批时才启动。
- **G4** 是 P1：原生插件和可写 outbox 不得阻塞 P0；原生能力不得删除 Web fallback。
- **G6** 的 E6-S1 是 P0a 发布基础，E6-S2 至 E6-S5 按各自阶段完成；不得以“存在 flag/迁移回滚”但未定义实现来替代证据。

## 5. 风险驱动排序

先做 E0-S3、E2-S2、E3-S4、E0-S6，再做视觉扩展：审批误操作、越权、回滚不可操作和跨 workspace 数据泄露的代价高于页面丰富度。任何任务发现既有契约与实际代码不一致，应先开阻塞问题并更新契约，不在 feature PR 内静默兼容多个语义。
