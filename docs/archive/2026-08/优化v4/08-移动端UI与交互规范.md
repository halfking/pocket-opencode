# 08 移动端 UI 与交互规范

**版本**：优化 v4
**编写日期**：2026-08-14
**适用范围**：Vue 3 + TypeScript + Capacitor Android 客户端；后续 iOS 复用信息架构与状态契约
**证据边界**：本规范吸收仓库已有 UI/UX 设计系统、移动架构、前端蓝图和 2026-08-12 UI 审计结果。规范中的“目标”不是“已实现”，以第 09 篇验收结果为准。

## 1. 产品与设计约束

### 1.1 核心任务

移动端首先解决三类任务，而不是把桌面端缩小：

1. **看清状态**：会话、任务、工具调用、同步和待处理请求在一屏内可判断。
2. **安全地作出决定**：权限请求、问题请求、删除、同步恢复等不可逆或高风险操作必须可理解、可撤销或可追溯。
3. **低成本输入**：文字优先保证可靠，语音作为加速入口；网络或原生能力不可用时仍能完成本地记录。

### 1.2 既有基础与边界

- 已有 `frontend/src/styles/tokens.css` 统一颜色、字号、间距、圆角、阴影、动效和暗色别名。
- 已有暗色模式、`prefers-reduced-motion`、`focus-visible`、skip link、`main` landmark、底部导航 `aria-current`。
- 2026-08-12 审计记录 `vue-tsc --noEmit` 与 `npm run build` 已通过；该结论仅覆盖当时已有代码，不代表本规范新增工作已通过。
- 受保护路由逐页审计、原生 Kotlin 插件、真实 PG/kxmemory/ACC 集成、性能压测和渗透测试仍需单独验收。
- 移动端默认单栏；平板/横屏可使用双栏，但不能把“检测到更宽屏幕”当作“存在第二块物理屏幕”。

## 2. 视觉语言

### 2.1 令牌使用规则

| 类别 | 规则 |
|---|---|
| 颜色 | 只使用 `tokens.css` 语义变量；成功、警告、错误、信息和待审批必须同时有文字/图标，不得只靠颜色 |
| 文字 | 正文默认 16px；次要信息不低于 14px；代码使用等宽字体并允许横向滚动 |
| 间距 | 4px 基线；页面水平边距 16px；卡片内部 12–16px；危险按钮与普通按钮至少 8px 间隔 |
| 圆角 | 输入/标签用小圆角，卡片用中圆角，Bottom Sheet/对话框用大圆角；同一页面不混用无语义的临时值 |
| 动效 | 快速反馈约 150ms、展开约 250ms、页面转场约 350ms；所有动效必须有 reduced-motion 分支 |
| 层级 | 页面内容 < 浮层 < Bottom Sheet < 模态对话框；禁止用任意 z-index 破坏层级 |

### 2.2 页面骨架

- **顶栏**：标题、返回、上下文操作。返回必须有可访问名称；详情页不以仅图标按钮承载唯一导航语义。
- **内容区**：列表默认摘要优先；完整正文、工具输出、推理和 diff 使用折叠区，折叠按钮要读出当前状态。
- **全局状态条**：连接、同步、离线队列、错误和处理中状态置于内容上方或页面内，不用只显示 Toast。
- **底部导航**：统一采用最多 4 个高频入口加“更多”（当前推荐为“今日/收集/智能体/更多”）；当前项同时有图标、文字和 `aria-current`；详情/编辑态隐藏或降级底部导航，避免误离开。
- **浮动录音入口**：只在有录音权限且当前页面允许录音时出现；必须有 `aria-label`、录音中 `aria-pressed` 和可读状态文本。

### 2.3 信息密度

- 列表项最小高度 72px；核心操作触摸区域至少 48x48dp，推荐 56x56dp。
- 摘要最多 2 行，标题最多 1 行；截断内容必须可进入详情，不得把省略号当作完整信息。
- 同一列表只保留 1 个主操作和不超过 2 个次操作；删除、拒绝等危险动作放入二次确认或明确滑出操作。
- 空状态包含“当前没有什么”“为什么为空”“下一步怎么做”三部分。
- 加载状态使用局部骨架或 spinner；错误状态包含重试和保留已加载内容的策略。

## 3. 交互规范

### 3.1 触摸、手势与键盘

- 点击是唯一必备路径；长按、滑动、捏合均为增强路径，不得成为完成任务的唯一方式。
- 列表滑动动作先露出操作，再在阈值后触发；危险动作默认不因轻微误滑立即执行。
- 不使用“三指下拉”等系统/厂商不一致手势作为核心功能。
- Android 返回键遵循：关闭浮层 → 退出选择模式 → 返回上级页面；表单有未保存修改时先确认。
- 外接键盘与 WebView 场景下，Tab 顺序、Enter/Space、Escape 必须可完成主要流程；焦点不可被关闭的浮层吞掉。

### 3.2 语音输入

状态文案必须明确“录音中 / 转写中 / 需要确认 / 已保存 / 失败可重试”。推荐流程：

1. 点击或按住录音按钮，显示权限说明和录音计时。
2. 录音中实时显示可选的转写预览，不能把预览误标为已保存内容。
3. 停止后进入“转写中”，允许取消；转写结果先进入可编辑确认区。
4. 用户确认后才创建笔记、发送 Prompt 或执行命令。
5. 命令类语音（批准、拒绝、删除、发送）必须展示解析结果并二次确认，不能仅凭 STT 直接执行高风险动作。

### 3.3 权限/问题请求

- 权限卡片显示动作、目标资源、影响范围、来源会话和当前状态；长路径提供完整值的展开/复制方式。
- 默认动作分为“仅此一次”“本会话允许”（若后端支持）和“拒绝”；“始终允许”必须单独解释持久化范围，不作为视觉上最强的默认按钮。
- 代码 diff、命令、文件变更和外部目录访问使用折叠详情；详情加载失败时禁止显示“看起来已安全”的结论。
- 批量请求逐项可见，批量批准显示数量和范围；任何批准响应失败都要保留请求并提供重试，避免 UI 假装完成。
- 不以滑动批准/拒绝作为唯一入口；若实现滑动，必须有等价按钮、阈值提示、撤销窗口和触觉/视觉反馈。

## 4. 状态模型

### 4.1 通用异步状态

所有 feature store 和视图统一使用：

```text
idle → loading → ready
             ├→ empty
             └→ error(retryable | terminal)
ready/empty → refreshing → ready | error(保留旧数据)
任何状态 → offline（保留本地数据与待发送队列）
```

规则：同一请求有 request id；过期响应不得覆盖新数据；取消不是错误；错误需保留用户可执行的下一步。

### 4.2 应用与数据层

```text
auth: unknown → unauthenticated → authenticating → authenticated → expired
lobster: uninitialized → initializing → ready | failed → locked
network: unknown → online → degraded → offline → online
sync: clean ↔ pending → syncing → synced | conflict | failed
```

- `authenticated` 不等于 `lobster ready`；本地加密数据库/密钥未初始化时，Vault、Notes 等页面必须阻止进入或显示解锁界面。
- `offline` 下本地读和可离线写可继续；云端审批、发送邮件、同步恢复等必须显式标记为待联网。
- 冲突不得静默覆盖；显示版本、时间、来源和可选操作。

### 4.3 会话与工具状态

```text
session: unknown → idle → running → waiting_user → completed
                                  ├→ failed
                                  └→ cancelled
```

`waiting_user` 是会话层聚合状态；它必须由底层 `Run.waiting_approval` 或 `Run.waiting_question` 映射而来，不能替代 Approval/Question 各自的状态机。

工具执行至少支持 `queued / running / completed / error / cancelled`。流式消息按 `event id` 去重，断线重连后以快照校正，不依赖客户端“猜测”最终状态。

### 4.4 Run、Approval 与 Question 的映射

- **Run 状态**：`queued / running / waiting_approval / waiting_question / succeeded / failed / cancelled / expired`，描述一次执行尝试。
- **Approval 状态**：`pending / submitting / approved / rejected / expired / failed`，描述一次授权决定；`approved` 不代表 Run 已成功。
- **Question 状态**：`pending / submitting / answered / expired / failed`，描述等待用户补充信息。
- **Session 聚合**：只读地将 Run 的 `waiting_approval` 或 `waiting_question` 映射为 `waiting_user`；服务端事件确认前不得渲染成功。

### 4.5 审批状态

```text
pending → submitting → approved | rejected | expired | failed
```

`failed` 不等于 `rejected`；服务端未确认时按钮不得改成已批准。重复事件必须幂等，已结束请求不得再次弹出阻塞式审批。

## 5. 可访问性验收基线

- 触摸目标至少 48x48dp，推荐 56x56dp，邻接间距至少 8dp。
- 正文与背景对比度目标至少 4.5:1，大字至少 3:1；状态图标/边框至少 3:1。
- 所有图标按钮有可访问名称；装饰图标 `aria-hidden=true`；表单控件有可见 label 或等价语义。
- 加载、保存、转写、同步、连接和审批结果使用 `role=status`/`aria-live`；错误使用 `role=alert`，避免重复播报。
- 支持系统字号放大、横竖屏、暗色模式和 reduced motion；文字不因放大而被固定高度裁切。
- 读屏顺序与视觉顺序一致；Bottom Sheet/对话框打开时焦点进入，关闭时回到触发控件。
- 可访问性测试覆盖 Login、AI/Tasks、Notes、Email、Vault、Settings 及所有新增审批/语音路径；仅 SPA shell 审计不能视为全路由通过。

## 6. 错误与通知

| 情况 | 首选反馈 | 允许的补充 |
|---|---|---|
| 保存成功 | 页面内状态 + 可读 status | 短 Toast |
| 可重试网络错误 | 页面内错误、重试、保留旧数据 | Snackbar |
| 权限被拒 | 就地说明所需系统权限和设置路径 | 系统权限提示 |
| 高风险失败 | 明确失败原因、保留上下文、重试/取消 | 不自动重试造成副作用 |
| 后台完成 | 未读角标/通知中心；进入页面后定位 | 非阻塞横幅 |

禁止使用 `alert()` 作为唯一错误反馈；禁止把 console 日志当作用户可见状态。

## 7. 组件 Do/Don't

- **Do** 使用共享 `Input`、`Textarea`、Button、Modal/BottomSheet 和 tokens；**Don't** 在 feature 内复制一套颜色、z-index 或动效。
- **Do** 为异步操作禁用重复提交并显示进度；**Don't** 只在按钮文字中隐含 loading。
- **Do** 显示内容来源和更新时间；**Don't** 把本地缓存伪装成实时数据。
- **Do** 对 Markdown/HTML 使用既有安全清洗路径；**Don't** 直接注入未经清洗的邮件或 AI 输出。
- **Do** 允许用户取消和恢复；**Don't** 用不可逆手势替代确认。
