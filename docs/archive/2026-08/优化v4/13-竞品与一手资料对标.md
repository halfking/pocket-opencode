## 3. 可借鉴与不应照搬

### 可借鉴

1. GitHub 的远程 agent、分支和 PR 让“生成”与“合并”分离，适合本项目把 AI 操作、diff、审查和审批分层。
2. Replit 的移动体验导向说明小屏应围绕用户目标重新组织，而不是简单压缩桌面 UI。
3. 官方设计规范共同强调可访问触摸目标、状态反馈、系统权限和平台适配；本项目应把这些变成可测 DoD。

### 不应照搬

1. 任何“可在手机查看/聊天/跟踪”的证据都不能扩张成“可在手机批准代码执行”。
2. Agent 能改分支或生成 PR 不代表它能自动合并、绕过权限或替代人工审查。
3. 桌面 IDE 的多面板、长 diff 和终端输出不能原样搬到窄屏；移动端必须摘要优先、详情可展开。
4. 第三方平台的云端权限模型不能替代 Pocket 后端的 user/workspace/resource 校验。

## 4. 研究结论与产品措辞

推荐对外措辞：

> OpenCode Pocket 是连接已配置 OpenCode/ACP agent 的 Android 优先移动工作台，提供会话查看、流式状态、权限请求展示和经服务端确认的操作响应。

禁止措辞：

- “官方 Codex 手机 App”。
- “Codex 已支持手机审批”。
- “手机可直接批准任意代码执行”。
- “竞品都支持移动端审批”。
