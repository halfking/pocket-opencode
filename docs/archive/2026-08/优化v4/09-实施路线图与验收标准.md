# 09 实施路线图与验收标准

**版本**：优化 v4
**日期**：2026-08-14
**目标**：把现有 Vue 3 + Capacitor + Go 能力收敛为可安全使用的移动端 AI 编程工作台；先闭环，再扩展，不以“文档设计完成”替代产品验收。

## 1. 基线与口径

### 1.1 已有证据

- 仓库已有认证、实例/任务/会话、ACP Stdio Adapter、权限/问题管理、WebSocket 定向广播、Notes/Email/Vault 等基础模块。
- 2026-08-12 UI 审计记录：设计 token、暗色、reduced motion、focus-visible、skip link、main landmark、导航语义和多处错误/ARIA 状态已落地；`vue-tsc --noEmit`、`npm run build` 当时通过。
- 2026-08-08/09 审计记录：Go build、vet、带 Postgres 的测试、部分 race、前端 typecheck/build 通过；真实邮箱链路已用本地 IMAP 内存服务器与一次性 Postgres 测试覆盖。
- 已知盲区：受保护路由逐页审计、原生插件、真实 OAuth、真实 kxmemory/ACC 集成、生产规模性能、渗透测试和前端自动化测试运行器。

以上是历史报告中的结果，不是本路线本轮重新执行的结果。本路线所有“通过”均须附命令、环境、提交和日志。

### 1.2 指标原则

先在 P0 建立基线，再在同一设备/网络/数据集上比较。没有基线时不得写“提升 xx%”；只写“目标值”和“待测”。指标分为用户可感知、可靠性、安全性和工程质量四组。

## 2. P0–P3 路线

### P0：安全可用的核心闭环（拆为 P0a/P0b；总计建议 3–4 个 Sprint）

- **P0a（安全止血，1–2 Sprint）**：登录/解锁、workspace/resource scope、WS/SSE 凭据边界、状态/事件契约、前端 CI 基础。
- **P0b（核心体验，2 Sprint）**：AI 会话列表与详情、流式事件、权限/问题请求、断线恢复、Notes/Email/Vault 关键详情和移动端可访问性基线。

该估算以至少一组 BE、FE、QA/SEC 并行资源为前提；原生语音、可写离线 outbox、冲突解决和统一 `/api/v4` 控制面不作为 P0 发布阻塞。

**交付**：

1. 统一状态模型：auth、lobster、network、sync、session、tool、approval；事件幂等与过期响应保护。
2. 移动端高风险审批 Bottom Sheet：目标、影响、详情、仅一次/会话允许/拒绝、服务端确认、失败重试。
3. WebSocket 快照 + 增量事件 + 重连退避 + 订阅清理；断线时只保证可读缓存、事件去重和不误报成功。可写待发送队列与冲突解决放入 P1。
4. Notes/Email/Vault 详情页、错误/空/加载/离线状态和路由守卫；敏感字段复制自动清理与生命周期清理。
5. Android 真机/模拟器最小发布链路和日志采集。

**量化目标**：

- 核心任务（登录→打开会话→查看流→处理审批）成功率 ≥ 95%，测试样本至少 20 次/设备档位。
- 已有数据下冷启动首屏 P50 ≤ 2.5s、P95 ≤ 4s；从点击到视觉反馈 P95 ≤ 150ms。实际值待测。
- WS 断线后 ≤ 30s 内恢复或明确显示离线；重复/乱序事件不造成重复消息或错误批准。
- 关键页面无 P0/P1 可访问性缺陷；触摸目标和对比度抽样 100% 合格。
- 高风险动作未获服务端确认时“已批准”误显示率为 0。

### P1：效率与离线能力（建议 2–3 个 Sprint）

**范围**：语音转写确认、离线 Notes/Tasks、同步冲突、搜索/过滤、通知中心、邮件同步状态和可恢复任务。

**量化目标**：

- 离线创建笔记成功率 ≥ 99%（≥100 次故障注入）；恢复联网后幂等同步，无重复记录。
- 语音流程“录音→转写预览→确认保存”完成率 ≥ 90%；无权限/无网络时有可执行替代路径。
- 列表首屏内容在 2.5s 内可操作；1000 条本地条目滚动无明显卡顿，具体帧率以设备实测报告为准。
- 未读/审批/同步通知不丢失；通知点击能定位到具体资源。

### P2：多模块与大屏适配（建议 3–4 个 Sprint）

**范围**：会议录音/转写/摘要、双栏平板布局、代码 diff、会话搜索/归档、企业集成只读状态、可选 TTS。

**量化目标**：

- 会议录音暂停/继续/取消/恢复覆盖率 100%；异常退出不遗失已落盘片段。
- 平板/横屏双栏下主内容可独立滚动，窄屏回退单栏；无横向溢出和遮挡。
- Diff 在 5,000 行输入下可分段渲染；性能阈值以真实设备基线确定，不以桌面浏览器代替。
- AI 生成结果明确标注模型、时间和“需人工确认”，不可直接转为已执行操作。

### P3：企业化与扩展（建议 3–4 个 Sprint）

**范围**：多租户治理、审计查询、成本/配额、iOS 编译验证、插件能力、发布运维和灾备。

**量化目标**：

- 跨 workspace 读写隔离测试覆盖所有新增资源；越权请求统一拒绝且不泄露存在性。
- 审批、同步、密钥、模型调用和导出行为有可检索审计事件；敏感值不进入日志。
- iOS 只在构建、安装、核心导航和关键流程真实验证后标记支持；未验证则标为预览。
- 发布包可回滚到上一稳定版本，数据库迁移可前向执行并有恢复演练记录。

## 3. Definition of Done（通用）

一个 Story 只有同时满足以下条件才可关闭：

1. 范围与非目标写入 PR 描述，接口/状态/错误契约已更新。
2. 代码通过项目已有格式、类型检查和对应单元/集成测试；测试命令和输出附在 PR。
3. 关键交互覆盖 loading、empty、error、offline、retry、cancel、success；敏感操作覆盖权限与审计。
4. UI 通过浅色/暗色、窄手机、横屏/平板、系统字号、reduced motion、键盘/读屏人工检查。
5. 不新增未审查依赖；安全清洗、作用域、超时、幂等和日志脱敏得到 reviewer 明确确认。
6. 迁移有 up/down 或明确不可逆说明；回滚步骤经过演练或标注“待演练”。
7. 文档、截图/录屏、测试数据和已知限制齐全；未执行项目不得写成通过。

## 4. 分阶段验收门

| 门 | 必须满足 | 证据 |
|---|---|---|
| P0-A 设计门 | 状态图、事件表、权限动作矩阵、移动 UI 规格获评审 | ADR、设计评审记录 |
| P0-B 工程门 | `go test`/`go vet`、前端 typecheck/build、关键单测通过 | CI 日志；若 DB-gated 需显示 DSN 已配置 |
| P0-C 设备门 | Android 模拟器 + 至少一台真机完成核心流程 | 设备、版本、录屏、缺陷清单 |
| P0-D 安全门 | 越权、重复审批、断线、日志脱敏、危险动作确认通过 | 测试报告与审计事件样例 |
| 发布门 | 无未豁免 P0/P1；回滚演练完成；监控和告警可用 | 发布清单、回滚日志 |

## 5. 建议验证命令与状态声明

以下是执行清单，不代表本次已执行：

```bash
(cd backend && go test ./... -count=1)
(cd backend && go vet ./...)
(cd frontend && npm run typecheck)
(cd frontend && npm run build)
```

带数据库的测试必须先提供隔离的 `POCKET_TEST_POSTGRES_DSN`；真实邮箱、OAuth、ACC、kxmemory、原生插件和性能测试不能用上述命令的通过替代。Android 构建事实源是 `frontend/android/`（使用其 `gradlew` 和 Gradle 配置）；根 `android/` 当前仅保留占位 README 与 Capacitor 同步脚本，不得作为第二套发布工程。

## 6. 发布与回滚原则

- 功能开关优先于大范围上线；但仓库当前没有统一 feature-flag 基础设施，必须先由 REL 定义服务端配置位置、前端读取方式、默认值和旧路径回退，再宣称“可关闭”。审批、语音、后台同步和新事件类型均可独立关闭。
- 客户端事件解析必须向后兼容未知事件；服务端先发布兼容字段，再发布依赖字段的客户端。
- 回滚应用版本不自动回滚不可逆数据；迁移先做备份、容量评估和恢复演练。
- 发现安全越权、误批准、数据丢失、进程崩溃或敏感信息泄露时立即停止扩量，保留现场并回滚相关开关/版本。
