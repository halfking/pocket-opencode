# 14 首批 PR 与执行顺序

**版本**：优化 v4
**日期**：2026-08-14
**目标**：用 13 个小边界 PR 建立可回滚的 P0 基础，避免把状态、审批、页面、后端和设备能力揉成一个不可审查的大 PR。

## 1. 合并前总规则

- 每个 PR 只有一个主题，描述范围、非目标、影响文件、测试命令和回滚方式。
- PR 必须基于前置 PR 的合并提交；若需并行，禁止同时重写同一文件的同一段。
- 所有测试报告区分“已执行通过 / 已执行失败 / 阻塞 / 未执行 / 未确认”。
- 不在首批 PR 中引入独立移动端 Codex、手机审批宣传、iOS 支持承诺或未经验证的原生能力。
- 每个 PR 合并后保留可构建主线；发现 P0 回归立即停止后续合并。

## 3. 合并分组与顺序

```text
PR1
 ├─> PR2 (仅当 /api/v4 纳入首批)
 ├─> PR3 ─> PR4
 ├─> PR6
 └─> PR5 ─┬─> PR7 ─> PR8
          └─> PR13 (P1，可延后)
PR9 ───────┬─> PR10
PR6+PR8+PR9+PR10 ─> PR11
PR1 ───────────────> PR12
PR12+PR13+PR14 属于发布/设备扩展，不阻塞 Web fallback 的 P0b，除非发布门明确要求。
```

- **串行核心**：1 → 3 → 4；5 与 6 可在 1 后并行；7 依赖 4/5；8 依赖 5/6/7。
- **后端并行**：9 可与 5–8 并行，但 10 必须等 9 合并。
- **Control-plane 决策**：2 不得隐式进行；只有 PR1 将 `/api/v4` 纳入首批，才进入实现，否则提交 ADR 标注 P1。
- **质量汇总**：11 必须在 P0 功能完成后执行，不用早期 mock 结果替代。
- **发布基础**：12 明确 CI/Android gate；未通过不得标记 P0 可发布。
- **P1 扩展**：13/14 是离线可写和原生能力，不阻塞 Web fallback 的 P0 发布。

## 4. 每个 PR 的审查清单

### 代码与契约

- [ ] 改动未越过表中边界；没有顺手重构无关模块。
- [ ] 新字段/事件/错误码有兼容策略和示例。
- [ ] user/workspace/resource scope、大小限制、超时、幂等和日志脱敏经过 reviewer 检查。
- [ ] 共享组件和 tokens 已复用，没有临时 z-index、颜色或 alert。
- [ ] 若写“关闭 flag”，必须指向 PR1/PR12 定义的配置项、默认值、读取路径和旧路径回退。
- [ ] 若包含迁移，必须给出 up/down；不可逆时列出备份点、前向兼容和应用层回滚方式。

### 测试与证据

- [ ] 只报告本 PR 实际执行的命令和环境。
- [ ] DB-gated、真实邮箱/OAuth/ACC/kxmemory、原生设备和性能项目若未执行，明确列出。
- [ ] P0 PR 有至少一个失败路径和一个回滚路径验证。
- [ ] UI PR 有浅色/暗色、窄屏、横屏/字号/读屏检查记录。

### 产品与安全

- [ ] 审批未收到服务端确认时不显示成功。
- [ ] 手机查看/跟踪能力没有被措辞扩大为官方 Codex 移动端或手机审批。
- [ ] 高风险动作可取消、拒绝、重试，并有审计关联 ID。
- [ ] 迁移和数据变更已评估容量、锁表和恢复边界。

## 5. 回滚决策表

| 现象 | 立即动作 | 后续 |
|---|---|---|
| UI 显示 approved 但服务端未确认 | 立即关闭 PR8 flag，保留请求为 failed/pending | 修复确认状态和重放测试，重新走 PR11 |
| 跨 workspace 读写或敏感泄露 | 停止扩量，回滚 PR6/9/相关服务版本，保留审计 | 增加正反向越权测试，SEC 签字后重发 |
| 客户端崩溃/原生能力不可用 | 关闭 PR14 插件 flag，回退 Web fallback | 修复能力探测、权限和生命周期 |
| 迁移失败或锁表 | 停止发布，恢复备份/旧版本；不盲目反向迁移 | 低峰重演练并更新 PR12/迁移 ADR |
| WS 高频崩溃/消息重复 | 降级到轮询/只读或关闭新事件消费 | 修复事件版本、去重和连接上限 |
| 前端构建/类型检查失败 | 不合并、不发布；定位首个失败命令 | 不用容错 shell 或删除检查“修绿” |

## 6. 合并完成定义

首批 PR 完成不等于产品发布。只有 PR12 通过 P0 验收门、设备证据、作用域安全门、回滚演练和残余风险签字，才可标记“P0 可发布”；否则应报告为“代码已合并、发布门未通过”，并保留未完成项。P1 的 PR13/PR14 只能在各自证据通过后声明离线可写或原生能力可用。
