# 优化 v4：移动端个人 AI 助手整体方案

**审计与方案日期**：2026-08-14
**范围**：`services/opencode-pocket` 当前仓库
**交付性质**：架构审计、产品优化方案、数据/安全设计、实施拆解与并行执行提示词
**本轮变更**：完成本目录方案与任务规划审计，修正交付边界、依赖、状态和回滚表述；不修改业务源码

## 1. 一页结论

当前项目已经具备一个有价值的移动控制面基础：Vue 3 + Capacitor 移动壳、Go `pocketd` 后端、workspace/任务/会话、OpenCode/ACP/Agent Bridge、SQLCipher 本地库、笔记本地检索、会议录音、邮件、Vault、LLM BFF 和 WebSocket/SSE。它还不是完整的个人 AI 助手，主要原因不是缺少更多页面，而是以下闭环尚未统一：

1. **产品闭环**：`/ai` 仍以任务/OpenCode 聚合为主，缺少通用助手、统一上下文和跨模块 action。
2. **数据闭环**：笔记、会议、账本存在本地/云端双轨；会议和账本后端仍有内存存储；细粒度同步、冲突和恢复不足。
3. **执行闭环**：自然语言意图、typed action、审批、运行状态、重试、补偿和审计没有统一为 durable run。
4. **安全闭环**：跨 workspace/session/agent/plugin 资源授权、tracked secret、JWT 撤销、WS token、出站 URL、持久审计仍需优先整改。
5. **移动闭环**：网络离线、断线回放、通知回唤、后台能力、原生 Keystore、统一错误/空/加载状态和弹层可访问性还需收敛。

推荐路线是：**先安全止血与资源授权，再建立 durable run + Approval Center + Audit，随后把 `/ai` 演进为助手工作台，最后统一会议/账本/同步/通知和连接器**。

## 2. 重要事实边界

- 本文不把项目描述成官方 OpenCode、Codex 或 Claude 的移动应用；项目是连接已配置实例/agent 的 Pocket 移动控制面。
- 截至本次研究资料范围，没有足够官方证据证明存在独立 Codex iOS/Android 产品或官方手机审批能力；不能用搜索摘要或第三方文章补齐事实。
- “手机审批”在本方案中是 Pocket 自己的控制面能力：手机发起请求，后端再次校验 user/workspace/resource/capability/TTL，目标 connector 返回成功后才显示成功。
- 本轮没有执行凭据轮换、Git 历史清理、源码修复、构建、测试、真实 ACC/OAuth/kxmemory/设备验证；正文中的“通过”若来自历史报告，会明确标为历史证据。
- `docs/优化v4/` 中的方案是目标设计和任务分配，不代表对应功能已经存在。

## 4. 目标产品定义

> **一个本地优先、云端协同、以安全执行为边界的移动个人 AI 助手；它既能记录和理解个人信息，也能在用户授权后安排、控制和审计远程智能体任务。**

### 核心能力柱

- **Capture**：文字、语音、会议、截图、附件和快速记账。
- **Understand**：本地 FTS/vector + 云端模型的可解释检索、摘要、分类和关联。
- **Plan**：将自然语言请求转成可审阅的 typed action plan。
- **Execute**：通过 OpenCode/ACP/ACC/邮件等 connector 执行，服务端作为信任边界。
- **Review**：在 Approval Center/Inbox 中处理权限、问题、失败重试和完成摘要。
- **Remember**：本地加密存储、选择性同步、版本、冲突和恢复。

### 体验原则

1. **核心优先**：助手、收件箱、知识、会议、任务/智能体、账本和安全设置必须能形成闭环；不以堆叠连接器替代核心质量。
2. **极客但不喧闹**：用状态、时间线、事件、模型/实例信息提供掌控感；默认摘要，细节可展开。
3. **建议与执行分离**：AI 可以建议，副作用必须有 schema、权限、预览、确认、执行结果和审计。
4. **本地优先但不假装实时**：明确显示本地、云端、离线、stale、同步中和冲突状态。
5. **安全是后端能力**：UI 不是授权边界；所有资源、动作和审批都在后端重新校验。

## 5. 当前最优先的 10 件事

1. 撤销并轮换仓库中已跟踪的 master key、JWT 和 MCP-like 凭据；再清理 Git 历史并建立 secret scanning。
2. 为 instance/session/task/agent/plugin/asset 建立统一 resource authorization，修复跨 workspace 和资源存在性泄露。
3. 去除 WS/SSE query token，统一短时连接凭据、设备撤销和连接生命周期。
4. 引入版本化 migration runner、全局锁、FK/CHECK/组合唯一约束和可恢复迁移流程。
5. 将 agent、邮件动作、AI 分类、ACC 同步统一为持久化 lease/retry/dead-letter 状态机。
6. 持久化 `Run/Event/Approval/Audit`，实现快照 + cursor replay，断线后不依赖内存事件。
7. 把 `/ai` 改造为助手工作台，建立上下文选择器和 typed action preview/confirm。
8. 将账本从内存 store 补为 PG + 本地离线 UI；统一会议本地/云端流水线并沉淀 action item/task。
9. 合并两套 HTTP/WS transport、双轨笔记/会议模型，并将 `frontend/android/` 作为唯一 Android 构建事实源；根 `android/` 仅保留占位/同步脚本边界。
10. 补前端/Android CI、移动 viewport/可访问性/故障注入测试，并用真实设备验证发布链路；feature flag 与 migration runner 先于可操作回滚。
