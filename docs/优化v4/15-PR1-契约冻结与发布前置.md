## 3. 状态转移图（冻结）

### 3.1 通用异步状态

```
idle ──> loading ──> ready
                  ├─> empty
                  └─> error(retryable | terminal)
ready/empty ──> refreshing ──> ready | error(保留旧数据)
任何状态 ──> offline（保留本地数据与待发送队列）
```

### 3.2 应用与数据层

```
auth:       unknown → unauthenticated → authenticating → authenticated → expired
lobster:    uninitialized → initializing → ready | failed → locked
network:    unknown → online → degraded → offline → online
sync:       clean ↔ pending → syncing → synced | conflict | failed
```

### 3.3 会话与 Run

```
session:    unknown → idle → running → waiting_user → completed
                                  ├→ failed
                                  └→ cancelled
tool:       queued / running / completed / error / cancelled
run:        queued / running / waiting_approval / waiting_question
            / succeeded / failed / cancelled / expired
approval:   pending → submitting → approved | rejected | expired | failed
question:   pending → submitting → answered | expired | failed
```

`session.waiting_user` 只读地映射自 `run.waiting_approval` 或 `run.waiting_question`；不可作为聚合状态独立来源。

## 4. WS envelope（冻结 v1）

```json
{
  "v": 1,
  "id": "01HXXXXXXXXXXXXXXXXXXXXXXXX",
  "ts": 1730000000000,
  "channel": "session|approval|run|event|tool|question",
  "topic": "instance:{instance_id}.session:{session_id}",
  "type": "approved|rejected|expired|progress|completed|failed|cancelled|gap|unknown",
  "data": { /* 类型特定字段 */ },
  "cause": { "action_id": "...", "approval_id": "...", "correlation_id": "..." }
}
```

- 字段：`v` 协议版本；`id` 事件 id（ULID/UUID，不可重复）；`ts` 客户端时间；`channel` 与 `topic` 用于路由；`type` 业务事件类型；`data` 与 `type` 对应；`cause` 用于跨事件回放。
- 重复：`id` 已处理直接忽略；同一 `cause.action_id` 的多事件必须幂等。
- 未知事件：客户端记录日志并保留订阅，不得断开。
- 断线重连：客户端带 `after=<last_id>` 重放；服务端返回 `gap` 事件，UI 须展示“可能丢失”提示，不得伪造“已成功”。
- 错误语义：服务端确认前 run/approval 不得切到 `succeeded`/`approved`。

详细路由与 channel 划分见 `docs/优化v4/07-AI编排与智能体控制面.md §3`。

## 5. 权限动作矩阵（冻结 v1）

> 命名空间 `resource.action`，capability 由策略层动态分配；未知能力默认拒绝。

| resource | action | 最低角色 | 必备字段 | 备注 |
|---|---|---|---|---|
| workspace | read | member | workspace_id | 成员有效期内 |
| workspace | manage_members | owner/admin | workspace_id, actor_role | 撤销即时生效 |
| workspace | view_audit | owner/admin | workspace_id | 不可降级 |
| instance | read | member | instance_id | shared instance 需显式 capability |
| instance | dispatch | member + capability:session.dispatch | instance_id, session_id | scoped 查询 |
| session | read | member | workspace_id, instance_id, session_id | 三元组必带 |
| session | cancel | member | 同上 + capability | 仅 owner/admin 可强终 |
| agent | send | member | agent_id, workspace_id, capability | attach 失败需 partial_failure |
| plugin | command | member + capability:plugin.command | workspace + instance + plugin | 三元组校验 |
| migration | run | member + capability:migration.run | source/target workspace | 源/目标必须 scoped |
| asset | read | member | workspace_id, asset_id | CAS |
| asset | write | member | workspace_id + base_server_rev | 409 on mismatch |
| vault | reveal | member + capability:vault.reveal | workspace_id, entry_id | 仅一次消费 |
| oauth | connect | owner/admin | provider, workspace_id | state 一次性 |
| audit | read | owner/admin | workspace_id | 不可由普通成员改写 |

拒绝语义：

- 缺 workspace → 401/404，不区分“未登录”与“越权”。
- 缺 capability → 403 + 稳定 `code=capability_denied`。
- 跨 workspace 资源 → 404，不暴露存在性。
- membership expired → 401 + `code=token_expired`，触发重新登录。

完整 capability 命名与数据分级参考 `docs/优化v4/02-安全审计与整改清单.md §3 SEC-03/04`。

## 7. Feature flag 最小实现（冻结）

| 维度 | 规则 |
|---|---|
| 服务端配置位置 | `internal/config` 已有配置下，新增 `feature_flags` map（key→value）；默认值在 config 装载时设定 |
| 前端读取路径 | `frontend/src/config/featureFlags.ts` 单一来源；通过 `useFeatureFlag(key)` 暴露 |
| 命名规范 | `<scope>.<feature>.v<n>`，例如 `realtime.ws_envelope_v1`、`approval.bottom_sheet_v1` |
| 默认值 | 与 PR1 之前的旧行为等价；引入新行为必须以 `false` 默认起步 |
| 关闭路径 | 服务端读取后立即回退旧行为；前端读取失败回退 `false` |
| 审计 | flag 变更必须写入审计（仅 key + actor + before/after） |
| TTL | 任何 flag 必须在 PR 合并后 ≤ 90 天内被移除或转为常量 |
| 不可替代 | flag 不能替代迁移 runner、备份或回滚演练 |

`realtime.ws_envelope_v1`、`approval.bottom_sheet_v1`、`approval.server_confirm_required`、`realtime.idempotent_ws_bus` 是首批必须存在的 flag。

## 8. Migration runner 与不可逆迁移（冻结）

| 类别 | 规则 |
|---|---|
| 命名 | `YYYYMMDD_HHMM_<module>_<purpose>`；模块名避免重叠 |
| 顺序 | 全局字典序；新迁移只追加，不修改历史 |
| 锁 | 启动期使用 advisory lock；运行期对目标表使用行锁或事务 |
| 回滚 | 默认提供 `down.sql`；不可逆迁移必须显式声明 `irreversible=true` 并提供前向兼容读路径 |
| 备份点 | 不可逆迁移前必须定义 backup hook（pg_dump/快照/复制槽） |
| 应用回滚 | 当迁移不可逆且代码回滚后，应用必须能在新结构下仍提供旧字段/默认读 |
| 失败处理 | 任意迁移失败 → fail closed；启动拒绝 |
| 跳过 | 不允许跳过；DB-gated 测试必须真执行（参考 02 §P2 与 audit `2026-08-09-email-pipeline-audit.md`） |

详细 ADR 见 `docs/优化v4/12-ADR与风险台账.md ADR-005`。

## 9. UI 状态映射（冻结 v1）

| 状态 | 触发 | 文案 | 必备元素 | 禁止 |
|---|---|---|---|---|
| idle | 初始化未启动 | 留空 | — | spinner/文字 |
| loading | 首次/硬刷 | “正在加载…” | 骨架或 spinner + status | 假数据 |
| empty | 0 条且非错误 | “当前没有… 试试…下一步” | 三段式说明 + CTA | alert |
| error.retryable | 网络/超时 | “连接中断，重试” | 重试按钮 + 保留旧数据 | 静默失败 |
| error.terminal | 4xx 无权限/资源 | “不可用” | 跳转或返回 | 报错堆栈 |
| offline | 网络掉线 | “离线，仅本地可读” | 离线队列提示 | 误导用户 |
| refreshing | 下拉刷新/分页 | 顶部进度条 | 保留旧数据 | 覆盖错误 |
| waiting_approval | run 进入 waiting | “需要你的授权” | 跳审批 Bottom Sheet | 假装通过 |

## 10. 错误码与稳定 error code（冻结）

所有 handler 必须返回结构化错误，字段：

```
{
  "code": "stable_error_code",
  "message": "人类可读",
  "request_id": "...",
  "retryable": true|false
}
```

稳定 error code 列表（首批）：

| code | 含义 | 客户端处理 |
|---|---|---|
| `unauthenticated` | 未登录或 token 失效 | 跳登录 |
| `token_expired` | token 过期 | 静默刷新一次 |
| `workspace_required` | 缺 workspace 上下文 | 引导选择 workspace |
| `capability_denied` | capability 不足 | 不允许 UI 宣称已批准 |
| `not_found` | 资源不存在（与 401/403 不可区分） | 显示“不可用” |
| `conflict` | CAS/版本冲突 | 进入冲突 UI |
| `rate_limited` | 频率过高 | 退避 |
| `approval_required` | 高风险动作 | 弹审批 |
| `approval_expired` | 审批已过期 | 重新生成 action |
| `idempotency_key_required` | 高风险需 key | 客户端自动补 |
| `upstream_unavailable` | 上游失败 | 保留请求 + 重试 |
| `payload_too_large` | 超出限制 | 截断/分片 |
| `unsupported_event` | 未知事件类型 | 记录 + 忽略 |

任何新增 code 必须在 PR 描述中给出兼容策略和示例。

## 11. 审计最小字段（冻结）

审计条目必须包含（不可空，缺一即视为缺陷）：

- `audit_id`：ULID/UUID
- `actor_id`、`actor_role`
- `workspace_id`
- `action_type`：枚举（login/workspace_switch/credential_*/oauth_*/smtp_*/llm_*/stt_*/session_dispatch/plugin_command/migration_*/sync_conflict/admin_*）
- `resource_type`、`resource_id`
- `correlation_id`：与 cause.action_id 关联
- `policy_decision`：`allow`/`deny`/`approval`
- `result`：`success`/`failure`/`partial`
- `input_digest`、`output_digest`：hash；不允许存 payload
- `ip`、`user_agent`：可脱敏
- `created_at`：服务端时间

只写摘要/hash，禁止 payload、token、邮件正文、Vault body 进入审计。

## 12. 设备与可访问性基线（冻结）

- 设备矩阵：Android 模拟器（Pixel 6 API 33）+ 至少 1 台真机（型号记录在 PR）。
- 系统：Android 10+；最低 SDK 与 target SDK 与 `frontend/android/build.gradle` 当前保持一致；变更需在 PR 描述说明。
- 字号：默认 16px；放大两档不裁切。
- 触摸目标：≥48x48dp，主操作 ≥56x56dp；间距 ≥8dp。
- 对比度：正文 ≥4.5:1，大字 ≥3:1，状态图标 ≥3:1。
- 读屏：TalkBack 通过核心任务。
- 暗色、reduced motion、横竖屏、平板单/双栏均纳入检查。
- 自动化：playwright/Detox 等运行器仅在没有原生插件时可作为唯一证据。
