# 03 产品蓝图与信息架构

**版本**：优化 v4（方案）
**定位**：把 OpenCode Pocket 从“OpenCode 实例移动控制台”演进为“移动端个人 AI 助手”，保留远程编程控制能力，并把笔记、会议、任务、账本、安全、邮件、云同步和 ACC 远程智能体纳入同一个个人工作台。

> 本文只定义产品蓝图、信息架构和核心用户体验。领域模型、数据所有权、接口与事件见 `docs/优化v4/04-目标架构与领域拆分.md`；AI 编排、typed action、审批中心和 ACC connector 见 `docs/优化v4/07-AI编排与智能体控制面.md`。

---

## 1. 方案摘要

### 1.1 产品命题

用户不应先判断“这个需求属于哪个后端模块”，再分别打开笔记、邮件或 OpenCode。用户只需要表达目标：

- “把刚才会议的三个决定变成任务，并让远程 agent 在项目里开一个实现会话。”
- “找出本周所有待报销票据，合计金额，并在我确认后写入账本。”
- “总结今天未读邮件，只把高优先级的回复草稿放进审批中心。”
- “把这段语音存成工作区笔记，关联上上周的会议，并给我一个下一步。”

产品因此采用“两条入口、一个状态、一个审批中心”的模型：

1. **对话/捕获入口**：自然语言、语音、分享、快捷动作，负责理解意图并生成可检查的建议。
2. **领域工作台入口**：Notes、Meetings、Tasks、Finance、Mail、Vault、Agents 等页面，负责浏览、编辑和核实事实；其中 Finance 当前仅有后端能力，前端工作台仍是目标模块。
3. **统一状态**：所有长任务都可见，统一显示 `queued / running / waiting_approval / succeeded / failed / cancelled`，不把 AI 黑盒藏在页面背后。
4. **审批中心**：凡是外发、写入、执行、授权、敏感数据访问等副作用动作，集中显示证据、范围、目标和过期时间，由后端在信任边界内再次鉴权。

### 1.2 事实边界

| 事实 | 本方案的处理 |
|---|---|
| 当前仓库已有 Capacitor + Vue 前端 | 以 `frontend/src/` 继续演进，不做 Kotlin/Swift 大爆炸重写。 |
| 当前后端已有 Go API、JWT、workspace 隔离、REST/WebSocket | 继续把后端作为唯一信任边界；手机是呈现和意图提交端，不是授权源。 |
| 官方 OpenCode 资料确认终端、桌面、IDE 形态 | 将本产品称为 OpenCode Pocket 的移动控制面，不称为官方 OpenCode 移动端。 |
| OpenAI Codex 官方资料确认 CLI、IDE、桌面和云端形态 | 不声称存在已确认的独立 Codex 手机端，也不声称存在手机审批能力；手机审批只针对本仓库后端已接入并可验证的请求。 |
| ACP 官方资料确认编辑器/代理角色和本地 stdio；HTTP/WebSocket 仍在推进 | `ACP connector` 必须做能力探测和降级，不能把未来协议能力写成现状。 |
| `localDB` 与 `Asset` 已存在 | 新的个人内容优先走 Asset；旧表继续运行，通过适配器渐进迁移。 |
| 后端部分业务已有 PostgreSQL，会议 store 仍是内存实现 | 产品状态不能假设所有模块已经云端持久化；离线/同步状态必须显式显示。 |

### 1.3 非目标

- 不重写现有 Go 服务、前端路由或本地数据库。
- 不把手机变成远程 shell、Codex 客户端或万能 root 控制台。
- 不让 LLM 直接拥有数据库、邮件 SMTP、OpenCode API 或 ACC 凭证。
- 不以“自动执行”替代用户对外发邮件、转账/记账、密码箱读取、远程 agent 写文件等高影响动作的确认。
- 不把“搜索到一个实例”误认为“已经建立可信连接”；每个 connector 都必须有身份、能力和健康状态。

## 2. 用户与场景

### 2.1 核心用户

**个人操作者**：需要把生活信息、工作协作和远程开发环境集中到手机，但愿意保留对敏感副作用的最终控制。

**移动监督者**：不在电脑旁时查看远程 agent 进度、回答 question、批准权限或停止任务。这里的“批准”是 Pocket 后端代理到已连接的 OpenCode/ACP/ACC 目标，不代表 Codex 官方提供手机审批。

### 2.2 场景优先级

| 优先级 | 场景 | 成功定义 |
|---|---|---|
| P0 | 捕获文本并保存笔记；录音能力按平台降级 | 3 秒内看到本地草稿；网络恢复后可分类、关联和同步。Web fallback 可先保存录音文件，但不承诺原生录音/转写。 |
| P0 | 查看今日任务与待审批 | 一屏知道哪些是个人任务、远程任务、阻塞原因和下一动作。 |
| P0 | 远程 agent 会话监督 | 能看流式摘要、工具进度、问题和权限请求；断线后可恢复。 |
| P1 | 会议转写、纪要、行动项 | 录音、转写、纪要、任务之间都有来源链。 |
| P1 | 邮件聚合与回复草稿 | LLM 只处理被授权的字段；发送前必须进入审批中心。 |
| P1 | 票据/账本整理 | 图片/附件先落本地 Asset；金额、账户和分类可人工修订。 |
| P1 | Vault 与云同步 | 密文资产可跨设备同步；服务端不取得 e2ee 内容明文。 |
| P2 | ACC 多 agent 协作 | 能查看远端任务并提交结构化意图；不把 ACC 当作无边界执行器。 |

## 3. 产品蓝图

### 3.1 三层产品心智模型

```text
┌─────────────────────────────────────────────────────────────┐
│  捕获层 Capture                                             │
│  语音 / 文本 / 分享 / 扫描 / 外部事件                         │
│  目标：先不丢信息，形成 draft 或 intent                      │
├─────────────────────────────────────────────────────────────┤
│  工作台 Workspace                                            │
│  Notes  Meetings  Tasks  Finance  Mail  Vault  Agents        │
│  目标：把事实、来源、状态、关系和人工修改呈现清楚             │
├─────────────────────────────────────────────────────────────┤
│  控制面 Control                                              │
│  AI 编排 / Action Registry / Approvals / Connectors / Sync    │
│  目标：在后端信任边界内安全地产生和执行副作用                 │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 首页不是 Dashboard，而是“今日队列”

首页 `Today` 只回答四个问题：

1. **我现在需要处理什么？**：待审批、待回答问题、逾期任务、未读高重要度邮件。
2. **AI 刚刚做了什么？**：已完成的总结、分类、转写、同步和远程 agent 进度。
3. **我刚才捕获了什么？**：语音草稿、分享进来的网页/图片、未归档会议片段。
4. **我可以说什么？**：持续对话入口和可发现的快捷动作。

首页卡片必须是可追溯的：每张 AI 卡片带 `sourceType + sourceId + generatedAt + model + confidence`；没有来源的推断不能伪装成事实。

### 3.3 推荐导航

#### 手机窄屏：四项高频入口 + 更多

```text
[今日]  [收集]  [智能体]  [更多]
```

- **今日**：Today、Inbox、Approvals、Questions、最近运行。
- **收集**：语音、文本、拍照/扫描、分享接收、快速新建。
- **智能体**：Agent 列表、Instances、Sessions、ACC 远程任务、连接健康。
- **更多**：工作台（Notes、Meetings、Tasks、Finance、Mail、Vault）与设置；详情/编辑态可隐藏底栏。

#### 折叠屏/平板：双栏

```text
左栏：今日 / 工作台树 / 智能体树
右栏：选中实体详情 / 会话流 / 审批详情
```

不新增一套“平板业务模型”，只把同一 canonical IA 变成 master-detail。

### 3.4 Canonical IA

```text
Pocket
├── 今日 Today
│   ├── Inbox（待归档捕获）
│   ├── Approvals（待审批动作）
│   ├── Questions（远程 agent 待回答）
│   ├── Runs（AI/同步/远程运行）
│   └── Digest（每日摘要）
├── 收集 Capture
│   ├── Voice note

│   ├── Scan voucher / PDF
│   ├── Start meeting
│   └── Share to Pocket
├── 工作台 Workspace
│   ├── Notes
│   │   ├── All / Pinned / By workspace / Semantic search
│   │   └── Note detail → links / tasks / source assets
│   ├── Meetings
│   │   ├── Upcoming / Recording / Processing / Completed
│   │   └── Meeting detail → transcript / decisions / action items
│   ├── Tasks

│   │   └── Task detail → sources / sessions / agent run
│   ├── Finance
│   │   ├── Inbox / Ledger / Accounts / Reports
│   │   └── Voucher detail → source image / extracted fields / audit
│   ├── Mail
│   │   ├── Priority / Unread / Accounts / Drafts / Sent
│   │   └── Thread detail → summary / suggested reply / approval
│   └── Vault

├── 智能体 Agents

```

### 3.5 命名规则

- **工作区 Workspace**：权限和数据隔离边界；来自 JWT `workspace_id`，不由客户端请求体决定。
- **资产 Asset**：可同步的个人内容单元；笔记、会议音频、票据图片、附件等使用 `Asset.kind` 区分。
- **任务 Task**：需要完成的目标；可以关联本地任务、OpenCode session 和 ACC 远端任务。
- **运行 Run**：一次 AI 编排或 connector 调用；可暂停、重试、等待审批，不能等同于 Task。
- **智能体 Agent**：可被控制的逻辑工作者；其底层可能绑定 OpenCode 实例、ACP 进程或 ACC connector。
- **审批 Approval**：对某个具体 action 的一次授权；不是永久权限，也不是前端按钮状态。

## 4. 核心用户流程

### 4.1 语音捕获 → 笔记 → 任务

```text
长按“收集”
  ↓
本地录音 + 本地草稿（无网络也可完成）
  ↓
本地 STT 或后端 STT，结果带 transcript confidence
  ↓
用户确认标题/可见范围（工作区、私密、共享）
  ↓
写入 localDB / Asset(kind=voice_memo 或 note, dirty=1)
  ↓
后台 AI classify / summarize / extract_tasks
  ↓
展示建议：分类、标签、关联笔记、任务候选
  ↓
用户接受/修改/忽略；每个副作用生成可追踪 action
  ↓
同步状态：本地已保存 → 上传中 → 已同步 / 冲突
```

**关键体验**：网络失败不阻塞保存；AI 失败不影响原文；建议与事实分层显示。

### 4.2 会议 → 纪要 → 远程 agent

```text
Start meeting
  ↓
local_meetings + meeting_audio Asset 建立
  ↓
分段录音、转写、说话人标签（可逐步完成）
  ↓
生成“决定 / 行动项 / 未决问题”草稿
  ↓
用户确认行动项及负责人、截止日期
  ↓
创建本地 Tasks；必要时选择 Agent + workspace + directory
  ↓
生成 agent.run action（先 dry-run 预览）
  ↓
若涉及写文件/执行命令 → Approval Center
  ↓
后端 dispatch 至 OpenCode/ACP/ACC connector
  ↓
Session/Task 实时回流，失败可重试或转人工
```

### 4.3 邮件 → 摘要 → 回复

```text
同步账户（OAuth/IMAP/SMTP 等现有 connector）
  ↓
邮件归属 user + workspace 校验，凭证只在后端/加密本地存储
  ↓
摘要/重要度/建议动作（只把允许的邮件字段交给 LLM）
  ↓
回复草稿写入 draft，不直接发送
  ↓
用户检查收件人、主题、正文、附件和账户
  ↓
POST /actions 生成 email.send，状态 waiting_approval
  ↓
审批中心显示完整 diff 和目标；后端再次检查账户归属和策略
  ↓
批准后由后端 SMTP/邮件 connector 发送并记录审计
```

### 4.4 票据 → 账本

```text
拍照/分享 PDF
  ↓
本地加密 Asset(kind=voucher_image/pdf)
  ↓
OCR/LLM 提取金额、币种、商户、日期、类别（候选字段）
  ↓
用户修改并确认事实
  ↓
生成 finance.entry.create action
  ↓
本地账本可直接落库；跨设备/云端按 sync_mode 处理
  ↓
若涉及外部账户、报销提交或转账，必须进入审批中心
```

### 4.5 远程 agent 监督

```text
智能体 → 选择 Agent / Instance / Session
  ↓
查看能力、健康、workspace、目录和最近运行
  ↓
输入自然语言，后端转换为 typed action 或 prompt
  ↓
dry-run：展示目标、预计副作用、所需权限
  ↓
无副作用 → 后端执行并流式返回
有副作用 → waiting_approval
  ↓
手机 approve/reject/question answer（仅作为用户操作入口）
  ↓
后端鉴权、绑定 nonce、检查过期，再调用目标 connector
  ↓
通过 Mobile WebSocket/SSE 回传进度、工具摘要、结果和审计引用
```

### 4.6 Vault 解锁与同步

1. 进入 Vault 只展示条目元数据的最小必要部分。
2. 读取密文内容前由本地 Keystore/生物识别解锁；前端 `native/keystore.ts` 和 `native/crypto.ts` 负责本地能力。
3. `e2ee_local_first` Asset 的云端只保存密文镜像；服务端不解密、不做全文索引。
4. 同步冲突不静默覆盖：显示两个 revision、更新时间和“保留本地/保留远端/导出合并”。
5. 任何把 Vault 内容提供给 agent 或 LLM 的动作必须显式显示字段、目的、目标 connector 和一次性授权范围。

## 5. 统一页面状态与可用性

### 5.1 运行状态条

所有 Runs、远程 Session、同步作业和 AI 处理采用统一状态组件：

```text
queued → running → waiting_approval → running → succeeded
   │         │              │              ├→ failed
   │         └──────────────┴──────────────└→ cancelled
   └→ expired（未开始且超过 TTL）
```

`waiting_approval` 必须是可点击的队列项，展示“为什么停住”和“需要谁做什么”，不能只显示 spinner。

### 5.2 离线与重连

| 状态 | UI 表达 | 用户动作 |
|---|---|---|
| 本地已保存 | `仅本机` | 继续编辑、手动重试同步 |
| 上传中 | `同步中` | 查看队列、暂停非紧急同步 |
| 远端已确认 | `已同步` | 查看 server revision |
| 冲突 | `需处理` | 打开冲突比较页 |
| connector 离线 | `连接断开` | 查看诊断、重试、切换可用 connector |
| 运行等待审批 | `等你确认` | 进入审批中心，不重复提交 |

### 5.3 无障碍与触控

- 关键按钮最小触控区域至少 48×48dp，推荐 56×56dp；危险操作使用二次确认和明确动词。
- 语音输入必须有文本回退；用户可看到原始转写和修订后的最终文本。
- 颜色不是唯一状态表达；每个状态有文字、图标和可访问名称。
- 会话流默认显示摘要，工具原始输出按需展开；移动端不强行展示长日志。
- 所有 action/approval 详情均提供“复制 JSON 摘要”和审计 ID，便于故障报告。

## 6. 渐进式交付

### Phase A：稳定控制面与入口统一

- 保留现有 `router-mobile.ts`、`features/tasks`、`features/notes`、`features/email`、`features/meetings`、`features/vault`。
- 新增 Today、Approvals、Questions、Runs 的统一聚合视图；底层先复用现有 API 和 WebSocket。
- 统一 `workspace_id` 显示和前端 store 的请求上下文；不改变老接口语义。

### Phase B：Asset-first 新业务

- 新捕获内容统一写 `frontend/src/native/asset-store.ts` 的 Asset。
- 旧的 `local_notes/local_emails/local_vault_entries/local_meetings` 保持不动；只新增双写/读取适配器和迁移标记。
- 使用已有 `/api/assets/sync` 与 `backend/internal/lobster/store.go` 逐步接入跨设备增量同步。

### Phase C：AI 运行与审批中心

- 把现有笔记分类、会议总结、邮件建议和 agent dispatch 包装为 Run/action。
- 将 OpenCode permission/question 事件映射到统一 Approval/Question read model。
- 先做单步 action，再支持依赖链和可恢复编排；不直接引入 DAG 引擎。

### Phase D：ACC 与多 connector

- 先把现有任务聚合中的 `source=acc` 做成只读 ACC connector。
- 增加 typed command 的最小子集和幂等键；默认 dry-run。
- 只有 connector 能力、租户和策略全部满足时才允许写操作。

## 7. 体验验收标准

### P0 验收

- 新用户登录后能看到带 workspace 的 Today；切换 workspace 后不会泄露另一工作区的任务、笔记、agent 或审批。
- 无网络文本捕获可保存到加密 `localDB`；录音在具备平台能力时保存为本地草稿，原生录音/转写确认属于 P1。刷新/重启后可恢复草稿。
- 一个 OpenCode 权限请求或 question 到达后，Today、Approvals、Session 详情三处状态一致；处理一次后不可重复执行。
- 远程 agent 断线时，手机明确显示 connector/实例状态，不显示“已完成”假象；恢复连接后能按事件游标补齐。
- 邮件发送、远程写文件、命令执行、Vault 读取均无法绕过后端审批和 workspace 校验。

### P1 验收

- 会议纪要中的行动项可追溯到 transcript segment；任务可追溯到 meeting/Asset。
- 票据提取结果区分“模型建议”和“用户确认值”；账本汇总只使用确认值。
- e2ee Asset 同步后服务端数据库中没有可直接读出的正文/附件明文；冲突可人工解决。
- ACC 任务可标记来源、connector、远端 ID 和同步时间；ACC 不可用时本地任务仍可使用。

### 产品指标

- 捕获成功率（含离线）≥ 99%；重复提交率 < 0.5%。
- P0 详情页首屏 p95 < 1.5 秒（本地数据）；远端状态首事件 p95 < 3 秒。
- 审批动作的幂等成功率 100%；过期/重复/跨 workspace 请求均被拒绝并记录。
- AI 建议可被用户逐项接受、修改或忽略，不能只有“一键全自动”。

## 9. 外部一手资料边界

- OpenCode 官方介绍：<https://opencode.ai/docs/>。资料明确介绍开源 AI 编程代理的终端、桌面和 IDE 形态，以及 build/plan 等交互；本方案不把它扩写为官方移动端。
- OpenCode 官方仓库：<https://github.com/sst/opencode>。README 可核实 CLI、桌面测试版、IDE 相关形态；不能据此推出官方手机审批。
- Agent Client Protocol：<https://agentclientprotocol.com/>。资料确认编辑器/IDE 与编码 agent 的角色及本地 stdio transport；远程 transport 的支持边界仍需能力探测。
- OpenAI Codex 官方仓库：<https://github.com/openai/codex>。可核实 CLI、IDE、桌面和云端入口；截至本方案研究，未确认独立 Codex 手机端或手机审批能力。

本文中的“移动审批”是 Pocket 后端对已接入目标的安全控制面能力，不是上述官方产品能力的宣称。
