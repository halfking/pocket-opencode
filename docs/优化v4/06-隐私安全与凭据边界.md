# 优化 v4：隐私安全与凭据边界

> **原则**：数据最小化、默认不出端、按 workspace 和 capability 授权、密钥只在需要时短暂可用、日志只记录不可逆摘要。本文是方案，不代表已经完成整改；不执行凭据轮换、历史清理或源码改动。
>
> **标记**：**现状事实** = 当前代码/审计可确认；**推断建议** = 目标控制；**待验证** = 需真实设备、网络、provider 或运维环境确认。

## 1. 数据分级

| 级别 | 示例 | 默认存储 | 默认出端 | 日志策略 |
|---|---|---|---|---|
| L0 公开 | UI 文案、版本、能力枚举、无用户关联健康状态 | 本地/云端均可 | 可出端 | 可记录 |
| L1 workspace | Task 标题、非敏感 Asset metadata、运行状态、非正文事件 | workspace scoped 云/本地 | 仅同 workspace 的 OpenCode/Plugin/LLM | 记录 id/hash，不记录正文 |
| L2 confidential | 笔记正文、邮件 header/snippet、会议转写、聊天消息、prompt/response | 本地优先；云端按明确授权密文或最小片段 | 仅 capability + policy + 用户动作允许的 provider | 禁止全文；长度、分类、digest |
| L3 secret | Vault 条目、IMAP/SMTP password、OAuth access/refresh token、LLM API key、设备 push token | Keystore/Keychain + 加密 DB；云端仅 E2EE 密文 | 默认禁止；仅专用 connector 使用短暂明文 | 只记 secret id、key version、结果 |
| L4 regulated/high impact | 身份证件、财务凭证、医疗/生物特征、跨组织合规数据 | 本地加密、最短保留；云端需显式授权和租户策略 | 默认禁止第三方 LLM/插件 | 只记策略决策和不可逆 digest |

**现状事实**：本地 schema 同时存在明文 title/metadata、可选加密 body、AES-GCM blob、邮件 snippet、会议 transcript（`frontend/src/native/schema.ts:17-34,124-163,171-197,268-331`）；新 Asset 由 `body_encrypted` 控制 FTS 是否索引（`schema.ts:290-310`）。这说明“字段是否敏感”不能由表名推断，必须进入数据字典。

## 2. 出端策略

### 2.1 总规则

任何出端请求先生成 `EgressDecision`：

```text
actor + workspace + resource + data_classification
→ destination/provider + purpose + capability + approval
→ allow(minimized payload) / redact / deny
```

请求必须带 `egress_id` 和 `correlation_id`；决策记录到 Audit，但只存分类、字段名、digest、目的地摘要，不存明文。

### 2.2 目的地策略

| 目的地 | 允许 | 禁止/限制 |
|---|---|---|
| OpenCode 实例 | L1；L2 仅在 `session.dispatch` capability 与用户选择目录/实例策略允许时 | L3 明文、未批准的工作区、任意 directory、任意 URL |
| Agent/Plugin | 仅其 capability 声明所需的最小字段 | 任意读取本地文件、跨 workspace 引用、绕过 Approval 的 shell/network |
| LLM/BFF/Gateway | 默认只发摘要/脱敏片段；按 provider policy 选择模型和区域 | Vault/refresh token、完整邮件/会议正文、未经批准的 L3/L4 |
| IMAP/SMTP | 仅 connector 需要的账号凭据和邮件协议字段 | 将密码回传 UI/日志；把收件箱全文交给无关 provider |
| OAuth provider | 固定 redirect、最小 scope、PKCE/state、短暂 code exchange | 客户端自定义 redirect、日志记录 code/token、跨 workspace state |
| 云同步 | E2EE ciphertext、版本、hash、墓碑、最少 metadata | L2/L3 明文；把密文 key 与 blob 一起上传 |
| 审计/监控 | decision、result、digest、resource id、timing | prompt、邮件正文、响应全文、Authorization、cookie、API key |

### 2.3 出端前最小化

- 邮件：默认只发送分类所需的 sender/domain/subject/snippet 截断；附件必须单独批准。
- 会议：默认只发送选定片段或本地摘要，不自动上传整段音频/完整 transcript。
- 笔记：默认本地 embedding；云端 embedding 需按 Asset classification 和 provider policy 决策。
- Prompt：记录 input digest，不把原 prompt 当 Audit payload；调试样本必须显式采样、脱敏、短期保留。
- 错误：向客户端返回稳定 code，不把上游 URL、认证头、内部路径、SQL 或 provider response 原样透传。

**待验证**：真实 `kxmemory`、LLM gateway、RedClaw、STT、IMAP/SMTP 链路的请求 body、重试 body、代理日志和第三方保留周期，需要抓包/供应商配置逐项确认。

## 3. 密钥与 Keystore 边界

### 3.1 当前实现事实

1. `frontend/src/native/local-db.ts:31-85` 说明 DB secret 由 Keystore 派生，用于 SQLCipher；`setEncryptionSecret` 失败时当前代码会 warning 并沿用既有 secret（`55-63`），改密路径暂未实现。
2. `frontend/src/native/keystore.ts:39-57,59-98` 只定义 Capacitor Plugin 接口；无原生插件时使用抛错 stub。不能把 TypeScript facade 当作所有平台已有硬件保护。
3. `frontend/src/native/crypto.ts:14-77` 在 Web Crypto 中将主密码 PBKDF2 100000 次派生 AES-GCM key；salt 存 localStorage（`17-44`），并保留旧静态 salt key 兼容解密（`69-76,116-145`）。
4. `frontend/src/stores/auth.ts:8-24,31-79` 将 JWT/user/workspace 写入 localStorage；这与 Vault master key 的保护边界不同。
5. 本地邮件凭据列标明 AES-GCM 加密（`frontend/src/native/schema.ts:124-137`），服务端 SMTP/邮件账号也存在加密凭据读写路径，真实密钥材料的部署边界仍需单独取证。

### 3.2 建议的 key hierarchy

```text
OS hardware root / Android Keystore / iOS Keychain
  └── device wrapping key (不可导出或受生物认证保护)
       ├── database key (SQLCipher)
       ├── content key (workspace/asset 分层)
       └── credential key (仅 connector session 解封)
```

- 主密码只用于解锁/派生，不作为数据库或网络 API 的长期 bearer token。
- 每个 workspace 使用独立 content key；每个 Asset/Blob 使用随机 DEK，DEK 被 workspace key wrap。
- credential key 与 content key 分离；读取 SMTP/OAuth/LLM credential 需要 connector capability，不因解锁普通笔记而自动暴露。
- key metadata：`key_id`、算法、用途、创建时间、状态(active/retiring/revoked)、父 key id；密文带 key id，支持平滑轮换。
- 设备注销、workspace 移除、用户 lock 时，撤销 session/ticket/capability；内存明文按最短 TTL 清除。

### 3.3 Web/PWA 降级

Web 端没有原生 Keystore 时，必须显式显示保护等级：

- 不允许把 L3 credential 当作普通 localStorage 数据；
- 可只提供云端密文同步或只读功能；
- 浏览器刷新/lock 后清除内存 CryptoKey；
- 禁止“legacy-token”兼容路径在生产变成真实授权。当前登录回退逻辑位于 `frontend/src/features/auth/LoginView.vue:161-190`，必须由部署模式门禁控制。

**验收标准**：移动端密钥不可由 JS 直接导出；PWA 明确降级且不允许 secret 操作；lock 后读取 Vault/邮箱 credential 失败；不同 workspace 使用不同 key scope；key version 可识别并支持迁移/回滚策略。

## 4. Capability 与授权矩阵

### 4.1 Capability 命名

采用资源、动作、数据级别三元语义，例如：

- `asset.read:L1`、`asset.read:L2`、`asset.export:L2`
- `credential.use:imap`、`credential.use:smtp`、`credential.use:oauth-refresh`
- `session.read`、`session.dispatch`、`session.migrate`
- `agent.invoke`、`plugin.command`、`network.egress:llm`
- `audit.read`、`approval.decide`

能力不能仅由 Agent/Plugin 自报；服务端 Registry/Policy 根据安装包签名、版本、workspace owner 授权和运行时上下文裁剪。

### 4.2 最小权限矩阵

| 主体 | 默认能力 | 需要额外批准 |
|---|---|---|
| 普通 user | 读写本人/当前 workspace 的 L1；发起低风险 Run | L2 出端、发信、迁移、插件命令、凭据使用 |
| workspace owner/admin | 成员/设备/审计管理；策略配置 | L3 凭据读取、跨用户数据、私网出站 |
| Agent | 仅绑定 workspace/instance、声明 tool 的输入 | shell、文件系统、network、跨 Asset kind |
| Plugin/Manager | heartbeat、能力范围内 command ack | 任意 session 控制、迁移、读取 L2/L3 |
| Worker/connector | 仅某个 Action 的短期 capability | 不得把 token 或明文 payload 传给另一个 worker |
| System | migration/repair 的编排能力 | 仍需保留原始 actor、workspace 和审批来源 |

**现状事实**：Agent 的 `Capabilities []string` 在创建接口中作为元数据进入（`server_agentbridge.go:145-171`）；目前并不等价于上述可执行 policy。Plugin WS 虽将 workspace/user 写入 metadata（`server_plugin_ws.go:57-74`），但 capability、设备信任、命令审批和过期策略需补齐。

## 5. 凭据生命周期

### 5.1 创建与存储

- 输入端只允许一次性提交 secret；成功后响应只返回 `credential_id`、provider、masked fingerprint、key version。
- 服务端先校验 workspace/account ownership，再用 KMS/Keystore wrapping 写密文；禁止把 secret 放进普通 Asset body、Task、Event、Audit。
- OAuth：`state` 绑定 user/workspace/provider/redirect/nonce 并一次性消费；PKCE verifier 只存在短期 server-side pending store。
- SMTP/IMAP：account row 是 workspace 归属权威；后台 scheduler 从 account row 派生 workspace，不接受客户端传入归属。

### 5.2 使用

- Connector 获取短期明文句柄/内存 buffer，不返回通用 API；调用结束立即清除引用并写使用结果摘要。
- 每次使用检查 workspace membership、credential status、capability、purpose 和 approval（若需要）。
- 禁止在 goroutine、panic、错误包装、重试队列或 URL 中携带明文 credential。
- 第三方 provider 只收到必要 scope；LLM/Gateway 只收 provider alias，不把租户 API key 推送到共享实例。

### 5.3 轮换、撤销与恢复

- 状态机：`active → retiring → revoked`；旧 key 在 grace window 内仅支持验证，不接受新写入。
- 轮换先写新版本、验证 connector，再切 active；失败回退到旧版本，但必须产生 Audit。
- workspace 成员撤销、设备注销、疑似泄露、provider revoke、密钥轮换都会使相关短期 ticket/capability 失效。
- 恢复只恢复密文版本或重新录入；不得从日志、死信或历史 prompt 恢复明文 secret。

**重要边界**：本文只定义轮换方案和验收；不会执行任何实际凭据轮换、历史清理、Git rewrite 或外部 provider revoke。

## 6. 日志、监控与审计

### 6.1 日志分层

- `security.audit`：actor/workspace/action/resource/decision/result/correlation/digest/key version；长期保留但不可变。
- `operational`：延迟、状态码、重试次数、连接状态、实例健康；不含 payload。
- `debug`：默认关闭生产；即使开启也只允许经过 redaction profile 的采样字段。
- `client`：禁止 `console.log(message.data)`；当前通用 WS handler 在 `frontend/src/services/websocket-hub.ts:160-170` 会记录消息 data，应改为类型、id、大小、digest。

### 6.2 必须脱敏字段

`Authorization`、`token`、`access_token`、`refresh_token`、`client_secret`、`api_key`、`password`、`credential_encrypted`、`cipher_blob`、邮件正文、会议 transcript、prompt、LLM response、文件路径、Cookie。对 URL 做 query/fragment 清空或 allowlist 序列化。

### 6.3 审计事件

至少覆盖：登录/登出/刷新/失败、workspace 创建/切换/成员/设备、凭据创建/使用/轮换/撤销、OAuth start/callback/revoke、IMAP sync、SMTP probe/send、LLM/STT/RedClaw 出端、Agent invoke、Plugin command、Session dispatch、Migration、Asset push/pull/conflict/restore、Approval decision、管理员读 Audit。

**验收标准**：给定 `correlation_id` 可以找到完整因果链，但任何查询结果都无法还原 L3 明文；审计查询按 workspace 强制隔离，非 admin 不可读取全 workspace；日志保留和删除有书面期限，删除动作自身也留 Audit。

## 7. 具体待验证项

| 项目 | 验证方式 | 通过条件 |
|---|---|---|
| 原生 Keystore 是否真实注册 | Android/iOS 真机检查插件、锁屏/生物识别测试 | JS 无法绕过锁定读取 L3 |
| localStorage token 泄露 | 浏览器历史、代理、XSS/console、崩溃报告检查 | 只见 ticket/opaque session，不能重放 JWT |
| OAuth | Google/Microsoft sandbox 全流程 | state/PKCE/redirect/revoke/refresh 均成功且 scoped |
| LLM/STT/RedClaw 出端 | 测试代理抓包 + provider retention 配置 | L2/L3 只按 policy 最小出端 |
| SMTP/IMAP | 无效/超时/畸形服务器、凭据错误和取消测试 | 无 hang、无凭据日志、workspace 归属不漂移 |
| Plugin/Agent | 恶意 plugin、跨 workspace ID、重复 command、断线恢复 | 能力外命令拒绝且不产生副作用 |
| 审计脱敏 | 全量日志/APM/错误/死信扫描 | 无秘密明文和完整敏感正文 |
| 轮换 | 双 key grace、connector failover、旧 key revoke | 新写入使用新 key，旧 key 不能新建会话 |

## 8. 优先级与依赖

### P0

1. 完成 tracked secret/工件取证；在确认影响后由负责人执行轮换和历史治理。
2. 取消实时通道长寿命 query JWT，落地 ticket/cookie；token 不进日志和 localStorage。
3. 强制 workspace/session/agent/plugin/migration scope；共享实例改为显式系统 policy。

**兼容窗口**：实时通道改造必须先发布日志脱敏，再以服务端同时支持 ticket/cookie 与旧 query JWT 的方式过渡。旧 query JWT 只能在明确版本和截止日期内兼容，且限制为最小通道、最短 TTL 和高可见告警；截止后服务端 fail closed。localStorage JWT 迁移到 Keystore/Keychain 时，Web/PWA 只能保留非敏感 hint 或 opaque session，不得把旧 localStorage token 当作长期生产授权回退。

**依赖**：客户端发布、反向代理配置、Identity/Registry policy。**风险**：旧客户端断连、需要短期兼容，但兼容期间不能继续暴露长期 token；回滚不得撤销已上线的日志脱敏和拒绝策略。

### P1

1. 引入 capability/Approval/Action 并覆盖凭据使用、发信、LLM、迁移、插件命令。
2. 分离 credential key/content key，接入原生 Keystore；补成员 expiry/revocation。
3. 统一日志脱敏和 Audit，完成 provider/真实设备/断网回归。

**依赖**：统一数据模型、KMS/Keystore、审计平台、沙盒 provider。**风险**：过度收紧 policy 可能阻断既有自动化，需要按 capability 灰度。

### P2

1. 旧表逐类迁移至 Asset 与 classification；补 retention/deletion/restore。
2. 统一 SSE/WS 事件投影和 durable replay；将 debug 采样纳入隐私审批。

**依赖**：数据字典、CAS/事件模型、迁移和恢复演练。**风险**：历史数据分类不完整，先隔离、后迁移、可逆发布。

## 9. 隐私安全最终验收

- **最小化**：每个出端请求可回答“谁、为何、向谁、发了哪些分类字段、依据哪条 capability”。
- **隔离**：同一 user 多 workspace 的 Asset、Vault、邮箱、Task、Session、Agent、Plugin、Audit 绝不共享隐式默认边界。
- **密钥**：L3 只在 Keystore/KMS 与短暂 connector 内存中出现；日志、URL、普通 DB、前端 state 均无明文。
- **撤销**：成员/设备/凭据/provider revoke 能使新请求和实时通道及时失效。
- **恢复**：冲突、误删、轮换失败、worker 重启可恢复，但恢复不会从历史日志重新暴露 secret。
- **证明**：每项通过条件均有测试/抓包/配置审计证据；没有“代码看起来安全”替代运行验证。
