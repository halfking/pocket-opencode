# 11 并行执行提示词

**版本**：优化 v4
**日期**：2026-08-14
**用途**：复制以下任一提示词分派给独立 agent。提示词默认面向后续开发，不改变本次“只写文档”的限制；执行 agent 必须遵守其任务范围和仓库既有指令。

## 0. 通用前缀（每个 agent 都要带）

```text
你在 OpenCode Pocket 仓库执行一个受限任务。先阅读适用的 AGENTS.md（若存在）、本提示词列出的文件和 docs/优化v4/08-移动端UI与交互规范.md、09-实施路线图与验收标准.md、10-任务拆解与依赖图.md。

原则：修根因，不做无关重构；复用已有 token、组件、store、HTTP/WS 客户端；不引入未经批准的依赖；不把 mock、静态检查或历史报告写成真实集成通过；不提交密钥、真实邮箱凭证或个人数据。

完成后报告：改动文件、未改文件、设计/契约变化、已执行的命令与实际结果、未执行测试及原因、已知风险、回滚方式。任何未验证项必须明确写“未执行/未确认”。
```

## 1. 移动状态与路由 agent

```text
角色：移动端架构师 + 前端基础工程师。
范围：只负责 frontend/src/app/router-mobile.ts、frontend/src/stores/、frontend/src/services/ 中与 auth/lobster/network/sync/session/approval 状态和 WS bus 直接相关的文件；必要时补对应类型/单测。
必读：08 §3–§4，09 §3，10 E0/E1，现有 router、auth store、websocket client、lobster-init、相关测试。
交付：状态转移表落地；未登录/已登录未解锁/过期/离线路径正确；事件按 id 去重、过期响应不覆盖新状态、注销时清理订阅；未知事件向后兼容。
禁止：不改后端协议、不新增 Pinia 以外的全局状态框架、不在视图内复制 WS 连接、不把 failed 当 rejected、不删除 Web fallback。
测试：执行与改动相关的 typecheck/build 和现有单测；若没有测试运行器，报告实际未执行项。
验收：可从状态树逐项追溯实现；刷新、退出、重连、重复事件、乱序事件均有证据；失败反馈可重试且不丢上下文。
```

## 2. 审批与 Agent 会话 agent

```text
角色：Agent/实时交互工程师。
范围：会话列表/详情、流式消息摘要、权限和问题请求 UI 与对应后端状态处理；只修改授权的 feature、agent、websocket/server 文件。
必读：08 §3.3、§4.3–§4.4，10 E2，现有 ACP adapter、permission_manager、question_manager、mobile_api、WS hub。
交付：pending→submitting→approved/rejected/expired/failed 状态；审批卡显示动作、资源、影响范围、详情；服务端确认前不显示成功；重复响应幂等。
禁止：不实现“手机审批”之外的产品宣传；不得加入滑动作为唯一批准方式；不得默认“始终允许”；不得记录命令参数、token、密钥到日志；不得绕过 workspace/user scope。
测试：覆盖批准/拒绝/网络失败/超时/重复/乱序/过期/未知事件；后端用 httptest 或现有测试模式，前端做可执行检查。
验收：P0 核心流程可录屏；失败保留请求；审计字段可定位 user/workspace/session/request；所有测试结果逐条标注实际状态。
```

## 3. Notes/Email/Vault 功能 agent

```text
角色：移动端 feature 工程师。
范围：只负责一个指定模块（Notes、Email 或 Vault）的详情/编辑/错误/空/加载/离线交互和对应 store 小范围补全；不跨模块重构。
必读：08 §2–§7，现有模块 store、API、路由、2026-07-02 frontend blueprint、2026-08-08/09 审计。
交付：页面状态完整；保存/取消/重试/返回键行为明确；Markdown/HTML 走既有清洗；敏感字段生命周期清理；云/本地来源和更新时间可见。
禁止：不使用 alert 作为唯一反馈；不直接 innerHTML 未清洗内容；不把本地缓存标为实时；不新增未批准依赖；不修改不属于本模块的路由契约。
测试：执行模块相关 typecheck/build/单测；手工覆盖浅色/暗色、窄屏、横屏、字号放大、读屏；未具备环境的项必须写未执行。
验收：主流程可用点击完成；加载、空、错误、离线、冲突、重复提交均有可见状态；与既有 tokens 和共享组件一致。
```

## 4. 后端 API 与作用域 agent

```text
角色：Go API 与数据安全工程师。
范围：只负责一个明确端点集合及其 handler、DTO、store 查询、迁移和测试；先核对现有路由，不重复造端点。
必读：08 §4，09 §3，10 E3/E6，server 路由、相关 store、2026-08-08/09 审计。
交付：400/401/403/404/409/422/429/503 语义清晰；所有查询和写入带 user/workspace scope；超时、大小限制、幂等键、错误脱敏、审计字段齐全；迁移可重复执行。
禁止：不得以 userID='local' 或 default 作为新功能的安全隔离；不得把共享实例凭据推给租户；不得吞错返回 200；不得修改无关 schema；不得将真实凭证写测试。
测试：`go test`、`go vet` 和相关 DB-gated/httptest；若需要 Postgres 必须使用隔离 DSN，并报告是否真正运行；必要时 `-race`。
验收：跨 user/workspace 正向与反向用例均有测试；未知资源不泄露存在性；迁移、回滚或不可逆边界有说明。
```

## 5. Android 原生能力 agent

```text
角色：Android/Capacitor 原生工程师。
范围：只负责指定插件（录音、Keystore/生物识别、通知或后台任务）及 TS bridge；保留 Web fallback 与能力探测。
必读：08 §3.2、§5，09 P1/P2，10 E4，`frontend/android/`（唯一 Android 构建事实源）、`frontend/capacitor.config.*`、现有 native 桩和 TS bridge。根 `android/` 目前只是占位/同步脚本目录，不得据此推断另一套发布工程。
交付：权限申请前说明用途；拒绝、永久拒绝、取消、进程重启、后台限制均可恢复；敏感数据不落明文日志；插件 API 与 TS 类型一致。
禁止：不假设 iOS 能力存在；不绕过系统权限；不在后台无限重试；不删除 Web fallback；不提交 keystore、音频或签名文件。
测试：Android 构建、模拟器能力测试、至少一台真机（若可用）、权限状态矩阵；没有设备时明确未执行，不得写通过。
验收：能力不可用时用户仍可完成替代流程；录音/密钥生命周期有清理和错误状态；安装/升级/回滚影响写清楚。
```

## 6. QA 与故障注入 agent

```text
角色：移动端 QA / SDET。
范围：只新增或维护测试、夹具、故障注入和验收报告；不为让测试通过修改产品逻辑。
必读：08 §4–§5，09 全文，10 E0-S4/E2-S4/E6-S4，现有 CI 与测试报告。
交付：设备矩阵、核心任务样本、网络/WS/数据库/权限故障矩阵、可重复命令、实际日志和缺陷分级。
禁止：不把 mock 通过写成真实服务通过；不跳过 DB-gated 测试后声称全绿；不修改生产配置绕过安全检查；不将历史报告当本次证据。
测试：从最小相关测试开始，再扩大到全量；记录提交号、设备、OS、依赖服务和时间；性能指标无基线时先产出基线。
验收：每个 P0 指标有分子/分母和样本量；失败可复现；报告区分已通过、失败、阻塞、未执行、未确认。
```

## 7. 安全审计 agent

```text
角色：应用安全工程师。
范围：审查新增移动流程、审批、作用域、日志、凭据、WebView/Markdown/HTML 和依赖；只提交审计修复或报告。
必读：08 §3.3、§5–§6，09 安全门，10 E0-S3/E6-S1/E6-S2，既有 2026-08-08/09 审计。
交付：威胁模型、滥用案例、严重度、最小修复、回归测试、残余风险和上线建议。
禁止：不把“有 JWT”当作授权完成；不把手机 UI 作为安全边界；不发送真实数据到外部服务；不证明不存在漏洞，只报告证据范围。
测试：越权、重放、重复批准、日志泄露、XSS/Markdown 注入、SSRF/超时、敏感剪贴板和锁屏泄露；所有未执行项明确标注。
验收：P0/P1 风险有 owner 和截止条件；修复后测试能失败再通过；残余风险进入 12-ADR 与风险台账。
```

## 8. 发布/回滚 agent

```text
角色：发布工程师。
范围：只负责 CI 门禁、feature flag、构建产物、迁移、监控、灰度和回滚文档/脚本。
必读：09 §4–§6，10 E6，现有 .github/workflows、deploy 脚本和数据库迁移约定。
交付：客户端/后端版本兼容矩阵；发布前检查；开关关闭路径；备份/恢复步骤；应用回滚与数据迁移边界；告警和现场保留。
禁止：不通过容错 shell 让失败命令显示成功；不删除失败日志；不在生产直接试迁移；不把未演练回滚写成已验证。
测试：在隔离环境执行构建、迁移、回滚和健康检查；记录退出码与产物 hash；无法执行的生产演练标为未执行。
验收：发现误批准、越权、丢数据、崩溃或敏感泄露可在约定时间内停止扩量并回到上一稳定状态。
```

## 9. Agent 汇报模板

```text
结果：已完成 / 部分完成 / 阻塞
范围：实际修改的文件与明确未修改的文件
契约：新增/变更的接口、状态、事件、迁移
验证：命令、环境、提交、实际输出摘要
未执行：测试、设备、真实服务或审计盲区及原因
风险：严重度、owner、下一步
回滚：关闭开关/回滚提交/恢复数据的具体步骤
```
