# 12 ADR 与风险台账

**版本**：优化 v4
**日期**：2026-08-14
**状态**：方案评审稿；ADR 在对应 PR 合并前需由 owner 和 reviewer 确认

## 1. ADR

### ADR-001：保持 Vue 3 + Capacitor，不新建移动端技术栈

- **状态**：Accepted for P0–P2
- **背景**：仓库已有 Vue 3/TypeScript/Vite、Android Capacitor 工程和 native bridge；另起 Flutter/React Native 会重写路由、store、测试和发布链路。
- **决定**：P0–P2 复用现有 WebView + Capacitor；原生能力用小而清晰的插件边界；iOS 只在真实构建验证后宣称支持。
- **后果**：交付快、复用高；但 WebView 性能、后台限制和平台差异需要专项验证。
- **拒绝方案**：当前阶段不因“原生体验更好”重写全部客户端。

### ADR-002：本地优先，云端能力显式显示来源和状态

- **状态**：Accepted
- **决定**：Notes/Vault 等敏感数据本地优先；云端同步、LLM、分类和审批通过明确的 loading/synced/offline/conflict 状态呈现。
- **后果**：离线可用性更好，但需要幂等键、冲突模型、队列和容量管理；不能把本地缓存误标为实时。

### ADR-003：审批以服务端确认作为唯一成功依据

- **状态**：Accepted / P0
- **决定**：客户端按钮点击只进入 `submitting`；收到服务端确认事件/响应后才进入 `approved`。超时、断线和重复请求保持 `failed` 或 `pending`。
- **后果**：用户可能多等一次网络往返，但避免“手机显示已批准、实际未执行”的高风险错觉。
- **补充**：不以滑动作为唯一批准/拒绝入口；持久化“始终允许”必须显示范围和影响。

### ADR-004：WS 采用快照 + 增量事件，并要求事件幂等

- **状态**：Accepted
- **决定**：连接/重连时拉取或接收快照，平时处理带 `event_id`、版本/时间和资源 ID 的增量事件；客户端去重，服务端状态为权威。
- **后果**：实现稍复杂，但可恢复断线、乱序和重复；未知事件必须忽略并保留可诊断日志。

### ADR-005：状态放在 feature store，不把业务状态全部塞进 Pinia

- **状态**：Accepted
- **决定**：Pinia 仅承载认证、设备和跨模块状态；Notes/Email/Vault/Meetings/Agent 各自维护领域状态，使用统一异步状态类型。
- **后果**：边界清晰、减少耦合；跨模块聚合需要事件总线或只读 selector，禁止互相直接改内部状态。

### ADR-006：权限按最小权限、默认单次，作用域由 user/workspace 双重约束

- **状态**：Accepted / Security gate
- **决定**：读取、编辑、命令、外部目录等动作显示具体目标；后端每次校验 user/workspace/resource；客户端不承担授权。
- **后果**：需要保持 workspace 字段一致并为共享实例另行定义配置人；兼容旧客户端时先兼容协议再收紧行为。

### ADR-007：敏感复制内容采用生命周期清理，但不宣称绝对安全

- **状态**：Accepted with residual risk
- **决定**：Vault 复制时显示倒计时；页面离开、卸载或超时清理 clipboard，并清理 timer/listener；同时提醒系统/第三方键盘可能保留剪贴板。
- **后果**：降低暴露窗口但无法控制系统剪贴板历史、截图、备份或恶意设备。

### ADR-009：Android 只保留一个构建事实源

- **状态**：Accepted for P0
- **决定**：`frontend/android/` 是当前 Capacitor Android 的唯一构建、安装和 CI 事实源；根 `android/` 仅保留占位 README 与同步脚本边界，不作为第二套发布工程。任何 Capacitor 版本升级必须同时更新 `frontend/package.json`、Gradle 配置和 CI 记录。
- **后果**：避免 agent 在两个目录之间误选；短期需要清理版本漂移和补充路径说明。

### ADR-010：P0 回滚能力先于功能开关承诺

- **状态**：Proposed / P0a gate
- **决定**：在 REL 定义配置位置、默认值、读取方、审计和旧路径回退前，不得在 PR 中写“关闭 flag 即可回滚”。数据库变更必须标记可逆/不可逆、备份点和应用层回退方式。
- **后果**：P0 前置工作增加，但回滚步骤可执行、可审计。

### ADR-011：`/api/v4` 先冻结范围，再决定首批实现

- **状态**：Proposed / E0-S5
- **决定**：`/api/v4` 是目标 control-plane 合同；PR1/E0-S5 必须明确首批是否实现 facade。未纳入首批时，P0 只修复既有端点的 scope/确认语义，前端不得依赖未落地 v4 路由。
- **后果**：避免方案 API 与 PR 计划脱节，减少未完成合同被误当成现状。

### ADR-008：不把“移动端 Codex”或“手机审批”作为竞品事实

- **状态**：Accepted
- **决定**：产品可实现手机访问自有 Pocket 后端的会话和审批，但对外材料必须区分“本项目能力”和官方产品能力；没有证据就写“未确认”。
- **后果**：避免把 ACP/CLI 接入误说成独立 Codex 移动端，也避免暗示官方提供手机批准代码操作。

## 3. 风险升级与停线规则

出现跨 workspace 访问、未经确认的批准、密钥/邮件正文入日志、数据丢失、未捕获 goroutine panic 或客户端崩溃时，立即按 P0 处理：停止灰度、保留日志和版本信息、关闭相关 feature flag，必要时回滚应用/服务。风险关闭必须有复现用例、修复提交、回归结果和 reviewer 签名；“代码看起来正确”不等于关闭。
