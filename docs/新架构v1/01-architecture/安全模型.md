# 安全模型 v3（审计修正版）

> 状态：**规范草案，未实现**
> 
> 本文档定义目标安全契约，不代表当前 pocketd、RedClaw 或 ZAgentGateway 已满足这些要求。当前审计结论见 [`00-research/RedClaw作为OpenCode后端审计.md`](../00-research/RedClaw作为OpenCode后端审计.md)。

---

## 1. 重要边界

### 1.1 RedClaw 不是 OpenCode drop-in runtime

- RedClaw platform-go 当前是企业控制面和 OpenClaw runtime 包装；
- OpenCode 仍负责 `/session`、message parts、`/event` SSE、permission/question、PTY、工具循环和 ACP；
- ZAgentGateway 只能在完成协议映射和安全验证后，作为控制面适配器；
- 不得把 RedClaw `/api/v1/tasks` 或 `/api/v2/tasks` 宣称为 OpenCode `/session` 兼容接口。

### 1.2 安全降级必须保持同等安全等级

以下降级一律禁止：

- mTLS 失败后自动降级为仅 HMAC；
- ZAgentGateway 不可用后绕过授权直接访问 RedClaw 或本地 CLI；
- 审计不可写时继续执行高危操作；
- 为恢复可用性自动切换到违反租户数据驻留策略的 Provider；
- 超时后不查询状态就重复执行写操作。

只读状态可以有限降级；任何 shell、文件写入、IDE 写操作、git push、Pod 控制和密钥操作必须 fail-closed。

## 2. 信任域

```text
┌──────────────────────────────────────────────────────────────────┐
│ 不可信客户端域                                                    │
│ 手机、浏览器、第三方 MCP 客户端、IDE 插件输入、用户 prompt        │
└──────────────────────────────┬───────────────────────────────────┘
                               │ TLS + 已验证用户身份
                               ▼
┌──────────────────────────────────────────────────────────────────┐
│ Pocket 控制域                                                     │
│ pocketd：移动 BFF、JWT 验证、对象授权、WS/SSE 出口、通知          │
└──────────────────────────────┬───────────────────────────────────┘
                               │ delegated service token + mTLS
                               ▼
┌──────────────────────────────────────────────────────────────────┐
│ ZAgentGateway 控制适配域（规划中）                                │
│ task/run/session 映射、策略投影、OpenCode/RedClaw 事件转换、审计    │
└───────────────┬──────────────────────────────┬───────────────────┘
                │                              │
                │ delegated token + mTLS       │ scoped token + mTLS
                ▼                              ▼
┌───────────────────────────┐       ┌──────────────────────────────┐
│ RedClaw 控制域             │       │ acc-go 编排域                 │
│ tenant/policy/approval/   │       │ taskdecompose/orchestrator/   │
│ audit/OpenClaw adapter    │       │ mission/MCP                    │
└──────────────┬────────────┘       └──────────────────────────────┘
               │ 出站连接 / 受限本地接口
               ▼
┌──────────────────────────────────────────────────────────────────┐
│ 用户 PC 执行域                                                    │
│ OpenCode runtime 或 OpenClaw runtime、workspace、shell、IDE、git   │
└──────────────────────────────────────────────────────────────────┘

外部 Provider、Git 服务、包仓库、浏览器和 Webhook 均视为不可信外部域。
```

**原则**：用户 PC 上的 RedClaw/IDE 不应把管理端口直接暴露到公网；优先使用出站长连接或内网 mTLS 通道接入 ZAG。

## 3. 身份与委托链

### 3.1 唯一身份来源

租户、用户、设备和权限范围只能来自已验证的身份断言：

- 请求 JWT 的 claims；
- mTLS 证书的已注册主体；
- 服务端持久化的 subject-to-tenant 绑定。

`X-Tenant-ID`、`X-User-ID`、`fleetId`、`userId` 只能作为一致性检查或 trace hint，不能单独授予权限。body/query 中的租户字段与 claims 不一致时必须返回 403。

### 3.2 服务间 delegated token

服务间不复用用户 token，也不使用一个全局共享 HMAC 代表所有用户。目标 token 至少包含：

```json
{
  "iss": "pocketd",
  "aud": "zagent-gateway",
  "sub": "user-id",
  "tenant_id": "workspace-id",
  "actor_id": "device-or-service-id",
  "actor_type": "user|service|worker",
  "delegated_by": "pocketd",
  "scope": ["agent:read", "task:create"],
  "jti": "unique-token-id",
  "iat": 0,
  "exp": 0
}
```

ZAG、RedClaw、ACC 必须验证签名、`iss`、`aud`、`exp`、`jti`、scope 和对象 tenant。token TTL 默认不超过 5 分钟；支持 `kid`/JWKS 或等价的轮换机制。

### 3.3 最小授权矩阵（M0 必须实现）

| 角色 | 读取状态 | 创建/取消自己的任务 | 审批自己的任务 | IDE 写操作 | Pod 控制 | 密钥/策略 |
|---|---:|---:|---:|---:|---:|---:|
| viewer | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| operator | ✅ | ✅ | ❌ | 仅低风险 | ❌ | ❌ |
| approver | ✅ | ✅ | ✅（绑定资源） | 按策略 | ❌ | ❌ |
| admin | ✅ | ✅ | ✅ | 按策略 | 按策略 | 受限 |

每次授权都必须同时校验 tenant、workspace、pod、agent、session、task 和 resource owner。

### 3.4 MCP 独立授权

ZAG MCP 不复用普通 Web JWT：

- 使用已注册的 MCP client 身份；
- 每个 client 绑定 tenant、用户/服务主体和 scopes；
- 工具 allowlist 按 `read`、`task:create`、`permission:approve`、`ide:write` 等 scope 控制；
- 写工具默认关闭；
- 每次 `tools/call` 重新进行对象授权；
- MCP session 不得把上一个租户的上下文复用给下一个租户。

## 4. 高危命令与 IDE 控制

### 4.1 命令注册表

ZAG 只允许调用已注册的命令 schema，不接受任意 command string：

```yaml
commands:
  file.read:
    risk: low
    approval: none
  ide.open_file:
    risk: low
    approval: none
  ide.apply_diff:
    risk: medium
    approval: policy
  shell.run:
    risk: high
    approval: always
  git.push:
    risk: high
    approval: always
  pod.terminate:
    risk: critical
    approval: dual_operator
```

执行点必须再次校验权限，不能只在 LLM tools 列表中过滤。

### 4.2 workspace 和路径边界

- 所有路径先 canonicalize，再验证位于已授权 workspace root；
- 拒绝绝对路径、`..`、符号链接逃逸、UNC 路径和跨设备挂载；
- 对检查与执行使用同一打开句柄或安全目录句柄，防止 TOCTOU；
- workspace 外的写入一律拒绝；
- command 使用 argv，不接受未经解析的 shell 字符串；
- 环境变量采用 allowlist，禁止继承 provider key、SSH key、系统 token；
- 限制 cwd、CPU、内存、进程数、网络出口、输出大小和 wall-clock timeout；
- connector endpoint 必须来自 Pod 注册表 allowlist，禁止任意 URL/SSRF。

### 4.3 双开关与审批

高危工具需要：

1. Pod/设备级 consent；
2. Agent 级 grant；
3. task/session 级 policy 允许；
4. 对 `git.push`、删除、部署、Pod 控制等操作额外 human gate。

`allow_always` 只能在限定 tenant/workspace/agent/tool/参数约束下生效，必须有过期时间、版本号、撤销记录；不能是全局永久放行。

## 5. mTLS、密钥和签名

### 5.1 mTLS 生命周期

- 证书由受管 CA 签发，不允许运行时自动信任未知自签 CA；
- enrollment 使用一次性 token，并绑定 tenant、Pod、ZAG instance；
- leaf certificate 短期有效，支持重叠轮换；
- 维护吊销列表/状态和紧急 revoke；
- CA rollover 必须支持旧/新 CA 的受控重叠窗口；
- 私钥进入 KMS/HSM 或 OS keystore，不写入镜像和普通日志。

### 5.2 请求签名与防重放

所有写请求至少绑定：

```text
HTTP method + normalized path + body SHA-256 + tenant + subject
+ issued_at + expires_at + nonce + key_id
```

服务端必须持久化 nonce/jti，拒绝重复使用、过期和未来时间漂移过大的请求。所有跨服务写请求要求 `Idempotency-Key`。

### 5.3 Ed25519 双签

Rollback、Upgrade、Terminate 等控制命令的签名对象必须是 canonical JSON，包含：

- command、tenant、pod、task/session；
- 参数和 artifact/diff digest；
- 当前 aggregate version；
- policy version；
- nonce、issued_at、expires_at；
- 发起者和审批者主体。

第二个签名必须来自独立主体、独立设备或独立审批服务；ZAG 不得持有第二个 admin 私钥。RedClaw 必须持久化一次性消费记录，并拒绝签名者与发起者违反独立性规则的请求。

## 6. WebSocket/SSE 安全与可靠性

- 新建连接使用 Authorization header、受限 HttpOnly cookie 或一次性短期 WS ticket；禁止把长期 JWT 放 query string；
- 校验 Origin、tenant 和 client scope；
- `subscribe` 时逐对象授权，不因已认证就允许订阅任意 task/pod；
- 每个事件包含 `event_id`、`sequence`、`schema_version`、`tenant_id`、`aggregate_id`；
- 定义 Last-Event-ID 补偿、去重和 out-of-order 处理；
- 限制单连接消息数、消息尺寸、订阅数量和缓冲区；
- 慢消费者不得阻塞其他租户，必要时断开并提供补偿；
- token 过期/撤销后主动关闭连接并要求重新认证；
- 异步事件必须有 durable outbox 或可重放 source cursor。

## 7. SSOT、幂等和故障恢复

### 7.1 领域状态

在真正实现前必须冻结映射：

```text
acc_task → zag_operation → redclaw_task/run → opencode_session
```

- ACC 负责编排状态；
- ZAG 负责适配 operation 和映射索引；
- RedClaw 负责其控制面 task/run；
- OpenCode 负责 session/runtime 状态；
- 任何状态冲突由 reconciliation worker 解决，不能由 mobile 猜测。

### 7.2 幂等

统一字段：`operation_id`、`idempotency_key`、`trace_id`、`event_id`、`aggregate_version`。超时后先 query/reconcile，再 retry；未知结果必须进入 `indeterminate`，不能直接重放写操作。

### 7.3 多副本

以下状态不得只放内存：

- pending control/approval；
- SSE cursor；
- operation mapping；
- idempotency result；
- WS ticket/revocation；
- event outbox。

ZAG 多副本使用 PostgreSQL/Redis 等共享持久状态，并通过 lease/唯一约束避免重复执行。

### 7.4 审计不可静默丢失

高危写操作必须先写 durable append-only outbox，再执行；审计后端不可达时阻止高危操作。Memora 作为检索/长期记忆层，不应是唯一不可篡改审计存储。审计记录至少包含：actor、delegator、tenant、设备、源 IP、操作摘要、参数/diff hash、policy version、审批人、签名 key ID、前后状态和结果。

### 7.5 RPO/RTO

上线前必须为 ZAG、PostgreSQL、Redis、证书、配置、Memora 审计归档定义并演练：

- RPO/RTO；
- 备份加密和访问控制；
- 恢复顺序；
- PC 离线、断线重连和未知执行结果处理；
- 至少一次定期 restore drill。

## 8. 数据保护与国内合规

### 8.1 数据分类

必须登记并按租户策略处理：

- 代码、diff、仓库 URL、文件路径；
- shell/IDE/OpenClaw 输出；
- prompt、语音、照片和附件；
- API key、SSH key、环境变量；
- PC 硬件、IDE、OpenClaw 版本和网络元数据；
- 任务、审批、审计和 usage；
- provider 请求和响应。

### 8.2 数据最小化

- 默认不把完整源码、终端输出和 prompt 写入普通日志；
- 事件正文与审计摘要分离；
- 代码/diff/prompt 采集有独立开关、大小限制、脱敏和 retention；
- 通知只展示摘要，正文按对象授权懒加载；
- 删除请求必须传播到缓存、ZAG、RedClaw、Memora、对象存储和备份策略允许的范围内。

### 8.3 合规声明边界

“境内节点”“境外提示”“可导出/删除”是目标要求，不是当前能力证明。上线前由合规负责人确认适用的网安法、数据安全法、个人信息保护法、等保、数据出境和生成式 AI 服务要求，并形成数据处理清单、保存期限、第三方处理、事件响应和用户权利流程。

### 8.4 日志脱敏

代码、diff、命令输出、Git URL 凭据、环境变量、SSH key、JWT、provider key 和模型上下文不得默认进入集中日志。日志字段使用 allowlist，未知字段默认丢弃或哈希化。

## 9. 供应链与发布

OpenClaw、OpenCode、IDE 插件、容器镜像、ZAG 二进制和 GitHub 导入 Skill 均纳入：

- 版本 + digest 固定；
- 签名/来源验证；
- SBOM 和 provenance；
- 漏洞门禁；
- 分批 canary；
- anti-rollback；
- 可撤回版本；
- 数据库 migration 的 forward/rollback 设计；
- 混合版本兼容矩阵。

不把未验证的 `curl | sh` 作为生产安装方式；安装包必须有可验证的签名和 checksum。

## 10. 发布门禁

M0/M1 未满足以下条件，不得开放真实租户的远程写能力：

- 身份链和对象级授权通过测试；
- 命令 schema、workspace sandbox 和 connector allowlist 通过测试；
- mTLS enrollment/rotation/revoke 通过测试；
- 防重放、幂等和未知结果 reconciliation 通过测试；
- WS/SSE 补偿、去重和背压通过测试；
- 审计 outbox 可恢复且高危操作 fail-closed；
- 最小 RBAC/ABAC 和 MCP scopes 已上线；
- OpenCode contract 与固定版本真实联调通过；
- ZAG/RedClaw/ACC 故障注入通过；
- 数据分类、驻留和删除策略经过合规审查。
