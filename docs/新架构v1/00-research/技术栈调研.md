## 1. DeepSeek（API 服务）

### 1.1 模型矩阵

| 模型 | 定位 | 上下文 | 输出上限 | 备注 |
|---|---|---|---|---|
| `deepseek-v4-pro` | 旗舰 | 1M in | 384K out | Pro 版，"highest capability" |
| `deepseek-v4-flash` | 性价比 | 1M in | 384K out | 5× 更高并发（2500 vs 500） |
| `deepseek-v4-flash-vision-exp` | 多模态 | — | — | 实验性视觉版 |

- **API 双兼容**：OpenAI 格式（`https://api.deepseek.com`）+ Anthropic 格式（`/anthropic`）。
- **协议类型**：JSON output、Tool Calls、Responses API、Anthropic API、Chat Prefix Completion、FIM（仅非思考模式）。
- **思考模式**：`reasoning_effort` 参数控制；非思考与思考模式**都能调用工具**（V3.2 起）。

### 1.2 工具调用

- 严格遵循 OpenAI function calling 协议。
- **Strict 模式（Beta）**：`base_url=https://api.deepseek.com/beta` + `strict: true`，服务端校验 JSON Schema。
  - 支持：object/string/number/integer/boolean/array/enum/anyOf、`$ref/$def`。
  - **不支持**：`minLength/maxLength/minItems/maxItems`、`additionalProperties: true`、部分 `pattern/format`。
  - 所有 properties 必须在 `required`，`additionalProperties: false`。
- 思考模式的 Tool Call：模型在 reasoning 之后输出 `<tool_calls>` block，可作为 ACP message 的一部分发送给执行器。

### 1.3 MCP 支持

- 官方文档**未声明** MCP 支持。
- 但因为兼容 Anthropic API 格式，理论上可走 Anthropic SDK 的 MCP 适配层——**需要自实现桥接**。

### 1.4 定价

| 类型 | Flash Peak/Off-peak | Pro Peak/Off-peak |
|---|---|---|
| Input cache hit | $0.014 / $0.007 | $0.044 / $0.022 |
| Input cache miss | $0.44 / $0.22 | $1.32 / $0.66 |
| Output | $1.32 / $0.66 | $3.96 / $1.98 |

- Peak：01:00–04:00、06:00–10:00 UTC。
- 自 2026-08-23（北京时间）起，**周末全 Off-peak**。

### 1.5 我们的集成建议

- `internal/aigate` 已经做了 LLM 代理，新增 `DeepSeekProvider` 实现 `Provider` 接口即可。
- 默认 `deepseek-v4-flash`，代码生成超长上下文场景（1M in）自动切 Pro。
- **Strict 模式**：因为限制太多，**生产不要强制开启**；用普通 Tool Calls + 本地 Zod 校验。
- Token 统计：DeepSeek 返回 `usage.prompt_tokens` / `completion_tokens` / `prompt_cache_hit_tokens`；后者可独立计费 → 走 kxmemory 时优先命中缓存。

## 2. Pi Coding Agent（earendil-works/pi）

### 2.1 是什么

- **作者**：Mario Zechner（`badlogic`，libGDX 之父）。
- **协议**：**MIT**。
- **形态**：最小化、激进的扩展点（"aggressively extensible"）。
- **组织**：GitHub `earendil-works/pi`，monorepo 含多个包：`coding-agent` / `ai` / `agent` 等。

### 2.2 关键能力

| 维度 | 详情 |
|---|---|
| 模式 | interactive TUI / print / JSON / RPC / SDK |
| Providers | Anthropic, OpenAI, Google, DeepSeek, Ollama 等 15+ |
| 系统提示 | minimal，含 AGENTS.md / SYSTEM.md 注入 |
| 历史 | **session tree**（分支/合并上下文） |
| 上下文压缩 | context compaction |
| 扩展 | TypeScript 模块化 extensions、skills、prompt templates、themes |

### 2.3 安装

```bash
curl -fsSL https://pi.dev/install.sh | sh
# 或
npm install -g @earendil-works/pi-coding-agent
```

### 2.4 我们的集成思路

Pi Agent **本身就是我们的"标准躯干"**：单二进制、RPC 模式可被 PocketFleet Executor Bridge 直接驱动。

**集成路径**：

1. **Executor Bridge** → Pi Agent 的 stdio RPC 模式：发 JSON 请求 → 收 SSE 流式事件。
2. Pi Agent 启动时注入 `AGENTS.md`（从 kxmemory 拉取工作区的 Charter）。
3. Pi Agent 用 DeepSeek / GPT / Claude 任一 provider，**用户在 PocketFleet UI 选**。
4. Pi Agent 输出的 tool call 由 Bridge 转发到 "remote tools"：本地没有的工具（git push / docker run / ssh）走 Executor → 真机执行。

**封装为 Adapter**：

```
internal/agent/adapter_pi.go  // 包装 Pi Agent 的 RPC 客户端
- 复用 AgentAdapter 接口
- SubscribeEvents 把 Pi 的 SSE 转成 AgentEvent
- 在 transport_ws.go 或新增 transport_pi_rpc.go 中实现 transport
```

### 2.5 风险与缓解

| 风险 | 缓解 |
|---|---|
| Pi Agent 还年轻（v0.x），breaking changes 多 | 封装在我们自己的 Adapter 后，**上游变动影响半径 = 1 个文件** |
| 远程执行能力内置弱 | Pi Agent 只做 LLM 调用 + 文件编辑；远程命令走 Executor Bridge |
| 多人协作共享 context 缺 | 我们用 kxmemory 注入 AGENTS.md + Skills |

## 3. 算力舱（Compute Pod） —— 执行机抽象

### 3.1 形态分类

| 类型 | 代表 | 优势 | 劣势 |
|---|---|---|---|
| **用户自建边缘盒** | Jetson Orin NX / Hailo-8 / 国产 RK3588 盒子 | 数据不出域；本地延迟极低；可断网作业 | 算力受限；维护成本 |
| **公有云 GPU Pod** | RunPod / Modal / Vast.ai / 矩池云 / AutoDL | 弹性、按需、H100 起步 | 跨境合规 / 隐私 / 持续成本 |
| **本地 Mac/Linux** | 用户自己的 M-series Mac / Linux 工作站 | 已有工具链 / IDE / git 凭据 | 必须开机 |
| **托管 MicroVM** | Daytona / E2B | 90ms 冷启动，sandbox 隔离强 | 长期任务成本高 |

### 3.2 我们的"算力舱"标准接口

定义一个 **`ComputePod` 接口**（参考 OpenHands Runtime / Daytona SDK）：

```go
type ComputePod interface {
    // 生命周期
    Health(ctx context.Context) error
    Capabilities(ctx context.Context) (*PodCapabilities, error)
    Shutdown(ctx context.Context, graceful bool) error

    // 工作空间
    Workspace(ctx context.Context, req WorkspaceRequest) (*Workspace, error)
    // git clone / pull / checkout, worktree per build

    // 执行
    RunCommand(ctx context.Context, ws WorkspaceID, cmd CommandSpec) (<-chan OutputChunk, func() error, error)
    StreamPTY(ctx context.Context, ws WorkspaceID, cols, rows int) (PTYSession, error)

    // Agent runtime
    SpawnAgent(ctx context.Context, ws WorkspaceID, spec AgentSpec) (AgentHandle, error)
    KillAgent(ctx context.Context, h AgentHandle) error
    StreamAgentEvents(ctx context.Context, h AgentHandle) (<-chan AgentEvent, error)

    // 文件
    ReadFile(ctx context.Context, ws WorkspaceID, path string) ([]byte, error)
    WriteFile(ctx context.Context, ws WorkspaceID, path string, data []byte) error
    Diff(ctx context.Context, ws WorkspaceID, base, head string) (*Diff, error)

    // 凭据 / Secrets（不算在 Pod 层）
}

type PodCapabilities struct {
    CPU, Memory, GPU     int64
    GPUModel             string  // "H100" / "RTX 4090" / "Apple M3 Max"
    Tools                []string // "git", "node", "docker", "python", "cuda"
    AgentRuntimes        []string // "pi-agent", "claude-code", "codex", "aider"
    ConcurrentBuilds     int
    PersistentStorageGB  int
}
```

### 3.3 Executor Bridge 协议

Pocket 后端与算力舱之间走 **`wss://` 长连 + JSON-RPC 2.0**（与现有 `ACP` 协议同源）。

```
[ Pocket Backend ] <──── wss://executor.pod.local:9443 ────> [ pocketd-executor ]
                                  │
                                  ├─ keepalive ping (30s)
                                  ├─ workspace.create / workspace.pull
                                  ├─ agent.spawn / agent.kill
                                  ├─ command.run (PTY stream)
                                  ├─ file.read / file.write / file.diff
                                  └─ agent.event (SSE over WS)
```

- **mTLS**：Pod 自签证书，由 PocketFleet CA 签发；证书含 Pod ID + 团队 ID。
- **JWT**：每次 RPC 调用携带 user JWT（短 TTL，刷新）。
- **审计**：所有 RPC 走 kxmemory 的 audit 流。

### 3.4 算力舱运行时：`pocketd-executor`

一个轻量 Go 二进制（复用 `pocketd` 后端的 `internal/agent` 包 + Cobra CLI），

```bash
# 在算力舱上启动
pocketd-executor enroll --server https://pocket.example.com --api-key xxx --team-id yyy
pocketd-executor start --foreground
```

启动后：

1. 与 Pocket 后端建立 WSS 长连。
2. 定期上报 `capabilities`、`health`、磁盘/内存。
3. 收到任务后：
   - `workspace.create` → git clone（或挂载 NFS）；
   - `agent.spawn` → 启动 Pi Coding Agent 子进程（stdio RPC）；
   - 把 Pi 的输出流转发回后端 → WebSocket Hub → 手机。

### 3.5 国内合规路径

- 默认 Pod 在用户自有网络内（VPC / 内网穿透 / Tailscale）。
- 公网 Pod 走自营节点（中国大陆：阿里云 PAI / 腾讯云 HAII / 火山引擎）；跨境需要明示告知并提供 audit 日志。
- 海外 GPU（H100/B200）若用户主动选择 Modal / RunPod，按合规说明披露。

## 5. 兼容性矩阵

| 算力舱形态 | Pi Agent | Claude Code | Codex | Aider |
|---|---|---|---|---|
| Mac M-series | ✅ | ✅ | ✅ | ✅ |
| Linux x86_64 | ✅ | ✅ | ✅ | ✅ |

我们**第一阶段只承诺 Mac / Linux x86_64 + 云 GPU**；ARM 边缘盒作为远期路线。
