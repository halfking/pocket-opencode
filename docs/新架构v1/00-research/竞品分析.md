# 竞品分析：移动端远程多 Agent 编排

调研日期：2026-08-23
方法：通过 todos.dev 及类似产品的官方网站、文档站、GitHub 公开资料汇总。

---

## 1. todos.dev —— PWA 协调 + 本地执行 + 多 Agent 编排

### 1.1 产品定位

- **标语**："a minimal agent workspace — making collaboration between humans and agents more efficient, easier, and more delightful."
- **形态**：Web 应用，**PWA 可装到手机桌面**，不进 App Store。
- **目标用户**：solo builders 和小团队，"in-house alternative to cloud coding agents"。
- **计费**：免费档 5 agents / 1 machine / 2 parallel builds / 0 credits；Pro $19/月 15 agents / 4 machines / 10 parallel / 35k credits。无 per-seat 费。

### 1.2 核心概念

| 概念 | 含义 |
|---|---|
| **Chief** | 站着说话不干活的"领队" Agent，做判断、分解、路由；它本身**永远不直接写代码**，每个改动走独立 build。 |
| **Charter** | 用户写的、Chief 每轮都读的"长期指令"：优先级、风格、产出规范。 |
| **Agent** | 团队成员。有名字、模型、能力描述。 |
| **Machine** | 真正干活的执行机。用户机器装 `tds start` 注册；或用 Platform Machine（Pro 才有）。 |
| **Todo** | 单个目标，被 Chief 拆出来。 |
| **Build** | 一次完整的执行：plan → build → optional reviewer。 |
| **Role / Slot** | 预设角色（Backend engineer、QA、Architect…）可按需组队。 |
| **Two-stage / Layered** | plan 与 build 用不同模型；可选独立 review（Architect/QA）。 |
| **Skills** | `SKILL.md` 形式的能力包，可团队共享或钉在 Agent 上。 |
| **Memory** | 每个 Agent 跨 round 持久化的记忆。 |
| **Schedules** | 自然语言周期调度（"every morning at eight"）。 |
| **Remote Shell** | 让被授权 Agent 直接对用户机器的 shell 发起命令（需要机器级 + Agent 级双开关）。 |
| **Platform Machine** | Todos 自己跑的、按需冷启动的远程执行机（Pro 才用）。 |

### 1.3 架构（推断 + 官方描述混合）

```
                ┌───────────────┐
                │   PWA / Web   │ ◀──── 手机 / 桌面浏览器
                │   Cloud Coord │       （同一份工作区）
                └───────┬───────┘
                        │ 长期 HTTPS 连接 / WebSocket / Push
                        ▼
                ┌───────────────┐
                │   Coordinator │  （托管：todo / chat / plan / diff / PR 状态）
                │   Service     │
                └───┬───────┬───┘
                    │       │
        dispatches  │       │  pull work
                    ▼       ▼
        ┌─────────────┐  ┌─────────────────┐
        │  tds CLI    │  │ Platform Machine│
        │ (executor)  │  │ (cloud runner)  │
        │ 用户机器上  │  │ Pro only        │
        │ Node ≥22.19 │  │ 按需冷启动      │
        └─────────────┘  └─────────────────┘
                │                  │
                ▼                  ▼
        ┌─────────────────────────────────┐
        │   Git worktree per build        │
        │   每个 todo 一个独立分支         │
        │   可推 PR / 评审 / 合并         │
        └─────────────────────────────────┘
```

**关键设计取舍**：

- 调度 / 工作区 / 评审全部在云端浏览器；执行要么在用户机器（`tds start` 后台守护进程），要么在 Platform Machine。
- **API key 留在用户机器**（"API keys stay on your machines"），不在云端代理 → 用户的 key 不被转售。
- 鉴权：CLI 注册时通过浏览器登录或 `--api-key --team` 注入；本机存 `~/.tds/machine.json`（mode 600）+ `~/.tds/device.json`（硬件指纹，便于重注册复用 ID）。
- "健康": 10 分钟无心跳视为离线；Platform Machine 是「sleep 而非 down」。
- **Remote Shell**：Agent 拿到的不是 terminal UI，而是工具描述里的一个 `remote_shell` tool；shell 持久（cwd/env/bg process 都在），约 1 秒静默或超时返回。

### 1.4 任务分发流程

1. 用户给一句话 → Chief 把目标锐化（goal / boundaries / DoD），问缺什么。
2. Chief 派发到空闲 Machine（pin 时强制指定）。
3. 用户可以"你问我答" → Chief 决定要不要提议新 todo，提议需要人确认才跑。
4. Build 完成后进 review 闸门；过了之后 merge 进 develop。
5. Chief 不主动醒来，只在用户 @它或 todo 停在闸门时回报。

### 1.5 启发我们的点

| 启发 | 我们的做法 |
|---|---|
| **Charter + Chief** | 用 `CHARTER.md` 作为工作区级长期记忆，写入 kxmemory 的工作区元数据 |
| **tds CLI 模式** | 我们要做 `pocketd-executor` CLI，部署在算力舱上 |
| **Agent / Machine 解耦** | 我们已经做了 `Registry` + `AgentRef`，天然契合 |
| **并行 build** | Task Scheduler 加并发池；WS Hub 加租户级 fan-out |
| **Skill + Memory 共享** | Skill 落到 kxmemory；Agent 记忆落 llm-gateway 的 embedding cache |
| **Mobile 是"同一份工作区"** | PWA-first；iOS/Android 后做 |

## 2. Cursor iOS —— 最成熟的"云 Agent 移动控制"

### 2.1 形态

- 原生 iPhone/iPad App（iOS 26.0+），Beta 阶段。
- **Android 暂无**。
- 同时存在于 Start / Pro / Pro+ / Ultra / Teams / Enterprise。

### 2.2 能从手机做什么

- 在云机 / 自建池 / "My Machines" 上跑 Cloud Agent。
- 选任意模型、最大上下文。
- **同时跟踪 8 个 live Agent**（Live Activities / Dynamic Island + push）。
- 实时跟进、子 Agent transcript、PR diff、commit、部署、check、merge (squash / auto-merge)。
- slash command / skill / automation。
- **Design Mode**：附照片、触屏或 Apple Pencil 圈画。
- **语音转指令**。
- **每跑可选 MCP server**（例如 Slack MCP）。

### 2.3 留在桌面/web 的

> 编辑器、终端、文件浏览、Secrets / Cloud Agent 环境、MCP server 管理、源代码控制、自动化规则、Admin/Billing/Usage。

### 2.4 跨设备连续

- 任何一端起的 Agent 进同一台手机的 inbox。
- **Remote Control**（Cursor 3.9.8+）：把一个本地会话的"循环"挪到 Cursor 云上跑，**工具调用（terminal、file edit、test、git）仍在你机器上**。要求 Pro+、Git workspace、本机不睡。
- 仓库、secrets、凭据仍在本地；**只有工具结果 + 模型上下文过云**。

### 2.5 启发

| 启发 | 我们的做法 |
|---|---|
| **Live Activities** | iOS PWA 用 Web Push + Capacitor 通知插件；Android 用 FCM |
| **PR/Check/Merge 移动化** | 复用 OpenCode 已有 SessionList/SessionDetail，但加 PR Diff viewer |
| **Design Mode + 语音** | 接入相机 + MediaRecorder；ASR 用现有 `stt` 模块 |
| **My Machines** | 我们已有 Instance Catalog，需要补 Mobile UI（InstanceListView 已存在，要扩） |
| **Remote Control 模式** | 第二期做，先做"指挥本地 Agent"再迁移 |

## 3. Factory.ai Droid —— 跨表面一致的 Agent

### 3.1 形态

- Factory App（桌面）/ Droid CLI / Web & Mobile / Headless。
- **Session 跨表面同步**：同一 session 在任何浏览器都能继续（app.factory.ai）。

### 3.2 Harness 层

通过 `AGENTS.md` + Connectors + MCP + **Subagents** + Skills + 自定义 slash command + Plugins + Hooks 高度定制。

### 3.3 卖点

- **Cloud Computers** —— Droid Computers 是云端执行环境。
- **Missions** —— 长跑自主工作流。
- **Software Factory** —— 端到端 SDLC 自动化（triage、code review、QA、文档、incident）。
- **企业** —— 自管部署、SSO、可观测、fleet governance。

### 3.4 启发

- **Session 跨表面同步**：我们的 WebSocket Hub 已经做了 UserID/WorkspaceID 定向广播，session 同步零成本。
- **Harness / Agent 的解耦**：和我们的 Adapter 设计一致。
- **Subagent 概念**：直接对应我们的「Chief → Builder → Reviewer」分层。

## 4. Devin.ai（Cognition） —— Session-centric

- 每条 session 有 progress steps；用户随时从本地 CLI `/handoff` 把活甩给云端 Devin。
- 嵌入式 IDE + Shell + Browser 三件工具。
- 没有原生 mobile，但 session 状态可由 API 拉取。

**启发**：我们的 WebSocket 订阅 + Activity 推送已经覆盖"session live 跟踪"，移动端可以直接呈现。

---

## 5. OpenHands（前身 OpenDevin） —— 开源多 Agent 标杆

- 完全开源（MIT 协议历史版本，部分组件协议有变）。
- 提供 **GUI / CLI / SDK / Enterprise control plane**。
- 多 Agent（Planner / Executor / Reviewer）模式。

**启发**：参考它的 Runtime / Sandbox 抽象；它用 Docker 做 sandbox，我们用"算力舱 = sandbox"。

---

## 6. Block Goose —— 开源 LLM-agnostic Agent

- 开源、本地优先。
- 内置多 Provider。
- **跨 LLM**：Claude / GPT / 本地 Ollama / DeepSeek 都接。

**启发**：和我们的 **Model Registry** 思路一致。Goose 不做 mobile 是它的弱点——我们做。

---

## 7. E2B —— Firecracker Sandbox 服务

- OSS，云端代码执行 sandbox。
- < 200ms 启动。
- SDK 简单：JS / Python。
- "thousands of concurrent sessions"。

**启发**：算力舱如果不够用时，可以 E2B 兜底做 ephemeral sandbox。

---

## 8. Daytona —— AI Agent 专用 Runtime

- 90ms 启动的 sandbox。
- 提供 **LSP、PTY、Git、Code Execution、MCP server integration** 工具集。
- 商业平台 + API。

**启发**：作为"标准算力舱接口"的参考；未来如果用户选 Daytona，我们可零改造接入。

---

## 9. Modal —— Serverless AI Infra

- Python 代码 → 云端运行。
- Sub-10ms 延迟，sub-second 冷启动。
- 0→1000+ GPU 自动扩缩。

**启发**：作为"无 idle 成本"算力舱兜底选项。

## 11. 我们的差异化定位

- **国内合规**：托管算力舱（公有云 GPU）只在中国大陆节点可选；on-prem 优先。
- **多 Agent 编排 + 中国 LLM 一等公民**：DeepSeek / Qwen / Doubao / GLM 原生支持。
- **现有 opencode-pocket 用户 100% 兼容**：所有原有 session / instance / email / notes 资产不动。
- **PWA + 双端原生**：和 Cursor Mobile 正面竞争；和 todos.dev 比，我们多一个"完整 IDE 级 session 控制"；和 Devin 比，我们是 open & self-hostable。
