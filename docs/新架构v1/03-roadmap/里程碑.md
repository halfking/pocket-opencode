> 状态：**规划中，尚未实现**

## 先做架构决策：RedClaw 不是 OpenCode drop-in backend

默认路线是：

```text
OpenPocket → pocketd → ZAgentGateway → RedClaw control plane
                                           ├─ OpenClaw runtime（可选执行器）
                                           └─ OpenCode runtime（默认保留的 coding runtime）
```

- RedClaw 负责企业任务、租户、策略、审批、审计和 LLM/控制面；
- OpenCode 负责 session、message parts、tool loop、PTY、ACP、`/event` SSE；
- ZAG 做 task/run/session 映射和安全适配；
- 只有完成兼容性验证后，才考虑 RedClaw OpenCode-compatible facade。

## 证据等级

| 等级 | 含义 |
|---|---|
| `implemented` | 当前仓库或指定依赖仓库有源码实现，并有对应测试/装配证据 |
| `contract-tested` | mock/contract 测试通过，但真实运行时未验证 |
| `source-inspected` | 已阅读源码/协议，未证明当前部署可用 |
| `mock-only` | 仅 mock 或 echo 测试通过 |
| `planned` | 目标设计，尚未实现 |
| `blocked` | 依赖缺失或协议未确认 |

## M0 — 事实基线、合同与安全门禁（Week 1-4）

**目标**：不开放远程写操作，先证明协议、身份和安全边界。

### 交付项

- `planned` 固定一个 OpenCode 版本/commit，建立唯一 OpenCode contract：
  - `/session`、`/session/:id/message`、`/event`；
  - `/permission`、`/question`、`/pty`；
  - parts、EventV2、Basic Auth、版本兼容矩阵。
- `planned` 建立 RedClaw façade/task/run 与 OpenCode session 的差异矩阵；
- `planned` ZAG 只读骨架：health、Pod/Agent/Session inventory；
- `planned` service JWT/delegated token：`iss/aud/sub/tenant_id/actor/scope/jti/exp`；
- `planned` 最小 RBAC/ABAC 和对象级 tenant binding；
- `planned` mTLS enrollment、rotation、revoke；禁止自动信任未知 CA；
- `planned` operation_id/idempotency_key/event_id/aggregate_version；
- `planned` durable audit outbox、审批状态和事件 cursor；
- `contract-tested` mock RedClaw、mock ACC、mock OpenCode 的健康与只读合同；
- `planned` OpenPocket 只展示“规划中/未连接”状态，不提供 shell、IDE 写、git push、Pod terminate 或写 MCP tool。

### 不做

- 不把 RedClaw `/api/v1/tasks` 冒充 OpenCode `/session`；
- 不实现 mTLS→HMAC 降级；
- 不把通用 RedClaw connector 标记为 IDE connector；
- 不开放 `allow_always`；
- 不将 query JWT 用于新 WebSocket/SSE 集成。

### M0 发布门禁

- 跨租户访问测试必须 403；
- token claims/header/body 不一致必须拒绝；
- 未授权 task/pod/session/IDE 订阅必须拒绝；
- 审计不可写时高危操作必须拒绝；
- 重放 nonce、重复 idempotency key、过期 token 必须拒绝；
- OpenCode 真实 server 至少完成只读 health/session/message contract 验证。

## M1 — 控制面集成，保留 OpenCode runtime（Week 5-9）

**目标**：通过 ZAG 管理 RedClaw/ACC，同时让 OpenCode 继续负责 coding runtime。

### 交付项

- `planned` 映射：`acc_task → zag_operation → redclaw_task/run → opencode_session`；
- `planned` RedClaw task/run 事件与 OpenCode `/event` 的双向事件投影；
- `planned` RedClaw approval gate ↔ OpenCode permission/question 映射；
- `planned` Pocket 移动审批，审批绑定具体 command/diff/hash；
- `planned` durable reconciliation：超时先 query，再 retry，未知状态进入 `indeterminate`；
- `planned` SSE/WS：header/ticket auth、Origin、subscribe ACL、Last-Event-ID、去重和背压；
- `planned` OpenPocket Live View、只读 Pod/Agent/Session 列表；
- `planned` Charter/Skill 使用 Memora，但不把 Memora 当唯一审计存储；
- `planned` RedClaw LLM gateway 仅作为已验证 Provider 接口，echo stub 不得作为成功证据；
- `planned` 基础成本读取和租户数据驻留策略。

### 受限写能力

仅允许低风险、可撤销、已 schema 化的操作；必须通过最小 RBAC、command registry、workspace boundary 和审计 outbox。shell、git push、任意 IDE command、控制信号仍关闭。

### M1 验收

- 真实 OpenCode 固定版本完成 session/message/event/permission/question 联调；
- RedClaw mock 和真实 API 的差异有测试覆盖；
- 一次任务在 ACC、ZAG、RedClaw、OpenCode 四层状态可追踪；
- 断线重连不会重复执行或跨租户推送事件；
- 故障注入（ACC/ZAG/RedClaw/Memora/LLM）达到预期 fail-closed/fallback 结果。

## M2 — 高危控制与首个 IDE adapter（Week 10-13）

**目标**：在安全门禁通过后，先支持 ZCode/OpenCode 的受控控制。

### 交付项

- `planned` command registry、argv 执行、路径 canonicalization、symlink/TOCTOU 防护；
- `planned` Pod workspace sandbox、环境变量 allowlist、网络/资源/输出限制；
- `planned` ZCode adapter；OpenCode adapter 必须基于固定 OpenCode HTTP/ACP contract；
- `planned` `ide.open_file`、`ide.apply_diff` 受控命令；
- `planned` git push/shell 通过 human gate；
- `planned` 独立审批服务/设备的双签，ZAG 不持有第二个 admin 私钥；
- `planned` connector endpoint allowlist 和 SSRF 防护；
- `planned` 供应链签名、digest、SBOM、provenance 和升级回滚策略。

### M2 门禁

- 任意路径逃逸、命令注入、SSRF、环境变量泄漏和审批参数篡改测试通过；
- 高危审计不可写时拒绝执行；
- 双签 signer independence、canonical payload、nonce 和一次性消费测试通过；
- OpenCode runtime 仍可独立运行，ZAG 故障不得破坏已有 OpenCode session。

## M3 — 多 IDE 与可选 OpenCode-compatible facade（Week 14-18）

**目标**：扩展 IDE，只有明确需求时才实现完整兼容 facade。

### 交付项

- `planned` VS Code adapter；
- `planned` Cursor adapter；
- `planned` OpenClaw adapter；
- `planned` Agent Memory 注入和 Skill 导入（来源签名校验）；
- `planned` Reviewer/QA 只在策略允许时启用；
- `optional` RedClaw OpenCode-compatible facade：
  - `/session`；
  - `/session/:id/message`、parts；
  - `/event` EventV2/SSE；
  - `/permission`、`/question`；
  - `/pty`/WebSocket；
  - Basic Auth 或受控 auth bridge；
  - snapshot/diff/revert/compact/ACP 兼容。

### 重要限制

OpenCode-compatible facade 是独立兼容项目，不得把 RedClaw task/session 粗粒度 API 直接映射成“兼容”。在所有必需 API 和真实 OpenCode client contract 测试通过前，标记为 `blocked`/`planned`。

## 依赖与降级

```text
pocketd → ZAG → RedClaw control plane → OpenCode/OpenClaw runtime
   ├─ ACC：编排，可选但不得绕过安全边界
   ├─ Memora：记忆/检索，不是唯一审计存储
   └─ llm-gateway-go：Provider 路由，fallback 受数据驻留策略约束
```

降级规则：

| 故障 | 允许行为 |
|---|---|
| ACC 不可用 | 只读状态或进入队列；不得绕过授权直接执行高危任务 |
| ZAG 不可用 | OpenPocket 显示不可用；已有 OpenCode session 可继续本地运行 |
| RedClaw 不可用 | 控制面任务暂停；不得直接执行未经授权的 CLI 命令 |
| Memora 不可用 | 使用有界本地缓存；审计仍写 durable outbox；高危操作不自动继续 |
| LLM gateway 不可用 | 按租户驻留策略选择已批准 Provider；否则失败 |
| OpenCode runtime 不可用 | 任务进入 `blocked/indeterminate`，不得改投另一 runtime 造成双执行 |

## 交付状态格式

每个里程碑在实施时必须维护：

| 项目 | 状态 | 证据 |
|---|---|---|
| ZAG API | `planned` | 实现路径 + commit + contract test |
| RedClaw integration | `source-inspected`/`contract-tested`/`implemented` | 外部仓库 commit + 测试日志 |
| OpenCode compatibility | `source-inspected`/`contract-tested`/`implemented` | 固定版本 + 真机/真实 server 测试 |
| IDE adapter | `planned`/`implemented` | connector 实现 + adapter test |
| Security gate | `planned`/`implemented` | 安全测试报告 |

禁止用 `✅` 表示尚未有证据的设计目标。
