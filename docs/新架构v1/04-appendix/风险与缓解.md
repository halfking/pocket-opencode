# 风险与缓解 v3

> 风险评估日期：2026-08-23
> 文档状态：v3 设计阶段
> **核心变化**：v3 引入 ZAgentGateway 作为新增依赖；其他服务的风险大部分与 v2 类似。

---

## 1. 技术风险

### 1.1 ZAG 是新服务，可能引入 bug

| 项 | 内容 |
|---|---|
| 风险 | ZAG 是 v3 全新引入的 Go 服务；自身可能有 bug；事件桥接、状态聚合、Ed25519 签名等逻辑复杂 |
| 影响 | ZAG 不可用时 OpenPocket 失去 PC Agent 控制能力 |
| 概率 | 中 |
| 缓解 | ① M0 严格集成测试；② ZAG 自身完整的 unit + integration；③ 关键路径 mock 测试；④ ZAG 启动健康检查 + graceful shutdown；⑤ pocketd fallback（acc-go 不可用时跳过 ZAG 直接走另一条路径） |
| Owner | BE Tech Lead |

### 1.2 ZAG ↔ RedClaw mTLS 配置复杂

| 项 | 内容 |
|---|---|
| 风险 | mTLS 需要双方证书 + CA 信任；RedClaw 已有 4-5 个微服务，每个都要配证书 |
| 影响 | ZAG 与 RedClaw 通信失败 |
| 概率 | 中 |
| 缓解 | ① 使用受管 CA、一次性 enrollment、证书绑定、轮换和撤销；② 禁止自动信任未知 CA；③ mTLS 失败必须 fail-closed；④ 通过合同测试验证 |
| Owner | BE + DevOps |

### 1.3 Ed25519 双签 Rollback / Upgrade / Terminate 流程复杂

| 项 | 内容 |
|---|---|
| 风险 | 双签需要两个 admin 独立签名；UI 流程复杂；签名丢失 / 错误 / 重放都需要防护 |
| 影响 | Rollback / Upgrade / Terminate 不能执行 |
| 概率 | 中 |
| 缓解 | ① M3 实现；② ZAG 内置 admin UI（第二个签名入口）；③ 飞书 / 邮件一键审批；④ Replay 防护（nonce + 5min TTL） |
| Owner | BE |

### 1.4 acc-go 是核心依赖（沿用 v2）

| 项 | 内容 |
|---|---|
| 风险 | acc-go 故障 = 整个 PocketFleet 故障（除 fallback 外） |
| 影响 | PocketFleet 退化为简单对话模式 |
| 概率 | 中 |
| 缓解 | ① 只读/入队降级；② 不得绕过 ZAG、RedClaw、审批或审计执行高危操作；③ 监控 acc-go 健康度 |
| Owner | BE |

### 1.5 RedClaw Gateway (`:8092`) 仍是 echo stub

| 项 | 内容 |
|---|---|
| 风险 | RedClaw Gateway 服务端改造在外部仓库 `FreshLab/RedClaw2`；不可控 |
| 影响 | 如果业务上想走 RedClaw Gateway LLM 路径，会卡 |
| 概率 | 高 |
| 缓解 | ① ZAG 检测 echo response → 自动 fallback 到 llm-gateway-go；② 不阻塞 M0-M5；③ Push 给 RedClaw Gateway 团队修复 |
| Owner | Tech Lead |

### 1.6 RedClaw platform-go 是企业级（multi-tenant / Ed25519 / Plan A/E）

| 项 | 内容 |
|---|---|
| 风险 | 集成复杂度高；版本兼容 / 接口稳定 / 配置项多 |
| 影响 | ZAG ↔ RedClaw 集成 bug |
| 概率 | 中 |
| 缓解 | ① ZAG 内置完整 RedClaw client（含 mTLS / Ed25519 工具）；② 集成测试覆盖主要场景；③ 参考 RedClaw platform-go 自带测试模式 |
| Owner | BE |

### 1.7 OpenClaw CLI 上游不稳定

| 项 | 内容 |
|---|---|
| 风险 | OpenClaw npm 包仍在 0.x / 1.x 早期；breaking changes 频繁 |
| 影响 | OpenClaw 跑任务失败 |
| 概率 | 中 |
| 缓解 | ① RedClaw agentcontainer 抽象隔离 OpenClaw；② pin OpenClaw 版本（`openclaw@1.2.x`）；③ 自动 fallback 到其他 harness |
| Owner | RedClaw 团队 + ZAG 团队 |

### 1.8 IDE 插件适配复杂

| 项 | 内容 |
|---|---|
| 风险 | ZCode / VS Code / Cursor / OpenCode 各自有不同的协议；适配工作量大 |
| 影响 | IDE 控制功能不可用 |
| 概率 | 中 |
| 缓解 | ① RedClaw Connectors 抽象统一；② M3 渐进适配（先 ZCode，再 OpenCode，再 Cursor，最后 VS Code）；③ 单个 IDE 不可用不影响整体 |
| Owner | BE + 各 IDE 插件开发 |

## 2. 产品 / UX 风险

### 2.1 ZAG 引入后调试难度增加

| 项 | 内容 |
|---|---|
| 风险 | 任务路径变长（mobile → pocketd → acc-go → ZAG → RedClaw → OpenClaw → IDE）；调试时定位问题困难 |
| 影响 | 用户遇到问题时排查慢 |
| 概率 | 高 |
| 缓解 | ① OpenTelemetry 跨服务 trace；② 每个环节打 structured log（含 trace_id）；③ ZAG 提供 `/api/v1/diag` endpoint 显示完整任务路径；④ self-debug dashboard |
| Owner | BE |

### 2.2 acc-go Chief 拆分质量不稳定（沿用 v2）

| 项 | 内容 |
|---|---|
| 风险 | acc-go taskdecompose.ai_decompose 偶发"幻觉" |
| 影响 | 用户信任崩塌 |
| 概率 | 高（早期） |
| 缓解 | ① UI 上 **必须用户 approve 才执行**；② 显示每个 subtask 的 goal / boundaries / DoD；③ pocketd fallback 跳过 Chief；④ 收集 feedback 训练 Charter |
| Owner | PM |

### 2.3 移动端 Live 流过载（沿用 v2）

| 项 | 内容 |
|---|---|
| 风险 | 多 Agent / 多 IDE / 多任务事件并发，UI 卡顿 |
| 影响 | 用户体验差 |
| 概率 | 中 |
| 缓解 | ① ZAG SSE 按重要性分级；② 客户端按时间窗口聚合；③ "暂停 stream"按钮；④ 历史事件分页 |
| Owner | FE |

### 2.4 离线审批体验断裂（沿用 v2）

| 项 | 内容 |
|---|---|
| 风险 | 用户手机离线，build 跑着产生 permission request |
| 影响 | build 卡住 |
| 概率 | 中 |
| 缓解 | ① ZAG taskgate 支持 auto-mode；② mobile 回来后看到"被自动决策 N 个权限"；③ web fallback（同账户）；④ 多通道 push |
| Owner | BE + Mobile |

### 2.5 多 IDE 协同体验差

| 项 | 内容 |
|---|---|
| 风险 | 用户预期 OpenClaw + IDE 协同流畅；但实际可能 IDE 响应慢 / 协议不兼容 |
| 影响 | 用户体验差 |
| 概率 | 中 |
| 缓解 | ① M1 只支持 ZCode（项目自有）；② M3 渐进添加；③ 提供 IDE 状态面板；④ 出错时降级提示 |
| Owner | FE + BE |

## 3. 商业风险

## 4. 合规风险

### 4.1 跨境数据流（沿用 v2）

| 项 | 内容 |
|---|---|
| 风险 | Pod 在境外、LLM 在境外、用户在中国 → 数据出境 |
| 影响 | 个保法违规 |
| 概率 | 高 |
| 缓解 | ① 默认 Pod 必须在中国境内；② LLM 默认境内（DeepSeek / Qwen）；③ 接入境外 LLM 时弹窗告知 |
| Owner | Legal + BE |

### 4.2 IDE 命令的 Side Effect

| 项 | 内容 |
|---|---|
| 风险 | IDE 命令（git push / 删除文件）有 side effect；可能误操作 |
| 影响 | 用户数据丢失 |
| 概率 | 中 |
| 缓解 | ① SideEffect Level 区分；② Plan A / Plan E 审批；③ 操作前显示 diff 预览；④ 撤销机制（git revert） |
| Owner | BE + Legal |

### 4.3 ZAG 收集 PC 元数据

| 项 | 内容 |
|---|---|
| 风险 | ZAG 知道用户 PC 的 CPU / 内存 / GPU / IDE / OpenClaw 状态；可能被视为敏感数据 |
| 影响 | 用户隐私顾虑 |
| 概率 | 低 |
| 缓解 | ① EULA 明确告知；② onboarding 时勾选；③ 提供"关闭 telemetry" 选项 |
| Owner | Legal + PM |

## 6. v3 特有的"集成复杂度"风险

| 风险 | 缓解 |
|---|---|
| **ZAG 是新依赖** | M0 严格集成测试；ZAG 自身完整测试覆盖；fallback 设计 |
| **多服务租户贯通**（pocketd → acc-go → ZAG → RedClaw）| fleetbridge / zag client 强制注入 X-Tenant-ID + X-User-ID；端到端 E2E |
| **多服务接口契约漂移** | fleetbridge 隔离上游变化；schema 验证；灰度发布 |
| **RedClaw 企业平台污染** | ZAG 做边界；OpenPocket / acc-go 不直接连 RedClaw |
| **IDE 协议碎片化** | RedClaw Connectors 抽象统一；渐进适配 |
| **ZAG 是单点** | ZAG 多副本；健康检查；fallback |
| **OpenClaw CLI breaking change** | RedClaw agentcontainer 抽象隔离；pin 版本 |

## 7. 缓解优先级矩阵

```
高概率 + 高影响  →  立即处理
  - ZAG 是新依赖
  - ZAG ↔ RedClaw mTLS 配置
  - 跨服务调试难度
  - 自有 Pod 部署门槛
  - 跨服务支持复杂

高概率 + 低影响  →  设计阶段规避
  - 多 IDE 协同体验差
  - 离线审批体验

低概率 + 高影响  →  应急预案
  - acc-go breaking change
  - OpenClaw CLI breaking change
  - ZAG 收集 PC 元数据隐私顾虑

低概率 + 低影响  →  关注即可
```

## 9. 应急手册（Runbook）摘要

| 场景 | 操作 |
|---|---|
| ZAG 大面积故障 | 1) pocketd 跳过 ZAG → fallback 直接调 RedClaw Gateway；2) 通知用户；3) 紧急修复 |
| RedClaw platform-go 故障 | 1) ZAG 任务暂时不可用；2) OpenPocket 显示降级；3) 紧急修复 |
| RedClaw Gateway (LLM) 故障 | 1) ZAG 自动 fallback 到 llm-gateway-go；2) 通知 RedClaw 团队 |
| acc-go 故障 | 1) 进入 queue-only/只读降级；2) 不跳过授权/审计执行高危任务；3) 修复 ACC 后 reconciliation |
| Memora 慢 / 挂 | 1) Charter / Skill 走 pocketd 本地缓存；2) Cost 不持久化；3) ZAG 内存缓存 |
| Ed25519 第二个签名丢失 | 1) ZAG admin UI 重新发起；2) 飞书 / 邮件一键审批 |
| OpenClaw CLI crash | 1) RedClaw agentcontainer 自动重启；2) 事件回流到 OpenPocket |
| IDE 插件 crash | 1) RedClaw Connector 自动 reconnect；2) OpenPocket 显示降级 |
| pocketd → fallback 触发率高 | 1) 排查 acc-go 故障；2) 同时检查 ZAG；3) 通知相关团队 |

## 10. 与 v1/v2 风险对比

| 类别 | v1 | v2 | v3 |
|---|---|---|---|
| 自建组件稳定性 | 多 | 0 | 0（ZAG 不算自建重复组件；它是新独立服务） |
| 第三方服务依赖 | 部分 | 主要 | **主要 + ZAG 自建** |
| 跨服务集成复杂度 | 低 | 高 | **更高**（4 个服务协同） |
| 自有 Pod 部署门槛 | 高 | 中 | **中**（沿用 RedClaw + ZAG） |
| LLM cost 失控 | 中 | 中 | 中（沿用 v2） |
| **多 IDE 适配** | ❌ | ❌ | **新风险**（IDE 协议碎片化） |
| **企业平台集成** | ❌ | ❌ | **新风险**（RedClaw Plan E / Ed25519） |

## 11. 关键监控仪表盘

1. **ZAG 自身健康度**：调用 RedClaw / acc-go / Memora / llm-gateway-go 的 RPS / 延迟 / 错误率；
2. **pocketd → ZAG fallback 触发率**：何时跳过 ZAG；
3. **RedClaw Gateway echo 率**：echo stub 何时被修复；
4. **整链路追踪 P99**：mobile → pocketd → acc-go → ZAG → RedClaw → OpenClaw CLI；
5. **IDE 插件状态**：每个 IDE 用户的在线率；
6. **OpenClaw runtime 状态**：每个用户的 OpenClaw 版本 / 心跳；
7. **Cost 实时仪表盘**：每 Fleet 当日 / 当周 / 当月 cost。
