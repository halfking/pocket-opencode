# RSS 订阅 & 分享 — 需求说明

**日期**: 2026-09-08
**状态**: 当前 MVP 已落地
**后端**: `backend/internal/rss/`、`backend/internal/server/server_rss.go`
**前端**: `frontend/src/features/rss/`、`frontend/src/api/rss.ts`

> 实施切片与运维细节见 [`2026-09-08-rss-design.md`](./2026-09-08-rss-design.md)。

## 1. 用户场景

> "我平时看 Hacker News、阮一峰博客、36 氪。现在我得打开三个网站，记不住哪些看过了。能不能把它们统一加到一个订阅流，过滤掉不感兴趣的，然后一键把今天的好文分享到微博或朋友圈？"

满足这条故事，需要四件事：

1. **添加订阅源** — 用户给一个网站 URL，自动找出 RSS/Atom feed；或者从内置种子一键添加。
2. **自动拉取 + 过滤** — 后台定期拉取，按关键字 / 语言 / 时间窗口过滤。
3. **查看详情** — 在 App 内打开 item 详情页。
4. **一键分享** — 选目的地（微信朋友圈 / 微博 / 剪贴板 / 下载），生成带二维码的分享卡。

## 2. 功能切片

### 2.1 必须（MVP）

| # | 能力 | 入口 | 行为 |
|---|---|---|---|
|1| 列出当前用户的所有 RSS 源 | `/rss` → "源" tab | 卡片展示源标题、URL、未读数、最近拉取时间、状态；支持启用/停用切换、单源立即拉取、删除 |
|2| 添加源 | `/rss/add` | 粘贴 URL → `discover` 返回候选 → 确认；或从内置种子（HN/36 氪/阮一峰/少数派/Smashing Magazine）一键添加 |
|3| 信息流 | `/rss` → "信息流" tab | 按未读/已读/收藏/归档筛选 + 关键字搜索；点击进详情 |
|4| 详情 | `/rss/items/:id` | 标题/作者/发布时间/原文链接；摘要 + 完整正文（HTML 渲染）；底部 sticky 操作栏：收藏 / 一键分享 |
|5| 自动拉取 | 后台 scheduler | 默认每 1 分钟扫描一次到期源；并发上限由 `POCKET_RSS_MAX_CONCURRENCY` 控制；ETag / Last-Modified 304 短路 |
|6| 关键字 / 语言 / 时间窗过滤 | `/rss/filters` | 用户维护一组 include/exclude 关键字、白名单语言、时间窗；命中的 item 标 `filtered_out=true`，仍保留原文 |
|7| 一键分享 | 详情页 → 分享 modal | 四个目的地：微信朋友圈、微博、剪贴板、下载卡片图；caption 可编辑；生成 1080×1350 PNG 分享卡（含标题 / 来源 / QR 占位） |

### 2.2 暂不做

- OPML 导入 / 导出（schema 已支持手动迁，UI 未做）
- 全文内容提取 / 智能摘要
- LLM 语义相似度召回（仅关键字匹配）
- 多租户共享源池（当前每用户私有；workspace_id 字段保留以便后续扩展）
- 微博官方 OAuth 发帖；朋友圈官方 API（均无公开 API）

## 3. 角色 / 权限

| 操作 | 需要登录 | 需要 workspace |
|---|---|---|
| 任何 `/api/rss/*` 调用 | ✅ | ✅ |
| 后台 scheduler 拉取（用户 "local" / workspace "default"） | n/a | n/a |

WS hub 仅推送新 item 事件，不存数据；前端订阅后只更新未读 badge。

## 4. 数据归属

每个 source / item 都有 `(user_id, workspace_id)` 元组，从 JWT claims 派生。

> 历史设计是 `(user_id, workspace_id)` 双列做 scope 隔离。本 MVP 沿用现有 schema；多用户/工作区共享可在未来通过引入 source-level ACL 字段 + 视图切换实现，**不需要迁移**。
