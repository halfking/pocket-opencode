# 02 — 布局、导航与账户

> 现行约束 + 部分已接线。

## 1. 壳层结构

```
App.vue
└── AppLayout.vue          共享顶栏 + BottomNav + <main> 滚动宿主
    ├── TopBar             wide：专业顶栏 / compact：返回 + 标题 + 更多
    ├── <main>             **独立滚动容器**（不是 window 滚动）
    └── BottomNav.vue      compact 常渲染、内部自显隐
```

`router-view` 由 `AppLayout` 包裹，共享 TopBar 与 BottomNav 全局生效。

## 2. 底栏（BottomNav）

- 只在 `compact` 档渲染/显示，席位不超过 5。
- 路由 meta 用 `bottomNav: true` 声明该页是否显示底栏。
- 层级：底栏 z-index 必须**低于**抽屉与遮罩。
- 底栏高度通过 `scroll-chrome.ts` 的 provide/inject 契约参与滚动联动
  （`chromeTotalHeight` / `bottomNavHeight` / `bottomInsetHeight`），
  消费方统一读 `--bottom-chrome-hide` CSS 变量做位移。

## 3. 返回：单一来源

改造前返回由多个来源各自裁决，现已收敛为 `BackDispatcher`
（见 [06](./06-Hyper导航上下文.md)）。

四个来源都只发意图：

| 来源 | 现状 |
| --- | --- |
| 左上角返回钮 | ✅ `AppLayout.vue` 的 `goBack()` → `dispatchBack()` |
| Android 硬件返回 | ✅ `CapApp.addListener('backButton')` → `submitSystemBack()` → `dispatchBack()` |
| 键盘 Esc | ✅ 文档级 `keydown` → `dispatchBack()` |
| 内容区左滑手势 | ✅ `<main>` 的 `touchstart/touchend`，12px 死区 + `\|dx\| > 1.3\|dy\|` 方向锁，只识别**左滑** |

> 四个来源都只发意图，不再各自判断弹窗关闭顺序。
> 抽屉开启与 `/login?unlock=1` 两个前置守卫保持在仲裁**之前**（它们优先级更高）。

返回钮的**语义**（`aria-label` / `title`）已由 `back.affordance()` 决定：页面「返回」/
弹窗「关闭」/ 专注「退出专注」。

⚠️ 返回钮的**可见性**仍由 `route.meta.canGoBack` 决定。改用「上下文是否有前驱」
需要逐条核对 40+ 路由，否则部分深链入口会突然不显示返回钮 —— 那是行为回归。
列入 [09](./09-审计与实施路线.md) H1 剩余项。

### 3.1 账号域隔离

`AppLayout` watch `auth.userId` / `auth.workspaceId`，变化时调
`runtime.setScope()`。登出时两值被清空 → scope 变回空串 → 同样触发清理。

> 这条曾经有缺陷：`setScope` 早期只在「非空」时清理，于是**登出**不触发 reset，
> 上一位用户的标题（含姓名）留在内存里等下一个人登录。判据：
> `runtime.test.mjs` 的「登出（scope 变回空）必须清空导航与标题」。

## 4. 账户与更多入口

- 语言 / 主题 / 退出**不堆在顶栏**，统一走账户面板。
- 顶栏右侧页面操作统一用**三点更多**图标；左侧全局导航才用三横线。
  - Android：`more_vert`（Material）
  - iOS：`ellipsis`
  - Web：`MoreFilled`（`@element-plus/icons-vue`）
  - 不得用字形 `⋯` / `☰` 代替。
- 菜单按钮 44×44px 触控框，图标 20–24px，带 `aria-label` / `aria-haspopup` /
  `aria-expanded`；**没有可执行动作时隐藏按钮**。

> 状态：顶栏图标统一尚未实施，属 spec-only。

## 5. 滚动联动

`composables/scroll-chrome.ts` 定义契约，`AppLayout` 持有引擎并 provide：

- `scrollMode: 'shell'` 的页面由 `AppLayout` 绑定 `<main>`
- 自管滚动页面（`PullToRefresh` 内置上报、`AIChatView` 的 `.msg-area`）自己喂增量

不可触发 chrome 唤出的区域（`isChromeToggleTap`）：

- `a, button, input, textarea, select, option, label, [contenteditable], [role=...]`
- 导航 chrome 自身与浮层：`.bottom-nav, .chrome-shell, .more-sheet, .more-panel,
  .refresh-indicator, .composer, .voice-bar, .uc`
