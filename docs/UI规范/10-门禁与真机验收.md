### 1.2b 返回路径判定契约（2026-10-06 新增门禁）

```bash
node scripts/check-back-navigation.mjs --selftest   # 自检 8 条
node scripts/check-back-navigation.mjs              # 判定；违规 exit 1，前置缺失 exit 3
```

接进 `frontend/gates.json` 的 `gates` + `ciRuns`（第 31 项）。

守两件事，**都跑真代码**而不是 grep：

| 面 | 判据 | 变异自测 |
| --- | --- | --- |
| 行为 | 导入真实 `createShellRuntime`，用一只**忠实复刻 vue-router** 的假 router（导航异步 + 落定触发 `afterEach` + 守卫阻止时 `failure` 非空且路径不变）跑 10 条场景 | 换成「旧实现」替身（`setTimeout(0)` 判定 + 一律记 push）→ **8 条转红** |
| 接线 | 四个返回来源（顶栏返回钮 / Android backButton / Esc / 内容区左滑）各自的**执行函数体内**必须有 `dispatchBack(` | 逐个单独打断 → 四条**各自**被报出 |

**为什么接线判据是「执行函数体」而不是「模板附近 ±1200 字符」**：
早先一版用字符窗口，顶栏返回钮的模板绑定 `@click="goBack"` 在文件头部、
实现 `async function goBack()` 在 400 行之后，窗口罩不到 ⇒ **真代码被判违规**
（假阳性），连门禁自检一起红。改成「模板来源 → 执行函数 → 函数体」才落在收口点。

**判据失明怎么办**：四个来源一个都认不出来时 exit 3 并明说「拒绝给结论」，
不输出「✓ 合规」——失明与通过在输出上必须不同形。

**对照组的对照也得是对照**：修复前那只假 router 不触发 `afterEach`，
判据挂在钩子上必然超时 ⇒「对照组也红」。那是**无效对照**，不是产品缺陷。
已改成忠实复刻 vue-router 后对照才成立。

#### ⚠️ 这条门禁第一版是**没有牙**的（记录在此以免重蹈）

第一版量的是 `documentElement.scrollWidth - clientWidth`。变异注入
`#app > * { min-width: 900px }` 后：

- 注入**确实生效**（`app-root` 的 `rectWidth=900`、`right=900`）
- 但某祖先 clip 了横向溢出 ⇒ `documentElement.scrollWidth` 仍是 320 ⇒ **报 0**
- 于是 16 条用例**全部照样绿**

根因：**「页面不能横滚」与「内容没被切」不是同一件事**。一个 900px 宽的
登录表单铺在 320px 屏上是彻底的坏 UI，而 scrollWidth 只会告诉你「没有横向
滚动条」。本仓有祖先 clip，所以这条路**结构性地瞎**。

改成元素级测量：任何 `getBoundingClientRect().right > innerWidth + 1` 且
**不在**声明了 `overflow-x: auto/scroll` 的容器内的元素，都算被切掉。
换后同一变异 → **8 条转红**，失败信息直接点名元素与尺寸：

```
登录页 @ 320px 有内容被视口右沿切掉：div.app-root(right=900,w=900),
div.app-layout(right=900,w=900), main.content.scroll-shell(right=900,w=900),
div.login-view(right=888,w=876)。若某元素写死了 min-width/width，
请改用档位或 .bp-* 工具类，不要新造断点。
```

移除注入后复跑回到 16 全绿 —— 确认红是注入引起的，不是别的东西。

> **可复用的判别动作**：任何「无溢出/无脏数据/无 X」的门禁，先注入一个
> 已知的坏法，**确认它会红**。`scrollWidth` 这类量尤其危险：它量的不是
> 你想量的东西，而且失败时长得像「通过」。

#### 接线位置

`check:e2e-responsive` 已登记进 `gates.json` 的 **`notGates`**，理由写明：
它需要一个**先跑起来**的 vite dev server，而 `gates` 是无服务的前置检查链，

## 2. 变异自测：判据有没有牙

**判据的价值在它能红的时候。** 本轮对关键判据做了变异验证：

### 2.0 变异总表

| 注入的变异 | 期望 | 实测 |
| --- | --- | --- |
| `responsive.css` 560 → 768（还原历史缺陷） | 🔴 | 🔴 「未登记宽度断点：768」 |
| `--bp-wide-min` 1280 → 1440 | 🔴 | 🔴 「与 TS 不一致」 |
| 删掉连续加载 `.then` 的代次守门 | 🔴 | 🟢 **首次全绿 —— 判据无牙** |
| 刷新失败也清空 pages（还原原缺陷） | 🔴 | 🔴 |
| 删掉 `record()` 里的 `touch()`（让 `version` 不再自增） | 🔴 | 🔴 |
| 恢复 `var(--z-fab, 40)` / `var(--z-popover, 30)` / `z-index: 7777` | 🔴 | 🔴 ×3 |
| 引用一个从未定义的 `--z-*` token | 🔴 | 🔴 ×2 |
| 响应式门禁注入 `#app > * { min-width: 900px }` | 🔴 | 🟢 **首版全绿** → 改量法后 🔴 8 条 | 🔴 |

### 2.1 第一次变异暴露的判据缺陷（值得记）

「旧代次响应不得回写」最初只断言**最终**行数。而缺陷发生在两条响应**之间**：
一条过期响应先 `pages.reset()`（清空）再被 `commitPage` 拒绝（不写入），
最终行数完全正确 —— 判据因此恒绿。

修法两条，缺一不可：

1. 把断言改成「订阅每次 emit，**一旦非空就不得再变空**」；
2. 让过期响应落在**已经有数据之后**（按代次控制时序：代次 1 快成功 →
   代次 2 慢 → 代次 3 快成功，到达顺序 1、3、2）。

第 2 条是关键：顺序写反的话，清空发生时列表本来就是空的，没有任何 emit，
判据同样恒绿。

### 2.2 接线期的两条新缺陷（都是接线才暴露的）

1. **`setScope` 登出不清空。** 早期实现只在「scope 非空」时清理，于是登出
   （scope 变回空串）不触发 reset，上一位用户的标题（含姓名）留在内存里
   等下一个人登录。判据补成「比较是否变化」而不是「是否非空」。
2. **`store` 非响应式导致顶栏标题永不更新。** `NavigationContextStore` 的
   状态是普通模块变量，`computed(() => store.snapshot())` 一次求值后被永久
   缓存 —— 它没有任何响应式依赖。加 `shallowRef` 的 `version` 计数器，
   并在 `record()`/`setTitle()`/`setScroll()`/`reset()`/`restore()` 五处
   `touch()`。判据直接对着 `computed` + `watchEffect` 写，删掉 `touch()`
   立即转红。

> 第 2 条是「**门禁绿 ≠ 东西上线了**」的又一个实例：这两条都是把模块
> 接到真实页面时才暴露的，模块自身的单测全绿。

### 3.1 产物必须验证「是新构建」而不是「看起来构建成功」

`cap sync` 在 vite 构建**失败**时仍会把**上一次**的 `dist` 拷进
android assets —— 此时 gradle 照样成功，APK 里是旧代码。

因此产物验证必须包含**内容指纹**，不能只看 BUILD SUCCESSFUL。
2026-10-04 第一次验证就抓到了这个问题：

- 控制组：`chromeTotalHeight`（**已接线**的 `scroll-chrome.ts` 契约）→ 在 APK 里 ✅
  证明 grep 方法有效
- 试验组：`hyper.navigation.v2`、`bp-show-on-narrow` → **不在** APK 里

据此定位到两个真实问题（都已修）：

1. **`styles/breakpoints.css` 从未被任何入口 import** —— 断点阶梯的 CSS 镜像
   根本没进产物。门禁只保证它与 TS 常量一致，**保证不了它被打包**。
   已在 `main.ts` 补 import。
2. **`lib/shell` 未被应用代码引用** —— 运行时模块写了但没接线，自然不在 bundle。
   已在 `AppLayout.vue` 建立单例并接线（见 [06](./06-Hyper导航上下文.md)）。

> 这两条合起来是一个可复用的教训：**「门禁绿」与「东西上线了」是两个命题。**
> 门禁只能验证它看得见的约束；接线与打包需要另一条独立证据。
