# 01 — 原则与断点

> 现行约束。改断点必须同轮改 `composables/useBreakpoint.ts`、
> `styles/breakpoints.css` 与 `styles/__tests__/breakpoint-mirror.test.mjs`。

## 1. 产品原则

1. **一套业务代码，三种窗口形态。** 不为手机重写页面副本。openpocket 只有一个
   router（`src/app/router-mobile.ts`，历史命名，内容是**全部**路由），视图全部
   来自 `features/*`。
2. **形态与能力分开。** 「处于 compact 宽度 / 在原生壳内」是**形态**；
   「能后台录音 / 能本地 OCR / 能持续后台执行」是**能力**，由
   `lib/shell/capabilities.ts` 逐项探测。见 [08](./08-Hyper框架与能力协商.md)。
3. **数据与展示分离。** 列表的布局模式（cards/table）与加载方式
   （continuous/paged）是**两个独立维度**，不要用一个开关同时控制。
4. **原生长于「原生壳」而不是「原生代码」。** 壳不拥有业务判断；金额、写入、
   鉴权、审计继续由后端与既有业务层裁决。

## 2. 四档窗口（SSOT）

档位定义在 `composables/useBreakpoint.ts`，CSS 侧镜像在 `styles/breakpoints.css`：

| 档位 | 宽度 | 形态要点 |
| --- | --- | --- |
| `compact` | < 560px | 底栏 `BottomNav`、列表强制卡片、写弹窗全屏、主操作 ≥44px、输入 ≥16px |
| `medium` | 560–839px | 大屏手机横屏 / 平板竖屏；表格可切；对话框居中 |
| `expanded` | 840–1279px | 平板横屏 / 小窗；侧栏可用 |
| `wide` | ≥ 1280px | **桌面红线区**：表格、侧栏、对话框形态零回归 |

具名子档：

| 子档 | 宽度 | 用途 |
| --- | --- | --- |
| `narrow` | ≤ 380px | compact 内超窄屏（SE / 折叠屏外屏）。收起文字标签只留图标 |

`narrow` 过去以裸 `@media (max-width: 380px)` 散落在 `AppLayout.vue`、
`TasksView.vue`、`AIChatView.vue` 三处，与 JS 侧对不上。现在登记为具名子档，
并提供 `.bp-hide-on-narrow` / `.bp-show-on-narrow` 工具类与 `isNarrow` 开关。

## 3. CSS/JS 双镜像与防漂移门禁

断点在两处落地，**不共享常量**（CSS 读不到 TS 常量）：

| 侧 | 落点 |
| --- | --- |
| JS（真源） | `composables/useBreakpoint.ts` 的 `MEDIUM_MIN_PX` / `EXPANDED_MIN_PX` / `WIDE_MIN_PX` / `NARROW_MAX_PX` |
| CSS（镜像） | `styles/breakpoints.css` 的 `--bp-medium-min` / `--bp-expanded-min` / `--bp-wide-min` / `--bp-narrow-max` |

因此**必须**有机器门禁，否则「改了一处忘了另一处」不会被编译器发现，只会在某档
设备上表现为「布局不对但说不清哪不对」。

`frontend/src/styles/__tests__/breakpoint-mirror.test.mjs` 守四件事：

1. CSS 的 `--bp-*` 值 === TS 常量；
2. TS 的 `matchMedia` 由常量拼出（防止有人又抄一份字面量阶梯）；
3. **`responsive.css` / `breakpoints.css` 里所有宽度型媒体查询的 px 值必须落在
   SSOT 集合内** —— 这一条专门抓「第三套阶梯」；
4. 档位边界无缝隙、无重叠；`narrow` 必须落在 `compact` 内部。

### 3.1 门禁真的抓得住吗（变异自测）

判据的价值在它**能红**的时候。2026-10-04 落地时实测：

| 注入的变异 | 结果 |
| --- | --- |
| 把 `responsive.css` 的 560 改回历史值 768 | 🔴 「responsive.css 出现未登记宽度断点：768」 |
| 把 `--bp-wide-min` 从 1280 改成 1440 | 🔴 「--bp-wide-min 与 TS 不一致」 |

两条都转红，说明门禁不是恒真。

### 3.2 本轮修掉的历史漂移

`responsive.css` 里 `min-width: 768px` 落在 medium 带（560–839）内部，导致
768–839 这一段「CSS 以为是平板、JS 以为是 medium」。已对齐到 SSOT 的 560。

> ⚠️ **可见影响**：560–767px 现在也会拿到 `.list-item` 更宽松的行内边距。
> 这是对齐 SSOT 的代价，已在 `responsive.css` 就地注释说明。

## 4. 禁止事项

1. 新增断点魔法数（裸 `768px`、`500px` 这类第三套阶梯）。
2. 新增范围语法媒体查询（`(width <= 559px)`）；统一用传统 `min/max-width`。
3. 用 `isMobile = width < 768` 或 User-Agent 分支替代四档。
4. 顺手改 wide（≥1280px）桌面既有规则。桌面是红线区，响应式改动一律以
   「新增 `@media`/分支逻辑」表达。
5. 判断行为时直接比档位**字符串**。用 `isCompact` / `isNarrow` 这类具名开关。
   （`mode.value === 'mobile'` 这类历史档位名正是旧实现对不上的根源。）
