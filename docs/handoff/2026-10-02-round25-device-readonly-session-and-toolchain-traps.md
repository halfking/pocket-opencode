## 3. 新事实：设备上的本地库是**加密**的

## 5. 本轮踩的三个工具链陷阱（都不报错，只是静默给出错误答案）

### 5a. `$pid` 是 PowerShell 只读内置变量

```powershell
$pid = (& $adb ... shell pidof $pkg).Trim()   # 赋值被拒
if ($pid) { "RUNNING pid=$pid" }             # 判的是 PowerShell 自己
```

赋值失败只写到 stderr，`if ($pid)` 于是拿 PowerShell 进程自己的 PID 当成
「App 在跑，pid=29824」的证据输出。**换变量名重查才是真值（18590）。**
和之前那次「探针没登录导致满屏 401」是同一类：**失败与「取到空值」塌缩成同一个输出**。

### 5b. PowerShell 的 `>` 会把二进制当文本写

`& $adb exec-out run-as … cat db > out.db` 得到 **1546660** 字节，
而设备上是 **811008**。PowerShell 重定向做编码转换，SQLite 库被毁。
`cmd /c "… > out.db"` 才字节一致（811008，头部正确）。

自证：拷完必须核对**字节数与设备一致**，且头部是 `SQLite format 3`——
不过这次头部就不是，因为它加密（§3）。于是**字节数是唯一还能用的那把尺子**。

### 5c. `node -e` 的引号被 PowerShell 吞掉（第三次了）

内联写正则提取路由表直接 SyntaxError。长探针一律写文件跑。

### 5d. **我在负控时把一个共享文件写成了 0 字节**（最严重的一次）

为了做需求 5 接线判据的负控，我在一条 PowerShell 里想做三次替换：

```powershell
$t3 = $t2 -replace 'a', 'b', '' -replace 'c', '' -replace 'd', ''
```

`-replace` 只接受 2 个参数，第三组让整条语句报错，**`$t3` 从未被赋值**。
紧接着的 `[IO.File]::WriteAllText($p, $t3, ...)` 于是写入了空内容——
`frontend/src/features/email/InvoiceListView.vue` 变成 **0 字节**。

**最坏的第二层**：我随后跑判据，看到「测试 1、2 转红」就以为负控成立并准备汇报。
那不是负控成立，是**判据正确地检测到了我刚犯的错**。如果我据此写下
「负控已验证」，就会把一次自造的事故当成证据。

发现方式：`git diff` 显示 245 行差异（整个文件被删）+ 文件大小 0。
`git checkout --` 还原（该文件我本无改动，HEAD 即正确版本，10533 字节，完好）。

**重来一遍的做法**（`logs/negctrl-a4-wiring.mjs`）：

1. 每一步都断言「编辑**确实生效**」——目标串不存在就 `exit 2`，不继续。
2. 替换后再次断言目标串**没有残留**，且文件大小没有异常缩水。
3. 回滚走 `git checkout --`，不把内存里的字符串写回去。

复用后结果正常：编辑生效（9697 → 9719 字符）、判据 1/2 转红而 3/4/5 仍绿、
回滚后 5/5 复绿且 `git status` 干净。

**教训**：负控的**结果**本身也会骗人。当「负控让判据转红」和「我刚刚破坏了环境」
能产生同一个观察时，必须先证明**是我预期的那个改动**造成的，再采信结论。
判据转红是必要的，不是充分的证据。


## 6. 顺带扫出来的接线缺口：后端测得厚 ≠ 用户点得到

用「把需求的用户可达链路逐段找测试」的办法扫了需求 1/3/5，
发现后端覆盖与客户端接线覆盖之间有一条系统性落差：

| 需求 | 后端 | 客户端接线 | 状态 |
|---|---|---|---|
| 1 定时/手工收信 | 充分 | `runPipeline` 有 **AST 级**判据 + 显式负控 | 已覆盖 |
| 1 清理垃圾→垃圾箱 | `POCKET_EMAIL_SPAM_DRYRUN` 安全阀 | **只有 `cleanup-filter.ts` 纯函数被测**；「预览→确认→真移」这段零覆盖 | **本轮补上** |

| 5 A4 拼版导出 | 三层（合并/几何/裁切线） | 按钮 + 2×3 选择 + 下载 **零覆盖** | 本轮补上（`1cdc1acb`） |

**为什么这类缺口值得补**：把「导出 A4 2×2」按钮删掉、或让「预览匹配」
改调真移函数，后端测试与 gates **全绿**，而需求在产品里静默消失或
变成破坏性一键操作。后端三层测试证明的是「算法对」，
接线证明的是「用户做得到」——只有后者叫交付。

### 6b. 需求 1 接线里最要紧的一处：`dryRun` 的**展开顺序**

    ✅ { ...filter, dryRun: true }   后者胜出 ⇒ 调用方无法覆盖这个安全值
    ❌ { dryRun: true, ...filter }   前者被覆盖 ⇒ 一个 dryRun:false 就能让
                                     「预览」变成真搬

两种写法读起来几乎一样，IDE 不提示，编译也过，**「文件里出现过
`dryRun: true`」这种判据照样通过**。所以判据必须钉顺序
（`spam-cleanup-move-safety.test.mjs` 第 2 条）。
负控实测：把顺序反过去，第 1 条仍绿、只有第 2 条转红并打出实际写法。
