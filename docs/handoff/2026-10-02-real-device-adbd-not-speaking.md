# 真机 192.168.31.19：不是「卡住」，是 5555 上根本没有 ADB 在应答

日期：2026-10-02
现象：自 16:40 起 `adb devices` 一直显示 `offline`，阻塞全部真机验收项。

## 结论

**宿主侧已经没有任何可用手段，必须在手机上操作。**

关键判据不是「offline」这个词，而是这条：

```
scripts/probe-adbd-handshake.mjs  →  [8014ms] 收到 0 字节
```

即：TCP 5555 **接受连接**，我们发出一个合法的 24 字节 ADB `CNXN` 包，
**8 秒内对端回 0 字节**。一个真正在运行的 adbd 不会不回包。

## 逐项排除

| 检查 | 结果 | 说明 |
|---|---|---|
| `ping 192.168.31.19` | 通 | 设备在线 |
| `Test-NetConnection -Port 5555` | True | 端口在监听 |
| 本机地址 | `192.168.31.20/24` (WLAN) | 同一网段，无路由问题 |
| ARP / 邻居表 MAC | `E2:4A:5D:2C:0D:7D` | `E2` 前缀 = 本地管理地址，Android 随机 MAC 的正常表现，说明**还是同一台设备**，DHCP 租约没漂移 |
| `adb reconnect offline` | 无效 | |
| `adb disconnect` + `adb connect` | `failed to connect` | |
| 裸 TCP + 合法 CNXN | **回 0 字节** | 决定性 |

## 两个最可能的原因（都在设备侧）

1. **Android 11+ 的无线调试用的是随机端口**，不是固定 5555。无线调试每次
   开启/重连端口都会变，`5555` 这个记录已经过期。端口上监听的是别的东西
   或是一个残留 socket。
2. 设备侧 adbd 在非正常断连后卡在了一个「内核层面 accept 了、但 adbd 线程
   不再 service」的状态。

## 需要你做的（任选其一）

1. 手机 **设置 → 开发者选项 → 无线调试**，看一眼当前显示的 **「IP 地址和端口」**，
   把那个端口发我，我立刻重连并补完验收。
   （Android 11+ 通常还需要「使用配对码配对设备」那一组端口，两个都要。）
2. 或者：把无线调试**关掉再打开**，让端口重新分配。
3. 或者：手机**解锁 + 重启无线调试 / 重启手机**。
