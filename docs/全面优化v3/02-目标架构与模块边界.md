# 目标架构与模块边界

> 状态：`TARGET`；实现状态以 [事实基线](01-事实基线与审计报告.md) 为准。  
> 设计原则：双端产品、单一事实源、协议按语义分层、渐进替换。

## 1. 两个产品，多个独立组件

### OpenPocket AI 移动工作台

移动端只承担用户交互、离线投影和轻量输入：任务列表、审批、告警、知识问答、远程 IDE 结构化状态、按需 WebRTC viewer。任务事实来自 RedClaw/ACC，记忆来自 Memora，模型调用经 llm-gateway-go。移动端不直接持有主机凭据，也不直接调用 navop。

### RedClaw + Navop 桌面工作平台

桌面体验由两个独立产品协同：

- RedClaw Web/Portal：任务、审批、团队、知识和系统入口；
- navop Desktop：独立的数据库、SSH、SFTP、终端、RDP/VNC、端口转发和 AI 工作台，继续承担 Royal TSX 替代能力。

第一阶段采用统一登录、深链、复制上下文和并置窗口，不做 navop 动态库嵌入、GPUI/WASM 嵌入或融合发行包。原因是 navop 的 `NAVOP_LICENSE` 明确限制作为平台组成部分再分发（`/Users/xutaohuang/workspace/ai/navop/NAVOP_LICENSE:31-40`），且当前 navop 是独立 Cargo workspace，不存在 headless bridge。

## 2. 组件 ownership

| 组件 | 权威职责 | 允许提供 | 明确不做 |
|---|---|---|---|
| OpenPocket | 移动 UI、离线投影、通知交互 | facade client、WS/SSE consumer、WebRTC viewer | 不定义任务状态、不持久化主机凭据、不直接调工具 |
| RedClaw façade | 统一入口、身份、路由、兼容矩阵 | `/api/v2` façade、JWT 下游适配、能力状态 | 不复制 ACC 状态机、不冒充事件事实源 |
| ACC | canonical task、dispatch、审批、租约、审计 | `/api/v2/canonical/tasks`、`/api/v2/orchestration`、discovery、MCP 兼容入口 | 不直接管理 navop 进程、不存长期记忆 |
| AgentCompanion（拟建） | 主机 daemon、agent 发现、反向连接、执行租约 | Runtime Control、标准 ACP client、MCP client/本机工具代理 | 不跨主机调度、不自行决定审批、不绕过 ACC |
| navop | 独立桌面运维工具和本机工具源 | GUI、Public MCP、CLI/Skill、终端/DB/SSH/SFTP/RDP | 当前不承诺 headless/A2A/ACP server/WebRTC server |
| IDE Bridge（拟建） | VSCode/Cursor 状态适配 | 只读 IDE 结构化状态、受控写操作 | 不作为任务调度器、不替代 LSP/DAP 全部语义 |
| Memora | 记忆/知识事实和派生索引 | v2 retrieval、typed ingest、候选治理 | 不拥有任务状态、不拥有审批、不路由模型 |
| llm-gateway-go | LLM 路由、凭据、配额、会话事实 | 现有 HTTP 推理契约 | 不被各端绕过直连模型 |
| myvpn/NetBird/Headscale/FRP | 网络可达性、隧道和节点身份 | 私网连接、反向 bootstrap、relay | 不承担应用权限、审批、审计 |
| LiveKit（候选） | WebRTC room、token、SFU/TURN、媒体轨道 | 屏幕/音频/data track 传输 | 不捕获屏幕、不注入键鼠、不授权命令 |

## 4. 三类事实源

1. **业务事实**：ACC 保存 task、dispatch、approval、run 状态和审计引用。
2. **运行事实**：AgentCompanion 保存本机 agent/session/tool 的短期运行状态；主机崩溃后以租约和事件恢复，不把本机内存当权威。
3. **知识事实**：Memora 保存有来源和版本的记忆、文档、提示词摘要、结构化产物；向量/图索引是派生数据，可重建。

任何 UI 投影都必须标记来源、版本和时间；任何缓存都不能成为新的写入事实源。

## 5. 远程 IDE 数据路径

### 主路径：结构化

`VSCode/Cursor Extension API → IDE Bridge → AgentCompanion → ACC task result/event → RedClaw façade → OpenPocket card`。

- workspace/active editor/diagnostics/tasks/debug/breakpoints/git/terminal summary 逐项声明能力；
- 每项带 schema、版本、敏感级别和 freshness；
- 写操作必须创建 ACC operation，携带审批和幂等键。

### 兜底路径：WebRTC

`Host capture/input adapter → LiveKit（候选）→ OpenPocket viewer`。

视频用于人工接管、观察图形化工具和结构化适配失败时的回退；不把视频 OCR 结果当作代码事实。屏幕捕获和输入注入均是 host adapter 的独立能力，必须接受 ACC grant 和本机 allowlist。

## 6. 接入原则

- 主机只建立出站 TLS/WS 连接，第一阶段不开放公网监听；
- 本机工具优先 UDS/stdio；跨主机才使用 TLS HTTP/2 或 WS；
- 网络层只证明“可达”，业务层仍检查 token、tenant、project、scope、lease 和审批；
- navop 只按现有 Public MCP 的 loopback + discovery token 方式接入，禁止把动态端口/Token 转发到公网；
- 在 AgentCompanion、IDE Bridge、LiveKit 实现前，状态统一标为 `PLANNED`。
