# 分阶段实施路线图与验收矩阵

> 版本：v3.0  
> 状态：`TARGET` 计划；所有未打勾项目均为待实施，不表示已完成。  
> 原则：先收口现有链路，再新增主机/IDE/媒体能力；不以新协议或新基础设施掩盖未闭环的旧契约。

## 1. 门禁规则

每个阶段必须登记：仓库路径、owner、配置项、输入输出、数据事实源、失败状态、幂等策略、测试命令、环境和证据文件。阶段未通过门禁时，后续阶段保持 `PLANNED`。

禁止：

- 使用已退役的 `/api/v2/tasks/orchestrator/*`；
- 使用未创建的二进制、crate 或 endpoint 作为执行示例；
- 把 `mock`、`PARTIAL`、`STUB` 当成生产闭环；
- 以 WS/SSE notification 代替任务或审批事实；
- 在没有测量方法时承诺延迟、带宽、并发或可用性；
- 在没有书面授权时把 navop 源码、动态库、GPUI/WASM 嵌入平台发行包。

## 2. Phase 0：事实与契约收口（2 周）

**目标**：让现有系统有一条真实、可测试、可回滚的 Golden Path。

| 工作 | 当前状态 | 目标产出 | 门禁证据 |
|---|---|---|---|
| ACC canonical task API | `CURRENT/PARTIAL` | 固定 `/api/v2/projects`、`/api/v2/canonical/tasks`，旧路径标 `RETIRED` | ACC route test + OpenAPI |
| ACC orchestration | `CURRENT/PARTIAL` | 固定 dispatch claim/complete/cancel、版本和租约语义 | `go test ./...` 及真实 PG 证据 |
| RedClaw façade | `PARTIAL` | mock/real 兼容矩阵、JWT 和下游 secret 对齐 | façade contract tests |
| OpenPocket façade client | `CURRENT/PARTIAL` | task/approval/memory client 与服务端契约一致 | OpenPocket adapter tests |
| Memora retrieval | `CURRENT/PARTIAL` | HTTP v2、scope、tenant/actor 和 degraded 语义固定 | Memora v2 tests |
| Memora ingest | `STUB/PLANNED` | 明确 501 限制，或完成最小 typed ingest | ingest contract test |
| 文档 | `PLANNED` | v1/v2 加历史标记，v3 成为唯一入口 | 路径/状态扫描 |

**阶段验收**：OpenPocket 创建任务 → RedClaw façade → ACC canonical task → 查询任务状态；任何请求均能以 `correlation_id` 和 `request_id` 追踪。此阶段不依赖 AgentCompanion、WebRTC 或 navop headless。

## 3. Phase 1：主机守护与现有工具闭环（4 周）

**目标**：以最小主机 daemon 接入一个真实 coding agent 和 navop Public MCP。

### 新增组件（全部 `PLANNED`）

- `agentcompanion` 独立仓库：Rust daemon；Linux/macOS 优先，Windows 后续；
- Runtime Control API client/server：register、lease、dispatch、ack、progress、complete、cancel、resume；
- 主机 allowlist 与本地 UDS/stdio 工具代理。

### 首条闭环

```text
ACC dispatch
  -> AgentCompanion outbound session
  -> 标准 ACP coding-agent session
  -> 同机 navop Public MCP（loopback discovery + token）
  -> artifact/result
  -> ACC complete
  -> OpenPocket durable event/query
```

| 验收 | 要求 |
|---|---|
| 注册 | host/agent/capability 可查询，tenant 来源于验证身份 |
| 租约 | 过期、续租、fencing token 和旧连接拒绝有测试 |
| 任务 | duplicate dispatch 不重复副作用；结果 unknown 可见 |
| 重连 | 连接恢复后从 snapshot/cursor 继续，不声称 exactly-once |
| navop | 仅调用真实 loopback Public MCP；Navop 未运行时显式 unavailable |
| coding agent | 使用标准 ACP 版本协商，不把自定义工具 RPC 称 ACP |
| 审计 | 每次命令/工具调用关联 task/run/dispatch/correlation |

## 4. Phase 2：VSCode/Cursor IDE 状态（4 周）

**目标**：先做只读结构化状态，不先做全量远程控制。

### 首批能力

1. active editor/workspace snapshot；
2. diagnostics；
3. task 最近状态和退出码；
4. Git branch/dirty/ahead-behind；
5. terminal summary；
6. debug session/breakpoint 摘要。

### 实施

- 一个 TypeScript 扩展，分别在 VSCode 和 Cursor 建立兼容性矩阵；
- 本地 bridge 通过 UDS/stdio 连接扩展；
- AgentCompanion 通过 MCP 或 typed local tool bridge 获取状态；
- OpenPocket 渲染卡片，完整源码和无限 terminal 不默认上传；
- 写操作另建 operation、审批、幂等和取消契约。

### 验收

- 五种 IDE/扩展重启、断线和版本差异场景；
- 诊断文件范围、Git 状态和 terminal summary 与 IDE 实际状态一致；
- Cursor 兼容性不得由“基于 VS Code”推断，必须有测试证据；
- 敏感文件路径和源码片段可配置脱敏；
- 事件带 sequence/freshness/provenance，旧事件不得覆盖新状态。

## 5. Phase 3：WebRTC 可视接管（4-6 周）

**目标**：让移动端按需查看/接管远程桌面，媒体和业务控制严格分离。

### 选型

- LiveKit：候选媒体服务，room/token/SFU/TURN/data track；
- billd-desk：当前只作为客户端/信令兼容参考，先验证其外部 Socket.IO/SRS/coturn 假设；
- RustDesk/Guacamole：只借鉴连接协商、协议网关和审计思路，不复制 AGPL 代码。

### 必须自建的能力

- 主机屏幕捕获和编码；
- 键鼠/剪贴板/文件输入适配器；
- room 与 tenant/project/task 绑定；
- token TTL、viewer/controller 区分；
- ACC grant、审批和审计；
- 录像/截图保留和删除。

### 验收

- Wi-Fi、4G、TURN 失败回退；
- 视频延迟、丢包和码率在固定设备/分辨率/网络条件下测量；
- data track 仅传非敏感结构化状态，不能取代 durable task events；
- 主机端无授权时键鼠输入必须拒绝；
- 移动端断线后恢复 room 或回到最近可信 snapshot；
- 任何 `<500ms`、`<1s` 等数字只作为待测目标，不能标为已完成。

## 6. Phase 4：桌面工作平台与知识扩展（持续）

**目标**：RedClaw Web 与独立 navop Desktop 形成可用的桌面工作流，不做未经授权的融合发行。

### 功能

- 统一登录和深链：任务 → 项目 → navop 连接/终端；
- RedClaw 任务/审批/知识面板与 navop 独立窗口/标签页协同；
- navop Public MCP/CLI 的受控连接指南；
- 运维技能目录：manifest、版本、权限、签名、审计；
- Memora typed ingest、候选晋升、项目文档和提示词版本；
- 需要时评估 Temporal/NATS/ConnectRPC，但以瓶颈证据和单独 ADR 为前提。

### 不做

- 不把 navop 动态库/GPUI/WASM 嵌进 RedClaw；
- 不将“RedClaw Desktop”描述成包含 navop 二进制的单一商业发行包；
- 不以 WebView 包裹完整 navop 来规避许可证或安全边界；
- 不在没有 owner 和部署入口时新增 Remote Gateway/Skill Gateway/Audit Gateway 品牌服务。

## 7. 可靠性和安全验收矩阵

| 类别 | 必须覆盖 |
|---|---|
| 身份 | token issuer/audience/tenant/actor 校验；body 不得覆盖身份 |
| 幂等 | task create、dispatch、tool invoke、approval、memory ingest 均有幂等键 |
| 租约 | heartbeat、过期回收、fencing、旧连接拒绝 |
| 状态 | queued/running/waiting_approval/completed/failed/cancelled/unknown 合法转换 |
| 事件 | append-only、event_id、sequence、schema_version、cursor/replay |
| 断线 | SSE cursor、snapshot fallback、WS 重连不等于 replay |
| 副作用 | 超时后不自动重复未知结果；provider/effect ledger 可查询 |
| 输出 | artifact 引用、大小上限、脱敏、保留期，禁止无限 stdout 入消息 |
| 工具 | allowlist、required scopes、side-effect class、approval policy、cancel 能力 |
| 网络 | NetBird/Headscale/FRP 只证明可达；应用授权仍单独校验 |
| WebRTC | viewer/controller 权限、room token、主机输入授权、录制删除 |
| 供应链 | Skill/扩展签名、SBOM、版本锁定和回滚 |

## 8. 取消/暂停后置项与升级条件

只有满足以下条件，才升级基础设施：

- PG outbox/inbox 的吞吐、延迟或保留成本成为实测瓶颈，才评估 NATS JetStream；
- ACC 长流程出现可重放性和补偿需求，才评估 Temporal；
- HTTP 契约在浏览器/服务间有明确 streaming 或代码生成收益，才评估 ConnectRPC；
- Memora 向量或图规模达到明确阈值，才评估 Qdrant/Neo4j/Graphiti 等派生组件；
- WebRTC PoC 证明 LiveKit 或 billd-desk 兼容性后，才选择正式媒体服务；
- navop 若需要 headless，另立 upstream change proposal，不能在本路线图中虚构实现。
