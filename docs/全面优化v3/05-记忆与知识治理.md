# 记忆与知识治理

> 状态：`TARGET`；Memora 当前实现状态见 [事实基线](01-事实基线与审计报告.md)。

## 1. 权威边界

| 数据 | 权威系统 | Memora 关系 |
|---|---|---|
| task/dispatch/approval/run 状态 | ACC canonical store | 保存摘要、来源引用和可检索事件，不替代事实 |
| 主机/agent lease 与连接状态 | AgentCompanion/ACC registry | 保存事件和历史快照 |
| LLM turn 元数据与配额 | llm-gateway-go | 生成可检索摘要，不复制原始秘密 |
| 原始文档、提示词、项目知识 | Memora | 事实与索引均由 Memora 管理 |
| 终端/构建/IDE 产物 | 原始 artifact store/ACC run | Memora 保存脱敏摘要和 artifact 引用 |

“所有现状、文档和提示词存在 Memora”应理解为：**所有需要长期检索的资料有可追踪的 Memora 记录**，而不是将所有原始数据、凭据、无限日志和屏幕帧无差别写入向量库。

## 2. 当前事实与缺口

- Memora v2 retrieval 是 HTTP/Gin `/api/v2/memories/search`，通过 service JWT、scope、tenant/actor 校验；见 `memora/internal/v2/retrieval.go:128-180`。
- Memora 当前 `ingest` 仍是 501 skeleton，不能宣称“文档/提示词自动回流已完成”；见 `memora/internal/v2/failclosed.go:75-90,115-130`。
- candidate 创建/晋升/拒绝已有 fail-closed 约束，需要 artifact_ref、source_task_id、sensitivity、confidence、project 和 gate/version；见 `memora/internal/v2/candidates.go:60-79,191-247,269-376`。
- ACC ContextAssembler 已有 v2 client，但应以 HTTP 契约和合同测试为事实，不在新方案中改写为未实现的 gRPC。

## 3. 统一记忆记录

```json
{
  "memory_id": "mem-...",
  "tenant_id": "tenant-...",
  "project_id": "project-...",
  "scope": "user|project|agent|run|organization",
  "source_type": "document|prompt|task|tool_result|ide_snapshot|screen_ocr|decision",
  "source_ref": "acc://runs/run-123/artifacts/art-456",
  "content": "脱敏后的可检索内容",
  "content_hash": "sha256:...",
  "version": 3,
  "actor": {"type": "user|agent|service", "id": "..."},
  "sensitivity": "public|internal|confidential|secret",
  "created_at": "...",
  "retention_until": "...",
  "deletion_ref": "...",
  "provenance": [{"system": "acc", "event_id": "..."}]
}
```

强制规则：

1. `tenant_id`、`project_id`、actor 由已验证身份和父资源派生；不能由正文覆盖；
2. 记忆写入采用幂等键和内容 hash，重复投递不产生重复事实；
3. 原始资料先进入可重放的 outbox，再异步生成 embedding、关键词和图关系；
4. 删除、纠错、过期和重建都保留审计引用；
5. secret 永不进入普通向量索引；需要时只保存 vault/artifact 引用；
6. 访问结果带 provenance、freshness、degraded 状态和实际 scope，不静默伪装成完整检索。

## 4. 数据流

```text
文档/提示词/任务产物
        |
        | 校验、脱敏、哈希、幂等
        v
typed memory ingest（当前 PLANNED）
        |
        | durable outbox / retry / DLQ
        v
Memora canonical memory + derived indexes
        |
        | retrieval with tenant/project/actor scope
        v
ACC ContextAssembler -> AgentCompanion / OpenPocket / Web
```

### 记录分类

- **原始记录**：对象存储或源系统中保存，保留最小访问面；
- **结构化记录**：任务摘要、诊断、Git 状态、决策、操作结果；
- **向量索引**：可删除、可重建的派生数据；
- **图关系**：项目、主机、服务、任务、决策的关系和有效时间；
- **提示词**：保存模板、版本、来源、适用范围和 hash；敏感运行 prompt 只保存脱敏摘要。

## 5. 借鉴而不替换

- Mem0 的 user/session/agent scope 可参考记忆 API 边界；不能把其 benchmark 或托管平台优化当成本项目指标。
- Graphiti 的 provenance、temporal fact 和失效关系可参考运维知识图谱；不能用它替代 Memora 的用户、会话、权限和生命周期。
- Letta 的 stateful agent 思路可参考；旧 server 已不应作为生产依赖。

## 6. 验收矩阵

| 场景 | 必须证明 |
|---|---|
| 文档入库 | source_ref、hash、tenant/project、脱敏和幂等 |
| 提示词版本 | version、owner、适用 agent、删除和回滚 |
| 任务回流 | task/run/artifact 可追溯，不能覆盖 ACC 状态 |
| 检索 | scope 过滤、provenance、freshness、degraded reason |
| 删除 | 原始记录、派生索引和缓存均有删除证据 |
| 纠错 | 新版本覆盖关系明确，旧版本可审计 |
| 跨租户 | token tenant 与 body/project 冲突时 fail closed |
| 后端故障 | 503 或显式 degraded，不伪造完整结果 |

## 7. 阶段优先级

1. 先完成 typed ingest 的最小 HTTP 契约和合同测试；
2. 再接 ACC task/run/artifact 的 outbox 回流；
3. 再补提示词目录、版本和搜索；
4. 最后做 L4-L6、时态图和 dream/整合任务；
5. 在 ingest 和删除闭环前，不宣称“全量资料已进入 Memora”。
