# 开源项目选型与许可证矩阵

> **资料日期：2026-08-27**  
> **用途：**为本项目（IT 人员 AI 工作平台及其控制、协作、远程执行能力）建立可复核的开源选型和许可证边界基线。  
> **阅读约定：**“事实”只记录官方仓库、官方文档和许可证文件所表达的能力/条款；“判断”是针对本项目的工程取舍，不是项目方的承诺。许可证结论以目标版本提交（commit/tag）中的 `LICENSE`、子目录许可证、第三方依赖和发布物清单为准，不能仅凭 GitHub 页面顶部的一个标签作结论。

## 1. 结论先行

| 事实 | 判断 |
|---|---|
| LiveKit 提供成熟的实时音视频、WebRTC、房间、发布/订阅、数据通道和服务端 API；其核心仓库采用 Apache-2.0。 | **LiveKit 是媒体平面的候选方案**。先以独立媒体服务接入，不把媒体状态塞进控制中心数据库；在确定规模、录制、转码和网络穿透需求后再锁版本。 |
| NetBird 的仓库存在根许可证与子组件许可证的分层：根目录为 BSD-3-Clause，而 `management`、`signal`、`relay`、`combined` 等服务边界标为 AGPL-3.0。Headscale 为 BSD-3-Clause。 | 网络平面可评估 NetBird（接受其 AGPL 服务边界并隔离部署）或 Headscale（BSD、控制面更窄）；**不能把 NetBird 根许可证误读为全仓 BSD**。 |
| 本项目已有 PostgreSQL 和可靠写库路径；outbox 可在现有事务内实现事件持久化、重试、幂等和审计关联。 | **PG outbox 当前优先**，先解决可靠投递和可追溯性，不因“需要事件”立即引入 Temporal 或 NATS。 |
| Temporal 和 NATS JetStream 都能承担可靠工作流/消息基础设施，但会带来新的运行时、运维和数据一致性边界。 | **Temporal/NATS 后置**：只有在 PG outbox 的吞吐、长流程恢复、跨服务订阅或消费积压达到明确指标后再引入，并保留 PG 事实源。 |
| RustDesk 和 NetBird 的部分服务边界是 AGPL；AGPL 的网络交互触发源码提供等合规义务，不能按“只是远程调用”规避。 | **绝不复制 AGPL 代码**。如采用 AGPL 服务，只通过清晰的进程/网络接口、独立部署和许可证审查接入；不得复制实现、改写后混入本项目，或把其代码静态/动态链接进闭源组件。 |

## 2. 总体许可证判读规则

| 事实 | 判断 |
|---|---|
| Apache-2.0、MIT、BSD-3-Clause 通常允许商用、修改、再发布和闭源组合，但要求保留版权/许可证通知；Apache-2.0 还包含明确的专利授权和修改标识要求，并有专利终止条款。 | 对 Apache/MIT/BSD 项目仍需保留 NOTICE、版权和依赖清单；“宽松许可证”不等于可以删除署名、商标或第三方条款。 |
| GPL/AGPL 项目的合规边界取决于复制、修改、链接、发布和网络提供方式；不同目录、生成代码、前端依赖和发行包可能有不同许可证。 | 以文件路径和发布形态做 SBOM/许可证扫描；对 AGPL 代码只允许经过法务确认的独立服务集成，不复制代码。 |
| 协议规范、文档、示例和参考实现可以采用不同许可证。 | 只借鉴协议语义和公开接口时，仍要分别记录规范、文档、示例和代码的许可证；不把“协议开放”当成“实现可复制”。 |
| 上游许可证会随版本、仓库迁移或子项目拆分发生变化。 | 每次升级固定 tag/commit，保存许可证快照、NOTICE、依赖许可证和构建产物来源；本矩阵是选型基线，不替代发布前法律审查。 |

**不能照搬：**不要把 RPC 框架当作授权、审计或可靠消息系统；不要复制 Connect 实现；本项目要在 RPC 层显式传递租户、请求 ID、幂等键和审计上下文。 |

## 10. 本项目最终选型结论

1. **媒体：LiveKit 作为候选。** 先验证房间、token、WebRTC 网络、录制/回放和多租户隔离，再决定单节点或集群部署；不复制 LiveKit 实现。
2. **网络：并列评估 NetBird 与 Headscale。** Headscale 的 BSD-3-Clause 和较窄控制面适合需要更小许可证/运行时边界的场景；NetBird 的能力更完整，但必须按 `management`、`signal`、`relay`、`combined` 等 AGPL-3.0 服务边界隔离和合规，不能写成“NetBird 全 BSD”。FRP 仅作为受控反向连接/穿透候选，**VirtualNet 仍按 alpha 处理**。
3. **可靠事件：PG outbox 当前优先。** 业务事务、outbox、重试、幂等键、投递状态和审计关联先落 PostgreSQL；避免为尚未量化的需求同时维护 Temporal/NATS。
4. **工作流/消息：Temporal 与 NATS JetStream 后置。** 只有在长时工作流恢复、复杂补偿、跨服务编排、吞吐/消费积压等指标明确超过 PG outbox 能力时再引入；引入后仍保留业务事实源和可重放策略。
5. **协议：按边界采用，不按项目整包复制。** MCP、ACP、A2A、LSP、DAP 分别解决不同互操作问题；实现最小必要子集，固定协议版本，并补充本项目的认证、授权、审批、租户隔离、超时、取消、限流和审计。
6. **编辑器：严格区分 Code-OSS 与 VS Code 产品。** 可研究 Code-OSS MIT 源码和扩展 API；不把 VS Code 产品二进制、品牌、专有资产或 Marketplace 内容当作 MIT 组件再分发。
7. **远程桌面：不复制 RustDesk AGPL-3.0 代码。** Guacamole、MeshCentral、RustDesk 只作架构和能力对照；任何采用都必须先完成代码路径、依赖、发布形态和网络交互合规审查。
8. **记忆：先事实源，后索引/运行时。** Mem0、Graphiti、Letta 的模型可借鉴，但不取代 PG 中的事实、事件、来源、删除和审计；Letta 旧 server unsupported，不能作为新部署基线。

> **硬性红线：绝不复制 AGPL 代码。** 这条红线适用于 RustDesk 全部主项目代码，以及 NetBird 明确标注 AGPL-3.0 的 management、signal、relay、combined 等服务边界；任何例外必须在进入代码库前完成书面许可证审查。
