## 3. 动态状态图标（核心交付）

```
头部：[←] [◉] 标题          [⋮]
           └ 状态·时长（副标题）

◉ 三态（信号即界面 §2.2——信号即入口）：
  🔴 notifications_active + 待办角标 + 呼吸动画 → 单击 = 查看审批（原 [查看]）
  🟢 progress_activity + 持续旋转             → 单击 = 停止（interruptSession）
  ⚪ play_arrow 弱化                          → 单击 = 继续（sendPrompt('继续')）
```

- 数据源不变：P1 的 `useSessionEvents`（session.activity 五态 phase）+ 审批 store；断线降级 `deriveFallbackPhase` 原样。
- 状态派生抽为纯函数（`resolveSessionStatusMode`/`sessionStatusLabel`），图标组件与头部副标题共用同一份逻辑，防两处漂移。
- 动画遵循全局 `prefers-reduced-motion` 裁剪（styles.css 既有规则）。
- aria-label 携带完整信号（"改文件中 · 40s · 点击停止"），role="status"。

## 4. 设计决策登记（DD）

| # | 决策 | 理由与取舍 |
|---|---|---|
| **DD-1** | **运行态单击停止，无二次确认**；Toast 提示"已停止，点击状态图标可继续"。与"停下二次确认"纪律（设计 v2 §4.4-2）的偏差**显式登记** | ① 停止可经同一图标一次点击恢复（toggle），误触成本 = 一次点击，非不可逆破坏；② 两步介入原则（§2.3）要求高频动作零摩擦，真机 P1 验证中停止是最高频介入；③ 面板内文字"停下"**保留** window.confirm 二次确认不变（用户主动输入场景防误触）；④ 兜底：误停止的最坏后果是重跑一轮，由 Toast 引导恢复 |
| **DD-2** | 状态条收敛为**头部内嵌图标**（而非保留独立行图标化） | 用户指认的问题是"标题栏重叠"——只图标化不合并仍留两层条。图标+副标题合并后：头部一层同时承担导航（返回）、信号（图标+状态·时长）、收纳（⋮）三职责，每层职责唯一 |
| **DD-3** | 固定目标模式下 Composer 目标 chip 不再渲染 | 会话标识已由头部标题承担（P1.5 后信息更全：标题+信号）；chip 显示的截断标题与头部完全重复。**targets 可切换模式保留 chip**（切换职责仍在，契约 §4 就绪待 P2 接线）。释放的横向空间给 textarea |
| **DD-4** | 底导"..."不加新按钮 | 盘点发现 `BottomNav.vue` 已有"⋮ 更多"收纳面板（3e4a9a3 落地：PKM/密码箱/任务/会话/实例/成本/设置），任务③的底导语义已满足；且该文件属并行流 WIP（勿动纪律）。本迭代的"..."落在会话级：⋮ 抽屉（实例信息+统计+轮摘要+导出） |
| **DD-5** | 图标字体**自托管子集**（4KB）而非 CDN/npm 全量（3.8MB）或逐文件改 SVG | ① 国内设备 fonts.googleapis.com 不可达，P-2 必须自托管；② 全量 3.8MB 不可接受（主 chunk 才 594KB）；③ 改 15 个文件为 SVG 侵入过大且与并行流冲突面大；④ 子集保留 liga 连字机制，模板写法（图标名字面量）零改动，并行流 ai-chat 的图标也被一并修复。代价：新增图标需重跑 `scripts/subset-material-symbols.sh`（脚本自动扫描源码，忘跑的症状是图标显示为文字，易发现易修） |
| **DD-6** | 字体轴值固定 wght=400 FILL=0（outlined 常规），不保留可变轴 | 移动端无需运行时变轴；固定后 gvar 数据（体积大头）被剔除，这是 376KB→4KB 的关键一步 |

### 6.1 验证中发现的存量缺陷（登记 P2 缺陷池，非 P1.5 引入）

- **DEFECT-P2-SSE-1（高）**：SSE 消息流不向 App 投递 assistant 输出且无流关闭信号。真机对照证据：opencode 侧 23:21:57 轮次已完成（assistant 已回复"链路正常-2"，直查 /session/:id/message 可见），App 侧同轮 100s+ 后仍 isStreaming=true、图标久挂"思考中"、assistant 气泡从未渲染（DOM bubbles=1）。后果：停止/完成信号不可达 → 图标状态机被上游数据钉死在运行态（状态机本身按输入正确运转，见 V-4/V-6）。P1.5 未触碰流/store 层（全部 diff 在展示层）。
- **DEFECT-P2-DUP-1（中，存疑）**：同文 prompt 重复投递一次（23:17:09 与 23:17:45 两条相同 user 消息入 opencode 历史，间隔 36s；两次发送均非用户操作窗口）。需 pocketd/opencode 服务端日志定位（重复 POST 方在 App 或 pocketd 重试逻辑）。
- 以上两项归属 P1 事件/流层（dc16666/e296193 交付），P1.5 仅负责发现与登记；修复排 P2（与 P2"订阅收窄 + since 追赶"同批处理最合适）。
