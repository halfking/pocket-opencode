## 0. 融合目的

OpenPocket 内部规划聚焦于"小而精的便携式控制服务"，并已落地 Android 部署。v4 总纲在此基础上加入"三大闭环 + 跨模块协作"维度。

跨模块关键发现：`agent-control-center/docs/04-implementation/plan/host-agent-gateway-integration-plan.md`（2026-08-20）的核心结论是 **"不要新建服务，扩展 pocketd 即可"**——把 Wake 磁盘会话聚合移植为 `pocketd` 内的 Go disk-reader 实现 `OpenCodeAdapter` 接口；pocketd↔ACC 的 MCP 从"只读"升级为"双向"。这对 OpenPocket 整体定位有重大影响，本融合文档做四件事：

1. **采纳整合方案**：把 host-agent-gateway-integration-plan 作为 OpenPocket 后续演进基线；
2. **节奏对齐**：把 v4 短中长期与内部 8 个计划文档对齐；
3. **三大闭环落地**：把"移动端入口 + 离线投影 + 客户端反馈"的角色明确；
4. **关键技术决策统一**：双源任务系统、MCP 双向化、disk-reader 适配器、Capacitor iOS PoC。

### 1.2 ownership（与 v4 总纲对齐）

| 责任 | OpenPocket 拥有 | 不做 |
|---|---|---|
| 移动 UI | ✅ TaskList / TaskDetail / Approval / Knowledge / IDE Status / WebRTC viewer | ❌ 不定义任务状态 |
| 通知交互 | ✅ 推送注册 + 点击行为归集 | ❌ 不替代审批事实源 |
| 离线投影 | ✅ 只读缓存（SQLite/IndexedDB） | ❌ 不持久化主机凭据 |
| 工具调用 | ❌ 必须经 façade 或 pocketd 适配器 | ❌ 不直接调 navop / LLM |
| WebRTC viewer | ✅ 远端屏幕按需查看（Phase 3） | ❌ 不控制键鼠（除非授权） |
| host-agent 网关 | ✅ pocketd 适配器（disk-reader + MCP 双向化） | ❌ 不替代 agent-companion |

## 6. 风险与回滚（融合 v4 + 内部 + host-agent）

| pocketd 主机服务 down | 进程崩溃 | supervisor + 自动重启 |
