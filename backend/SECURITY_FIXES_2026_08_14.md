### 2. Mobile Session Workspace Boundary

**Files:**
- `internal/server/mobile_session_handler.go` (modified)
- `internal/server/mobile_session_security_test.go` (new)
- `internal/registry/registry.go` (modified)
- `internal/registry/writable_scope_test.go` (new)

**Fixes:**
- All `/api/mobile/sessions` routes fail-closed: empty workspace claim → 400 before upstream
- Read operations use `GetInstanceAPIBaseForWorkspace` (shared instances visible)
- Write operations (create/prompt/interrupt/delete) use `GetWritableInstanceAPIBaseForWorkspace` (private instances only)
- Router-level workspace check prevents unknown subpaths from bypassing validation
- JSON decoder rejects unknown fields and trailing content
- Message pagination validates `limit` (1–100) and `order` (asc|desc) before upstream
- SSE workspace derived only from JWT claims, never query parameters
- SSE event filter rejects global events without provable session ID

**Tests:**
- `TestMobileSessionRoutesFailClosedBeforeUpstream` — verifies no-token, empty-workspace, cross-workspace, shared-write, unknown-json, trailing-json all rejected with zero upstream calls
- `TestMobileSessionCreateBindsClaimWorkspace` — confirms JWT workspace written to upstream Location
- `TestMobileMessagesRejectInvalidPaginationBeforeUpstream` — validates limit/order enforcement
- `TestWritableInstanceRequiresWorkspaceOwnership` (registry) — unit test for writable resolver

**Fixes:**

- Audit entries recorded only after upstream confirms success
- Validation errors return structured 400/401/404/413 with stable codes
